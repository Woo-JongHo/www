# 교차검증과 검토 예산 관리

## 범위와 권한

현재 요청과 저장소의 독립 검토 정책을 먼저 확인한다. 이 스킬은 검토를 준비하고 회수하는 절차이며 기존 필수 검토자·완료 조건·공식 실행기를 대체하지 않는다. 읽기 전용 검토자는 소스·원장·설정에 쓰지 않는다. 실제 호출·인증·사용량 소비는 현재 사용자가 허용한 범위에서 수행한다.

모델을 쓰기 전에 단계별 목적을 정한다. 작성·수정은 작성자가, 교차검증은 독립 검토자가 맡는다. 현재 지침이 최종 Opus를 요구하면 해당 감사를 유지한다. 사용 불가·예산 부족은 미실행으로 기록하며 이 스킬 자체를 대체 모델 승인으로 쓰지 않는다.

## 1. 실행할 검토를 고른다

| 종류 | 검토할 범위 | 다음 행동 |
|---|---|---|
| 사전 점검 | 요구·사용자 여정·변경 위험·준비된 증거 | 작성자가 빠진 구현·검사를 먼저 보완 |
| 변경 검토 | 변경 diff, 직접 호출자·상태 경계, 해당 기준과 검사 | 독립 검토 후 지적을 작성자에게 인계 |
| 수정 재검토 | 이전 지적, 수정 diff, 영향 경계와 회귀 증거 | 해당 지적의 해결·새 회귀·잔여 범위 확인 |
| 최종 감사 | 필수 기준 전체와 통합 경계, 현재 적용되는 증거 | 지정 정책의 검토자와 완료 core에 제출 |

앞 단계의 범위가 좁으면 최종 통과로 승격하지 않는다. 통합 실패 가능성이 같은 변경은 한 감사 묶음으로 준비하되 각 작업 UUID·기준의 검토 범위를 구분한다. 독립된 조사·테스트는 병렬로 할 수 있고 같은 경계를 중복 검토하는 호출은 필요를 설명한다.

## 2. 검토 패킷을 동결한다

[요청 양식](templates/review-request.md)을 현재 작업의 Git 제외 증거 디렉터리에 복사해 실제 값으로 작성한다. 기존 작업 UUID와 원장의 검토 이력을 재사용한다. WWW이면 같은 작업의 `work.json`, `verification.md`와 공유 검토 core가 정본이며 새 경쟁 원장을 만들지 않는다.

패킷에 다음을 연결한다.

- 검토 종류·목적, 작업 UUID와 기준 ID, 현재 기준 정의 식별.
- 구현·테스트·설정의 내용 식별과 diff 기준점. HEAD·dirty 표기만으로 내용 동일성을 판정하지 않는다.
- 필수 읽기 파일·필요한 범위·선정 이유와 확인할 사용자 여정. 변경 파일뿐 아니라 직접 호출자·상태 소유자·오류와 복원 경계도 포함한다.
- 실제 검사 명령·결과·실행 환경·한계와 원문 위치. 통과 요약과 원문을 구분한다.
- 제공한 내용, 위치만 알려 준 자료, 검토하지 않을 자료. 검토자가 실제 읽은 범위를 결과에서 회수한다.

기존 하네스의 source·criteria digest, 입력 선택 영수증과 검토 ID가 있으면 그것을 사용한다. 별도 패킷 식별이 필요하면 대상 소스·기준·정렬한 선택 경로와 내용 hash·검토 목적·정책·요청 모델의 정규화된 목록을 SHA-256으로 식별한다. 동적으로 바뀌는 시각이나 실행 ID를 동일성 키에 섞지 않는다.

유효한 기존 결과의 재사용 여부는 동일 목적·소스·기준·입력 범위·정책과 원문 영수증을 대조해 판단한다. 공식 core가 오래되거나 부적합하다고 판단한 결과를 임의로 통과 처리하지 않는다. 검사 중 내용이 바뀌면 기존 판단을 과거 기록으로 보존하고 현재성부터 다시 평가한다.

## 3. 문맥과 호출 예산을 정한다

검토 전 선택 파일 수·제공 bytes, 예상 도구 읽기 횟수, 출력 상한, 모델 호출 횟수와 재검토 한도를 기록한다. 금액·토큰 수는 작업 위험과 실제 제공 자료에 맞춰 정하고 모르는 값은 미확인으로 둔다. 예산을 맞추려고 필수 기준이나 위험 경계를 누락하지 않는다.

본문에는 현재 기준, 짧은 변경 설명, 필수 자료와 검사 요약을 넣는다. 누적 보고서 HTML·과거 원장 전체·원시 출력 전문은 필요한 지적에 해당하는 부분만 읽고 원문 경로·hash를 연결한다. 보존 원문과 매 호출에 제공하는 문맥은 별개다. 지침·도구 정의를 바꾸는 호출에서는 캐시 재사용을 당연하게 가정하지 않는다.

검토자에게 필수 읽기 목록을 먼저 주고, 부족할 때 해당 이유와 추가 경로를 좁혀 읽도록 요청한다. 지원하는 도구의 병렬 읽기·선택 제공을 사용한다. 프로젝트가 단일 literal 명령이나 고정 invocation을 강제하면 그 계약을 유지한다. 패킷에서 빠진 파일을 읽은 것으로 기록하지 않는다.

예산이 초과될 전망이면 중간 지적·미검토 범위·사용량을 회수하고 분할 또는 추가 호출의 필요를 설명한다. 실제 실행기가 지원하고 공식 어댑터가 허용한 한도만 강제 제한으로 사용한다. 이 스킬의 계획값은 **advisory**이며 현재 어댑터에 임의 CLI 플래그를 덧붙이지 않는다. USD 한도는 구독 사용 한도나 정확한 토큰 상한과 동일하지 않다.

## 4. 읽기 전용 검토를 실행한다

검토자에게 이 패킷과 필요한 적용 정책만 제공한다. 작성자의 기대 판정을 답으로 주지 않고 관찰 가능한 동작과 반례를 검토하게 한다. 단순 성공 경로뿐 아니라 해당하는 빈 자료·실패·중단·복원·중복·순서 역전·선택 전환을 확인한다. 실제 실행 없이 코드로 추론한 재현은 실행 관찰과 구분한다.

요청 모델·provider·읽기 전용 범위와 실제 호출 출처를 기록한다. 관측 모델·usage가 응답에 없으면 미확인으로 둔다. 주입 실행기를 실제 provider 호출로 보고하지 않는다. WWW의 필수 감사는 기존 `scripts/workflow/review.ts`와 공식 검토 경로를 사용하며 스킬 문서나 별도 CLI 결과로 통과 영수증을 꾸미지 않는다.

## 5. 지적과 수정 재검토를 관리한다

지적마다 식별자, 심각도, 파일·행, 문제 조건, 기대/관측 또는 판단 근거, 관련 기준, 수정 담당을 남긴다. 작성자가 수정과 집중 검사를 수행한 뒤 새 소스 식별과 변경 diff를 연결한다. 검토자는 자신이 소스를 고쳐 스스로 승인하지 않는다.

재검토 요청에는 이전 지적 목록·수정 근거·회귀 결과와 새 영향 범위를 먼저 제공한다. 같은 지적이 반복되거나 수정이 공통 계약·통합 경계로 퍼지면 좁은 재검토를 멈추고 필요한 범위를 다시 설계한다. 같은 소스의 불합격을 모델 교체나 무근거 재호출로 해결하지 않는다. 중단·시간 초과·사용량 소진은 각각 별도 시도로 보존한다.

최종 감사가 요구되면 현재 통합 소스에서 필수 범위를 확인한다. 수정 재검토의 통과가 최종 감사 전체를 대신하는지는 적용 정책과 완료 core가 결정한다.

## 6. 사용량과 결과를 회수한다

[사용량 보기 양식](templates/review-usage.md)에 실제 영수증의 원문 위치와 실행별 수치를 연결한다. 이 보기는 정본 검토 이력에서 파생한 관리용 요약이다. 원장의 상태나 비용 증거를 독립적으로 덮어쓰지 않는다.

- 신규 입력, 캐시 생성 입력, 캐시 읽기, 출력을 서로 다른 항목으로 기록한다.
- 내부 reasoning이 출력의 일부면 별도 합산하지 않는다. 미제공 usage를 0으로 채우지 않는다.
- 캐시 읽기 누적량을 고유 파일 크기나 새로 읽은 토큰 수로 해석하지 않는다.
- CLI의 API 환산 금액, 실제 청구액, 구독 한도 차감량을 구분한다.
- 같은 provider 실행을 raw/result/집계 파일에서 중복 합산하지 않고 검토 ID·실행 영수증으로 식별한다.
- 여러 작업에 한 감사를 연결해도 비용은 실제 호출 한 번으로 집계한다. 원가를 나누면 분배 기준을 표시한다.

종료 보고에는 검토 범위·현재 판정·남은 지적·미검토·원문 경로와 다음 행동을 남긴다. 토큰 절감률은 같은 완료 조건의 전후 실측이 있을 때만 제시한다.

## 완료 기준

현재 대상과 기준, 읽은 범위, 독립 검토자, 실제 검사와 한계, 지적 처리, 호출 사용량이 추적 가능하다. 필수 검토·증거가 부족하면 그 상태로 보고하고 업무 완료는 기존 정책이 허용할 때만 기록한다. 스킬 생성·발견 경로 등록은 호스트의 실제 호출 수용이나 자동 예산 차단의 증거가 아니다.
