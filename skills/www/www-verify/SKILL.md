# WWW 검증

## 호출 조건

사용자가 `www-verify`를 명시적으로 호출한 경우에만 실행한다.

## 입력

작업 ID, UUID로 스캔해 찾은 실제 작업 폴더의 수용 기준, diff, 실제 실행 가능한 검사와 환경. 문서 폴더를 작업 ID로 이어붙이지 않는다.

## 진입 조건

검증 대상 소스 상태와 필수 기준을 식별할 수 있다.

## 절차

1. [공통 계약](../../../docs/skills/WORKFLOW.md), [모델·추론 노력 권고](../../../docs/skills/MODEL_POLICY.md), [데스크톱 프로필](../../../docs/skills/profiles/desktop.md)을 읽는다.
2. 검증 당시 commit과 dirty 여부를 기록하고 상태를 사실에 맞게 `verifying`으로 둔다. 요청·실제 모델과 추론 노력을 관찰할 수 있을 때만 함께 기록한다.
3. 관찰 행동, 경계값, 오류 경로를 검사한다. 실패·경고를 숨기거나 실행하지 않은 검사를 통과로 쓰지 않는다.
4. `verification.md`에 시도별 섹션을 추가하고 정제한 요약 앵커를 만든다.
5. 각 기준의 `result`와 증거를 갱신한다. push, 색인, 비즈니스 수용, 프로세스 종료를 테스트 통과와 섞지 않는다.
6. 모든 필수 기준이 실제 증거와 함께 통과하고 차단이 없을 때만 `done`으로 바꾼다.

## 출력 경로

UUID로 찾은 실제 작업 폴더의 `verification.md`, 같은 폴더의 `work.json`.

## 허용 변경

검증 기록, 기준 결과, 검증에 직접 필요한 테스트만 변경한다. 제품 수정은 `www-build`, 불명확한 실패는 `www-diagnose`에 인계한다. 자동 commit·push는 하지 않는다.

## 완료 조건

각 필수 기준이 통과·실패·차단 중 하나로 정직하게 판정되고 실행 명령, 핵심 결과, 소스 상태, 미검증 한계가 재현 가능하게 남았다.

## 인계

[검증 템플릿](../../../docs/skills/templates/verification.md)을 사용한다. 실패는 구체적 재현과 함께 `www-build` 또는 `www-diagnose`로 돌려보내며, 통과는 게시·서버 색인을 자동 의미하지 않는다.
