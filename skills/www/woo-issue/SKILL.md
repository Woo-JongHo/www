# 세션 이슈 선정

이 저장소의 백로그 정본은 GitHub Issues다. 저장소와 이슈 번호로 식별하고 문제·기대 결과·우선순위·열림/닫힘은 GitHub에서 읽는다. 제품 명세와 코드, 해당 작업 UUID의 수용 기준·검증 시도·증거는 저장소에서 읽는다. GitHub 종료와 현재 소스의 검증 유효성은 각각 원천에서 확인한다.

1. 대상 원격을 확인하고 열린 이슈를 페이지 끝까지 읽는다. 명시된 마일스톤이나 필터가 있으면 적용한다. 연결된 PR, 작업 UUID, 최근 변경을 필요한 후보부터 대조한다. 접근 실패나 일부 조회는 수집 범위에 명시한다.
2. 로컬 명세·대시보드에서만 발견한 일은 미등록 후보로, 기존 이슈와 겹치는 일은 중복 후보로 표시한다. 제목만으로 합치지 않는다. 분류 요청은 읽기 전용이며 이슈 발행·라벨 변경·종료는 별도 게시 요청에 따른다.
3. 사용자 지정 우선순위와 선행 차단 해소를 먼저 고려한다. 같은 사용자 여정이나 통합 검사로 묶을 이유가 있고 병렬 소유 범위를 나눌 수 있는 후보를 최대 다섯 개 선택한다. 파일을 함께 수정해야 하면 선행 PR과 공통 파일 담당을 정한다. 실환경·계정·요구 결정이 필요한 후보는 가용성을 확인한다. 적합한 후보 수만큼 선택한다.
4. 선택 표에 이슈 링크, 해결할 문제와 기대 결과, 묶은 이유, 선행 이슈·충돌 파일, 연결할 작업 UUID, PR별 집중 검사, 결합 후보에서 한 번 수행할 검사를 기록한다. 소스 확인 전의 영향 경로는 추정으로 표시한다. 나머지는 보류 이유와 다시 선정할 조건을 짧게 남긴다.
5. 선정 결과는 조회 시점의 계획으로 전달한다. PR은 이슈 번호와 작업 UUID를 참조한다. 이슈의 해결 조건을 충족하는 최종 PR에 종료 연결을 둔다. 요구가 충돌하면 양쪽 근거와 해결할 결정을 표시한다.

선정한 작업의 실행과 GitHub 게시까지 요청받으면 [세션 등록과 PR 검사](../../../docs/skills/EXECUTION_EFFICIENCY.md#pr-집중-검사와-결합-후보의-전체-검사)에 따라 선정 표를 상위 이슈의 새 코멘트 한 건에 기록한다. 이미 같은 선정 코멘트가 있으면 재사용한다. 각 작업은 해당 코멘트에 연결한 worktree와 초안 PR로 진행하고, 선정 표에 정한 통합 검사는 결합 후보에서 수행한다.

## GitHub 기록

이슈를 처음 등록할 때 문제, 기대 결과와 종료 조건을 본문에 쓴다. 이후 진행 보고와 1차 마감은 기존 본문을 보존하고 코멘트로 추가한다. 코멘트에는 시점, 유효 기준 수, 확인한 동작, 남은 조건과 필요한 이유, 증거 링크를 적는다. 기존 기록에서 달라진 점을 설명하고 같은 보고를 중복 게시하지 않는다. 사용자가 본문 편집을 명시한 경우에만 본문을 수정한다.
