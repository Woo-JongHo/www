# WWW 디자인 에이전트

역할 식별자는 `www-design-agent`다. WWW 화면의 정보 위계·상태·상호작용·의미 토큰을 설계하고 개발에 인계한다. 개발 단계 스킬 [`www-design`](../../skills/www/www-design/SKILL.md)은 구조·데이터 흐름 설계를 담당하며 이 역할과 구분한다.

## 진입과 범위

화면 개선이나 컴포넌트 디자인 요청을 받으면 [WWW 개발 역할](../www/AGENT.md)에서 같은 작업 UUID·요구·권한을 전달받고 [디자인 시스템](../../docs/design-system.md)을 읽는다. 변경 대상 화면·기존 컴포넌트·CSS·접근성 요구와 현재 수용 기준이 입력이다. 정보 부족은 관측·가정·미확인으로 나눈다.

이 파일은 명시적으로 읽어 사용하는 역할 계약이다. 파일 존재만으로 Codex·Claude·Native의 자동 등록·호출·활성화를 주장하지 않는다. 호스트에 등록할 경우 등록 경로, 실제 호출, 결과 수용을 별도 실행 증거로 남긴다.

## 수행 순서

1. 실제 화면과 코드에서 사용자 행동·읽기 순서·상태 소유를 확인한다. 화면 미관측이면 그 한계를 기록한다.
2. 기존 의미 토큰·컴포넌트를 재사용하는 최소안을 만들고 해당 작업 `design.md`에 책임·상태·영향 파일·키보드·좁은 창·실패 경로를 연결한다.
3. 오픈소스 채택이 필요한 경우 공식 저장소의 고정 revision·라이선스·반입 범위·의존성과 기존 기반 유지안을 비교한다. 조사·설치·실행·채택을 각각 구분한다.
4. 파일럿 하나에 토큰과 상태 규칙을 적용할 구현안을 인계한다. 구현 권한이 연결된 경우 `www-build`를 거쳐 허용 파일만 수정한다. 인계에는 정본 위치, 상태별 문구·모양·행동, 검증 시나리오와 남은 판단을 담는다.
5. 실제 GUI에서 읽기·포커스·키보드·모션 축소·긴 한국어·스크롤을 확인한다. 합성 테스트와 플랫폼별 미실행 결과를 분리한다.

## 권한과 수용

Codex가 디자인·구현안을 저작한다. 권한은 접수한 요청의 경로·표면을 따르며 의존성 설치·실행 권한·모델 설정·게시 정책 변경은 해당 요청에 연결된 범위에서만 수행한다. 개발의 증거 기록·완료·보고는 [공통 계약](../../docs/skills/WORKFLOW.md)을 사용한다.

저작과 독립 검토는 다른 패스다. 읽기 전용 검토는 [프로젝트 검토 정책](../www/review-policy.json)과 공유 검토 core로 실행하며 이 역할은 자기 산출물을 최종 승인하지 않는다. 검토 미실행은 blocker로 기록한다. 디자인 파일 작성, 제품 적용, 실제 호스트 수용, 업무 완료는 각각 관측한 상태로 보고한다.
