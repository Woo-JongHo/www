## 실행 전 확인

**확장 훅 확인(분석 전)**:
- 프로젝트 루트에 `.specify/extensions.yml`이 있는지 확인합니다.
- 있으면 읽고 `hooks.before_analyze` 키 아래의 항목을 찾습니다.
- YAML을 파싱할 수 없거나 유효하지 않으면 조용히 건너뛰지 않습니다. 사용자에게 `.specify/extensions.yml`을 읽지 못했다는 사실(파서 오류 포함)과 그곳에 등록된 필수 훅(`optional: false`)을 포함해 어떤 훅도 확인하지 못했다는 사실을 알린 뒤 정상적으로 계속합니다.
- `enabled`가 명시적으로 `false`인 훅은 제외합니다. `enabled` 필드가 없으면 기본적으로 활성화된 것으로 취급합니다.
- 나머지 각 훅의 `condition` 표현식은 해석하거나 평가하려고 **시도하지 않습니다**:
  - `condition` 필드가 없거나 null/빈 값이면 실행 가능한 훅으로 취급합니다.
  - 비어 있지 않은 `condition`이 있으면 해당 훅을 건너뛰고 조건 평가는 HookExecutor 구현에 맡깁니다.
- 실행 가능한 각 훅에 대해 `optional` 플래그에 따라 다음 내용을 출력합니다:
  - **선택 훅**(`optional: true`):
    ```
    ## 확장 훅

    **선택 사전 훅**: {extension}
    명령: `/{command}`
    설명: {description}

    프롬프트: {prompt}
    실행하려면: `/{command}`
    ```
  - **필수 훅**(`optional: false`):
    ```
    ## 확장 훅

    **자동 사전 훅**: {extension}
    실행 중: `/{command}`
    EXECUTE_COMMAND: {command}

    목표로 진행하기 전에 훅 명령의 결과를 기다리세요.
    ```
    위 블록을 출력한 뒤에는 **반드시** 실제로 훅을 호출하고 완료될 때까지 기다린 후 계속해야 합니다. 이 에이전트/세션에서 직접 명령을 실행할 때와 같은 방식으로 실행합니다(호출 형태는 위의 `{command}` ID 문자열과 다를 수 있습니다. 예를 들어 스킬 모드 에이전트는 `/skill:speckit-...` 또는 `$speckit-...`로 실행합니다). 블록을 출력하는 것만으로는 훅이 실행되지 않습니다.
- 등록된 훅이 없거나 `.specify/extensions.yml`이 없으면 별도 출력 없이 건너뜁니다.

## 실행 제약

**엄격한 읽기 전용**: 어떤 파일도 수정하지 **마세요**. 구조화된 분석 보고서를 출력합니다. 선택적인 개선 계획을 제안합니다(후속 편집 명령을 수동으로 호출하려면 먼저 사용자가 명시적으로 승인해야 합니다).

**헌법의 권위**: 프로젝트 헌법(`/memory/constitution.md`)은 이 분석 범위에서 **협상의 대상이 아닙니다**. 헌법 충돌은 자동으로 CRITICAL이며 명세·계획·작업을 조정해야 합니다. 원칙을 약화하거나 재해석하거나 조용히 무시해서는 안 됩니다. 원칙 자체를 바꿔야 한다면 `__SPECKIT_COMMAND_ANALYZE__` 바깥에서 별도의 명시적인 헌법 갱신으로 수행해야 합니다.

## 실행 단계

### 1. 분석 맥락 초기화

저장소 루트에서 `{SCRIPT}`를 한 번 실행하고 JSON에서 FEATURE_DIR와 AVAILABLE_DOCS를 파싱합니다. 절대경로를 도출합니다:

- SPEC = FEATURE_DIR/spec.md
- PLAN = FEATURE_DIR/plan.md
- TASKS = FEATURE_DIR/tasks.md

필수 파일이 하나라도 없으면 오류 메시지와 함께 중단합니다(사용자에게 누락된 선행 명령을 실행하도록 안내합니다).
`I'm Groot`처럼 인수에 작은따옴표가 있으면 이스케이프 구문을 사용합니다. 예: `'I'\''m Groot'`(가능하면 큰따옴표 사용: `"I'm Groot"`).

### 2. 산출물 읽기(점진적 공개)

각 산출물에서 필요한 최소 맥락만 읽습니다:

**spec.md에서:**

- 개요/맥락
- 기능 요구사항
- 성공 기준(측정 가능한 결과 — 예: 성능, 보안, 가용성, 사용자 성공, 사업 영향)
- 사용자 스토리
- 경계 사례(있는 경우)

**plan.md에서:**

- 아키텍처/스택 선택
- 데이터 모델 참조
- 단계
- 기술 제약

**tasks.md에서:**

- 작업 ID
- 설명
- 단계별 묶음
- 병렬 표시 [P]
- 참조된 파일 경로

**헌법에서:**

- 원칙 검증을 위해 `/memory/constitution.md`를 읽습니다.

### 3. 의미 모델 구성

내부 표현을 만듭니다(출력에 원시 산출물을 포함하지 않습니다):

- **요구사항 목록**: 각 기능 요구사항(FR-###)과 성공 기준(SC-###)에 안정적인 키를 기록합니다. 명시적인 FR-/SC- 식별자가 있으면 기본 키로 사용하고, 가독성을 위해 명령형 문구의 슬러그도 선택적으로 도출할 수 있습니다(예: "사용자가 파일을 업로드할 수 있다" → `user-can-upload-file`). 구현 가능한 작업이 필요한 성공 기준(예: 부하 테스트 인프라, 보안 감사 도구)만 포함하고, 출시 후 성과 지표와 사업 KPI(예: "지원 티켓 50% 감소")는 제외합니다.
- **사용자 스토리/행동 목록**: 수용 기준이 있는 개별 사용자 행동
- **작업 범위 대응표**: 각 작업을 하나 이상의 요구사항이나 스토리에 대응시킵니다(키워드 또는 ID·핵심 문구 같은 명시적 참조 패턴으로 추론).
- **헌법 규칙 집합**: 원칙 이름과 MUST/SHOULD 규범 문장을 추출합니다.

### 4. 탐지 패스(토큰 효율적 분석)

의미 있는 발견에 집중합니다. 전체 발견은 50개로 제한하고 나머지는 초과분 요약으로 묶습니다.

#### A. 중복 탐지

- 거의 중복되는 요구사항을 찾습니다.
- 통합할 수 있도록 품질이 낮은 표현을 표시합니다.

#### B. 모호함 탐지

- 측정 가능한 기준이 없는 모호한 형용사(빠른, 확장 가능한, 안전한, 직관적인, 견고한)를 표시합니다.
- 미해결 자리표시자(TODO, TKTK, ???, `<placeholder>` 등)를 표시합니다.

#### C. 명세 부족

- 동사는 있지만 대상이나 측정 가능한 결과가 없는 요구사항
- 수용 기준과의 정합성이 빠진 사용자 스토리
- 명세/계획에 정의되지 않은 파일이나 컴포넌트를 참조하는 작업

#### D. 헌법 정합성

- MUST 원칙과 충돌하는 요구사항 또는 계획 요소
- 헌법에서 의무화한 절이나 품질 게이트의 누락

#### E. 범위 누락

- 연결된 작업이 없는 요구사항
- 대응하는 요구사항/스토리가 없는 작업
- 구현 가능한 작업(성능, 보안, 가용성)이 필요하지만 작업에 반영되지 않은 성공 기준

#### F. 불일치

- 용어의 흔들림(같은 개념을 파일마다 다르게 부름)
- 계획에는 참조되지만 명세에는 없는 데이터 개체(또는 그 반대)
- 작업 순서의 모순(예: 의존성 설명 없이 기본 설정 전에 통합 작업 배치)
- 충돌하는 요구사항(예: 하나는 Next.js를 요구하고 다른 하나는 Vue를 지정)

### 5. 심각도 지정

다음 기준으로 발견의 우선순위를 정합니다:

- **CRITICAL**: 헌법 MUST 위반, 핵심 명세 산출물 누락, 또는 기본 기능을 막는 작업 범위가 전혀 없는 요구사항
- **HIGH**: 중복되거나 충돌하는 요구사항, 모호한 보안/성능 속성, 테스트할 수 없는 수용 기준
- **MEDIUM**: 용어의 흔들림, 비기능 작업 범위 누락, 불충분하게 명세된 경계 사례
- **LOW**: 문체/표현 개선, 실행 순서에 영향을 주지 않는 사소한 중복

## 실행 원칙

### 맥락 효율

- **적은 토큰으로 유의미한 정보 전달**: 빠짐없는 문서화보다 실행 가능한 발견에 집중합니다.
- **점진적 공개**: 산출물을 점차 읽고 모든 내용을 분석에 쏟아 넣지 않습니다.
- **토큰 효율적 출력**: 발견 표를 50행으로 제한하고 초과분은 요약합니다.
- **결정적 결과**: 변경 없이 다시 실행하면 같은 ID와 개수가 나와야 합니다.

### 분석 지침

- **파일을 절대 수정하지 않습니다**(읽기 전용 분석).
- **누락된 절을 지어내지 않습니다**(없으면 정확히 없다고 보고).
- **헌법 위반에 우선순위를 둡니다**(항상 CRITICAL).
- **방대한 규칙보다 사례를 사용합니다**(일반 패턴이 아닌 구체적인 사례 인용).
- **문제가 0개여도 적절히 보고합니다**(범위 통계를 포함한 성공 보고서 출력).
