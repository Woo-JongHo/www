# 구현이 아니라 행동을 테스트하기

테스트는 코드가 사용자, 즉 호출자나 최종 사용자 또는 다른 서비스를 위해 무엇을 하는지에 관한 주장이다. 행동은 그 사용자가 자신이 사용하는 인터페이스를 통해 관찰할 수 있는 것이다. 여기에는 반환값, 오류, 다시 읽을 수 있는 상태와 요청 전송, 행 기록, 메시지 발행처럼 코드 외부 시스템에 미치는 효과가 포함된다. 구현은 사용자가 관찰할 수 없는 것으로, 비공개 헬퍼, 내부 호출 순서, 중간 데이터 및 어떤 내부 협력자가 작업을 수행했는지가 이에 해당한다.

각 테스트를 상상 속의 두 가지 수정에 비추어 판단한다.

- **행동을 망가뜨린다.** 코드가 잘못된 값을 반환하거나 효과를 건너뛰거나 효과를 두 번 내게 한다. 그래도 테스트가 통과한다면 아무것도 증명하지 못한다. 일반적인 원인은 계약보다 느슨한 단언, 테스트 대상 코드가 계산한 예상값, 해당 값을 읽는 코드를 실행하지 않는 상수나 프롬프트 문자열의 재진술, 테스트가 스스로 만든 데이터에 관한 단언이다.
- **내부를 변경한다.** 관찰 가능한 모든 결과를 동일하게 유지하면서 그 아래의 코드를 재구성한다. 이제 테스트가 실패한다면 구현에 고정된 것이다. 리팩터링할 때마다 다시 작성해야 하면서도 버그는 잡지 못한다.

첫 번째 수정을 잡고 두 번째 수정에도 살아남는 테스트를 유지한다. 나머지는 다시 작성하거나 삭제한다. 두 조건을 모두 충족하는 테스트를 작성하려면 구체적인 입력으로 사용자의 인터페이스를 통해 코드를 구동한다. 예상값은 코드 실행 결과가 아니라 요구사항에서 도출한다. 계약이 약속하는 내용을 그보다 적지도 많지도 않게 단언한다.

단언의 형태가 아니라 계약이 결정한다. "빈 장바구니에는 절대 요금을 청구하지 않는다"가 약속이라면 결제 클라이언트가 호출되지 않았다는 단언은 행동이다. 호출을 감지할 수 있음을 테스트가 보여 주도록 실제 청구가 일어나는 사례와 짝을 이룬다. 모의 외부 서비스가 받는 payload는 그 서비스가 관찰하므로 행동이다. 내부 헬퍼 호출은 어떤 사용자도 볼 수 없으므로 구현이다. 일치하는 레코드가 없을 때 빈 목록은 정확한 답이지만, 테스트가 그저 어떤 결과만 필요로 할 때는 공허한 검사다. 어떤 호출자도 읽지 않는 정확한 오류 메시지는 문구를 고정한다. 호출자가 분기 판단에 사용하는 오류 타입은 계약이다.

테스트는 호출 대신 두 테이블에 반드시 존재해야 하는 키나 컴파일 시점 타입 검사 같은 불변 조건을 고정할 수 있다. 그 불변 조건이 행동이다.
