# 작업을 검증 가능한 단위로 배열하기

작업을 작은 단위의 연속으로 배열하되, 각 단위를 확인 가능한 상태로 끝내고 현재 단위가 정상 상태가 될 때까지 다음으로 넘어가지 않는다.

**이유:** 문제를 일으킨 단위에서 발견한 문제는 원인을 찾기 쉽다. 일괄 작업 후에 발견한 문제는 묻혀 있으며, 이미 망가진 기반 위에 후속 작업까지 쌓은 상태다. 동일한 단위들을 검토자가 재현할 수 있는 전달물로 배열하면 "믿어 달라"가 "실패했다가 성공하는 과정을 보라"로 바뀐다.

**실행.** 일괄 순회, 마이그레이션 또는 유사한 수정이 이어지는 모든 작업에서는 다음 수정을 시작하기 전에 각 변경을 검증한다. 각 단위는 전후를 감싸는 구조다. 정상임을 아는 상태에서 시작해 하나를 변경하고 검사를 실행한 다음 진행한다. 먼저 깨끗한 trunk 위로 rebase하여 모든 검사가 실제 기준선과 비교되게 한다. 도구가 수정을 수행하면 단위별 검사는 비용이 거의 들지 않는다. 그래도 실행한다.

**전달.** 작업을 증명하는 순서로 커밋과 PR을 쌓는다. 정석적인 형태는 실패하는 테스트를 먼저 두고 그 위에 수정 사항을 놓는 것이다. 그 밖의 이야기 순서로는 형태 변경 전의 제거, 처치 전의 기준선 기록, 기능 전의 뼈대가 있다. 각 커밋은 독립적으로 적용되며 그 순서는 하나의 논증처럼 읽힌다.

각 검사를 실제 검사가 되게 하는 **prove-it-works** 원칙 스킬 및 단위별 검사를 저렴하게 만드는 **build-the-lever** 원칙 스킬과 짝을 이루는 배열 원칙이다.
