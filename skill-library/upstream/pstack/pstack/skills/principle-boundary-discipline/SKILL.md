# 경계 규율

검증, 타입 좁히기, 오류 처리를 시스템 경계에 배치합니다. 내부 코드는 조건 없이 신뢰합니다. 비즈니스 로직은 순수 함수에 둡니다. 셸은 얇고 기계적으로 유지합니다.

**이유:** 흩어진 검증은 잡음이 많고 중복되며 잘못된 안전감을 줍니다. 프레임워크 없이도 테스트할 수 있도록 프레임워크 연결부에서 로직을 분리합니다.

**패턴:**
- **경계에서** (CLI 인수, 설정 파일, 외부 API, 네트워크 프로토콜): 검증하고, 오류를 반환하며, 방어적으로 처리합니다.
- **시스템 내부에서:** 타입이 지정된 데이터, 오류 전파, 재검증 없음. 타입을 신뢰합니다.
- **경계를 가로질러.** 경계의 비공개 표현이 아니라 도메인 개념을 노출합니다. 범용 메커니즘은 내부에, 특수 목적 정책은 가장자리에 둡니다.

**적용:**

검증 및 오류 처리:
- 비즈니스 로직 내부가 아니라 파싱 시점(경계)에 설정을 검증합니다.
- 경계에서 원시 데이터를 도메인 타입으로 파싱합니다.
- 공개 표면을 통해 전송, 저장, 프레임워크 또는 통신 규약 타입을 다시 내보내지 않습니다.
- 경계에서 이미 검증했다면 호출 체인 깊숙한 곳에서 중복 nil 검사를 하지 않습니다.

코드 구성:
- 프레임워크 의존성이 없는 순수 함수에 비즈니스 로직을 둡니다.
- 파싱 함수: 원시 바이트를 타입이 지정된 상태로 바꾸는 순수 변환
- 프롬프트 구성: 구조화된 상태를 입력받아 문자열을 출력
- 점수 계산 및 평가: 상태를 결과로 바꾸는 순수 변환

**검사:**
- "이 데이터가 지금 시스템 경계를 통과하고 있는가?" 아니라면 검증은 중복입니다.
- "셸이 단순히 호출하기만 하는 순수 함수로 만들 수 있는가?" 그렇다면 추출합니다.
