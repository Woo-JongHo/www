# 동작을 증명하라

실물을 직접 확인하여 모든 작업 결과물을 검증한다. 대리 지표, 자기 보고 또는 "컴파일된다"는 사실로 추론하지 않는다.

**이유:** 검증하지 않은 작업은 정확성을 알 수 없다. 간접 검증(파일 수정 시각, 출력의 최신성, 에이전트의 자기 보고, 캐시된 스크린샷)은 직접 관찰보다 비용이 적게 드는 것처럼 느껴진다. 잘못된 추론에 따라 행동하는 비용은 소스를 확인하는 비용보다 훨씬 크다.

대리 지표가 아니라 실물을 확인한다.
- 파생된 상태를 통해 간접적으로 확인하지 말고 프로세스의 생존 여부를 직접 확인한다
- 캐시되거나 파생된 표현이 아니라 실제 값을 읽는다
- 검증이 실패하면 시스템을 의심하기 전에 관찰 방법을 의심한다

## 가능하다면 검사를 스크립트로 작성하라

가장 강력한 증거는 한 번 눈으로 확인하는 것이 아니라 같은 비교를 다시 실행하는 결정론적 스크립트다. 스크립트를 작성하고 실행한 뒤, 검토자가 당신의 말을 믿는 대신 다시 실행할 수 있도록 그 출력을 아티팩트로 보관한다.

사람이 볼 수 있도록 아티팩트를 유지한다. 대규모 포팅이나 마이그레이션처럼 나중에 이력을 감사할 수 있어야 하는 크거나 복잡한 작업에서만 커밋한다(**show-me-your-work** 스킬).
