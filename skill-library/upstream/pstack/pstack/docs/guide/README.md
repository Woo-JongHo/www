# pstack 가이드

에이전트를 세세하게 관리하지 않을 때 pstack이 가장 잘 작동합니다. 원하는 것과 완료 여부를 판단할 방법을 설명하세요. `/poteto-mode`는 플레이북을 선택하고, 단계에서 필요로 하는 다른 스킬을 실행하며, 증거를 보여 줍니다. 이 가이드는 현실적인 프롬프트를 통해 그 습관을 가르칩니다.

다음 내용을 배우게 됩니다.

1. [pstack 설정](./01-setup.md). 플러그인을 설치하고 모델을 선택합니다.
2. [`/poteto-mode`를 통한 작업 라우팅](./02-poteto-mode.md). 목표를 주고 플레이북을 선택하는 모습을 지켜봅니다.
3. [코드 이해](./03-understand.md). 읽기 전용 조사 후, 무엇이든 수정하기 전에 `/how`, `/why`, `/teach`, `/recall`을 사용합니다.
4. [변경 설계](./04-design.md). 코드의 형태가 굳어지기 전에 `/architect`, `/arena`, `/swarm`, `/interrogate`, 프로토타입, 계획을 사용합니다.
5. [변경 빌드 및 정리](./05-build-and-clean.md). 빌드 플레이북, `/tdd`, `/unslop`, `/no-comments`를 사용합니다.
6. [검증 및 배포](./06-verify-and-ship.md). 실제 앱에서 동작을 입증하고, 테스트가 좀처럼 닿지 못하는 부분을 형식적으로 검증하고, `/benchmark-checklist`로 수치를 검토한 다음, 초점이 분명한 PR을 열어 병합까지 진행합니다.
7. [잠자는 동안 작업 실행](./07-overnight.md). 루프보다 신뢰를 먼저 확보하고, 야간 계약, 감사할 수 있는 결정 로그, 한 에이전트를 넘어 확장되는 Projects와 자동화를 사용합니다.
8. [원칙 이름으로 방향 조정](./08-principles.md). 작업 도중 에이전트의 방향을 바꾸는 24가지 이름을 배웁니다.
9. [자신에게 맞게 만들기](./09-make-it-yours.md). 자신만의 모드, 반복되는 실수를 위한 `/correct`, 스킬 변경을 테스트하는 방법을 다룹니다.
10. [레시피와 함정](./10-recipes-and-pitfalls.md). 복사할 프롬프트와 피해야 할 실수를 다룹니다.

처음에는 페이지를 순서대로 읽으세요. 그다음부터는 각 페이지를 독립적으로 볼 수 있습니다.

막혔거나 어떤 스킬이 맞는지 판단할 수 없다면 질문과 함께 [`/poteto-help`](https://github.com/cursor/plugins/blob/63912a91d52c43946f974f2aaf661334a6116a82/pstack/skills/poteto-help/SKILL.md)를 입력하세요.

```text
/poteto-help 이 브랜치를 검토하려면 어떤 스킬을 사용해야 하지?
```

질문에 답하고, 전송할 프롬프트를 건네며, 답변의 출처인 스킬이나 가이드 페이지를 링크합니다. pstack 실행은 실제 토큰을 사용하므로 작업을 시작하지 않으며, 준비되었을 때 직접 프롬프트를 전송하면 됩니다. 직접 입력했을 때만 실행됩니다.

## 한 가지만 기억한다면

자신의 말로 에이전트에게 목표와 확인 방법을 알려 주세요.

```text
/poteto-mode 실행 도중 재시도가 들어오면 내보내기가 중복 행을 기록한다. 먼저 재현하고, 그런 다음 수정하고 검증해.
```

플레이북 이름을 대거나 스킬을 나열할 필요가 없습니다. "먼저 재현"과 확인 가능한 결과만 있으면 `/poteto-mode`에 필요한 라우팅 신호가 모두 갖춰집니다. 버그 수정 플레이북을 연결하고, 단계를 할 일 목록에 복사하며, 각 단계가 시작될 때 적절한 스킬을 호출합니다.
