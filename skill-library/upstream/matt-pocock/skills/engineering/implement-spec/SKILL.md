> 한국어 번역본: 고정 커밋 `4ae2317ddb22b046e26455e4f9c9b3aaaf62212d`의 원문을 한국어로 번역해 수정했습니다. 출처·원문 해시·라이선스는 `skill-library/sources.json`과 `skill-library/inventory.json`에 기록합니다.


명세가 제공되었습니다. 이 명세에는 명세를 구현하는 방법을 설명하는 티켓이 연결되어 있어야 합니다.

이슈 트래커도 제공되어 있어야 합니다. 그렇지 않다면 사용자에게 `/setup-matt-pocock-skills`를 실행하라고 안내하세요.

목표는 전체 명세를 하나의 **통합 브랜치**에 구현하고, 이슈 트래커가 작업을 닫는 방식에 따라 모든 티켓을 해결하는 것입니다.

티켓은 단계 목록이 아닙니다. 티켓들은 서로 차단 관계를 가진 **작업 그래프**입니다. 이는 언제나 바로 가져갈 수 있는 티켓들의 **프런티어**가 존재한다는 뜻입니다.

모든 하위 에이전트를 새로운 컨텍스트 창으로 시작하세요.

하위 에이전트와 주고받는 소통은 최소화해야 합니다. 주로 명세, 티켓, 조사 노트, 이전 커밋을 가리키는 **컨텍스트 포인터**를 통해 소통하세요. 포인터로 이미 확인할 수 있는 정보를 중복하지 마세요.

동시성을 극대화하려면 가능한 경우 **구현자 하위 에이전트**를 백그라운드에서 실행해야 합니다.

## 단계

1. 명세와 티켓을 읽고 작업 그래프를 이해하세요.

2. (선택 사항) **탐색 하위 에이전트**를 사용해 티켓에 필요한 탐색을 수행하세요. 관련 코드베이스 파일이나 외부 문서를 탐색합니다. 탐색 하위 에이전트가 파일을 저장할 수 있는지 확인하세요. 이후의 모든 하위 에이전트가 접근할 수 있도록 저장소 밖의 디렉터리에 마크다운 노트를 저장해야 합니다. 이렇게 하면 **구현자 하위 에이전트**가 탐색이 아니라 구현에 집중할 수 있습니다.

3. 통합 브랜치를 만드세요. 이슈 트래커가 PR을 통해 작업을 닫거나 사용자가 PR을 요청한 경우, 5단계에서 첫 병합을 마친 뒤 명세와 티켓을 닫는 것으로 표시한 초안 PR을 여세요(main보다 앞선 커밋이 없는 브랜치로는 PR을 열 수 없습니다).

4. 각 티켓마다 새로운 **구현자 하위 에이전트**를 사용하고, 각각 자체 브랜치의 자체 worktree에서 작업하게 하세요. 각 구현자 하위 에이전트는:
   - 시작하기 전에 자신의 worktree가 통합 브랜치를 기반으로 하는지 확인하고, 그렇지 않다면 그 브랜치로 재설정합니다.
   - 티켓을 구현하기 위해 `tdd`로 Skill 도구를 호출합니다.
   - 완료를 보고하기 전에 통합 브랜치의 최신 상태를 자신의 브랜치에 병합합니다.

5. **구현자 하위 에이전트**가 완료되면 **병합자 하위 에이전트**를 사용해 그 작업을 통합 브랜치에 병합하세요.

6. 이로 인해 사용 가능한 티켓의 **프런티어**가 바뀌면 더 많은 **구현자 하위 에이전트**를 가동해 새 티켓을 작업하게 하세요. 이렇게 하면 동시성을 극대화할 수 있습니다.

7. 모든 티켓이 완료되면 통합 브랜치에서 `code-review`로 Skill 도구를 호출하세요. 코드 리뷰에서 제기된 모든 문제를 하나의 새로운 **구현자 하위 에이전트**에서 수정하세요.

8. 초안 PR이 있다면 리뷰 준비 완료로 표시하세요. 그렇지 않다면 이슈 트래커가 작업을 닫는 방식에 따라 각 티켓을 해결하고 통합 브랜치를 보고하세요.

9. 모든 **구현자 하위 에이전트**의 worktree를 정리하세요.
