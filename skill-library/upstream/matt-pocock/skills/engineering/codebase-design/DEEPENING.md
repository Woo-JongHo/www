# 심화

의존성을 고려하여 얕은 모듈 군집을 안전하게 심화하는 방법입니다. [SKILL.md](SKILL.md)의 어휘인 **모듈**, **인터페이스**, **심**, **어댑터**를 전제로 합니다.

## 의존성 범주

심화 후보를 평가할 때는 의존성을 분류하세요. 범주에 따라 심화된 모듈을 심 너머에서 테스트하는 방법이 결정됩니다.

### 1. 프로세스 내부

순수 계산, 메모리 내 상태, I/O 없음. 항상 심화할 수 있습니다. 모듈을 병합하고 새 인터페이스를 통해 직접 테스트하세요. 어댑터가 필요하지 않습니다.

### 2. 로컬 대체 가능

로컬 테스트 대역이 있는 의존성(Postgres용 PGLite, 메모리 내 파일 시스템). 대역이 있으면 심화할 수 있습니다. 테스트 스위트에서 대역을 실행하여 심화된 모듈을 테스트합니다. 심는 내부에 있으며 모듈의 외부 인터페이스에는 포트가 없습니다.

### 3. 원격이지만 소유함(포트와 어댑터)

네트워크 경계 너머에 있는 자체 서비스(마이크로서비스, 내부 API). 심에 **포트**(인터페이스)를 정의하세요. 깊은 모듈이 로직을 소유하고 전송 계층은 **어댑터**로 주입합니다. 테스트는 메모리 내 어댑터를 사용합니다. 프로덕션은 HTTP/gRPC/큐 어댑터를 사용합니다.

권장 형식: *"심에 포트를 정의하고 프로덕션용 HTTP 어댑터와 테스트용 메모리 내 어댑터를 구현하여, 네트워크 너머에 배포되더라도 로직이 하나의 깊은 모듈에 있도록 하세요."*

### 4. 진정한 외부 의존성(모의 객체)

통제할 수 없는 서드파티 서비스(Stripe, Twilio 등). 심화된 모듈은 외부 의존성을 주입된 포트로 받으며, 테스트는 모의 어댑터를 제공합니다.

## 심 규율

- **어댑터가 하나면 가상 심이고, 둘이면 실제 심입니다.** 최소 두 개의 어댑터(일반적으로 프로덕션 + 테스트)가 타당하지 않다면 포트를 도입하지 마세요. 어댑터 하나뿐인 심는 단지 간접 계층일 뿐입니다.
- **내부 심와 외부 심.** 깊은 모듈에는 인터페이스의 외부 심뿐 아니라 내부 심(구현에 비공개이고 자체 테스트에서 사용됨)도 있을 수 있습니다. 테스트에서 사용한다는 이유만으로 인터페이스를 통해 내부 심를 노출하지 마세요.

## 테스트 전략: 쌓지 말고 교체하기

- 심화된 모듈의 인터페이스에 대한 테스트가 생기면 얕은 모듈의 기존 단위 테스트는 낭비가 되므로 삭제하세요.
- 심화된 모듈의 인터페이스에서 새 테스트를 작성하세요. **인터페이스가 테스트 표면입니다.**
- 테스트는 내부 상태가 아니라 인터페이스를 통해 관찰 가능한 결과를 단언합니다.
- 테스트는 구현이 아니라 동작을 기술하므로 내부 리팩터링 후에도 살아남아야 합니다. 구현이 바뀔 때 테스트도 바뀌어야 한다면 인터페이스 너머를 테스트하는 것입니다.
