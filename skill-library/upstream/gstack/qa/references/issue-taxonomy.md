# QA 이슈 분류 체계

## 심각도 수준

| 심각도 | 정의 | 예시 |
|----------|------------|----------|
| **critical** | 핵심 워크플로를 막거나, 데이터 손실을 일으키거나, 앱을 충돌시킴 | 양식 제출 시 오류 페이지 표시, 결제 흐름 손상, 확인 없이 데이터 삭제 |
| **high** | 주요 기능이 손상되었거나 사용할 수 없고 우회 방법이 없음 | 검색이 잘못된 결과 반환, 파일 업로드가 조용히 실패, 인증 리디렉션 루프 |
| **medium** | 기능은 동작하지만 눈에 띄는 문제가 있고 우회 방법이 있음 | 느린 페이지 로드(>5s), 양식 유효성 검사는 없지만 제출은 가능, 모바일에서만 레이아웃 손상 |
| **low** | 사소한 외관 또는 마감 문제 | 바닥글 오타, 1px 정렬 문제, 일관성 없는 hover 상태 |

## 범주

### 1. 시각/UI
- 레이아웃 손상(요소 겹침, 잘린 텍스트, 가로 스크롤바)
- 깨졌거나 누락된 이미지
- 잘못된 z-index(다른 요소 뒤에 표시되는 요소)
- 글꼴/색상 불일치
- 애니메이션 결함(jank, 불완전한 전환)
- 정렬 문제(그리드 이탈, 고르지 않은 간격)
- 다크 모드 / 테마 문제

### 2. 기능
- 깨진 링크(404, 잘못된 대상)
- 작동하지 않는 버튼(클릭해도 아무 일 없음)
- 양식 유효성 검사(누락, 오류, 우회됨)
- 잘못된 리디렉션
- 상태가 유지되지 않음(새로 고침, 뒤로 가기 시 데이터 손실)
- 경쟁 상태(이중 제출, 오래된 데이터)
- 검색이 잘못된 결과를 반환하거나 결과가 없음

### 3. UX
- 혼란스러운 탐색(현재 위치를 보여 주는 경로 탐색 없음, 막다른 경로)
- 로딩 표시기 누락(사용자가 진행 중인 작업을 알 수 없음)
- 느린 상호작용(피드백 없이 >500ms)
- 불명확한 오류 메시지(세부 정보 없는 "Something went wrong")
- 파괴적 작업 전 확인 없음
- 페이지 간 일관성 없는 상호작용 패턴
- 막다른 경로(돌아가거나 다음 작업을 할 방법 없음)

### 4. 콘텐츠
- 오타 및 문법 오류
- 오래되었거나 잘못된 텍스트
- 남아 있는 placeholder / lorem ipsum 텍스트
- 잘린 텍스트(말줄임표나 "more" 없이 잘림)
- 버튼 또는 양식 필드의 잘못된 레이블
- 누락되었거나 도움이 되지 않는 빈 상태

### 5. 성능
- 느린 페이지 로드(>3초)
- 끊기는 스크롤(프레임 누락)
- 레이아웃 이동(로드 후 콘텐츠가 튐)
- 과도한 네트워크 요청(단일 페이지에서 >50개)
- 최적화되지 않은 대용량 이미지
- 차단 JavaScript(로드 중 페이지가 응답하지 않음)

### 6. 콘솔/오류
- JavaScript 예외(포착되지 않은 오류)
- 실패한 네트워크 요청(4xx, 5xx)
- 사용 중단 경고(향후 손상 가능성)
- CORS 오류
- 혼합 콘텐츠 경고(HTTPS의 HTTP 리소스)
- CSP 위반

### 7. 접근성
- 이미지의 alt 텍스트 누락
- 레이블 없는 양식 입력
- 키보드 탐색 손상(요소로 tab 이동 불가)
- 포커스 트랩(모달 또는 드롭다운에서 벗어날 수 없음)
- 누락되었거나 잘못된 ARIA 속성
- 불충분한 색상 대비
- 스크린 리더로 접근할 수 없는 콘텐츠

## 페이지별 탐색 체크리스트

QA 세션 중 방문한 각 페이지에서:

1. **시각적 검사** — 스크린샷을 찍는다(페이지 읽기 스크립트, ref 레이블이 필요하면 `annotatedScreenshot(pg)`). 레이아웃 문제, 깨진 이미지, 정렬을 찾는다.
2. **대화형 요소** — 모든 버튼, 링크, 컨트롤을 클릭한다. 각각 표기된 대로 동작하는가?
3. **양식** — 채우고 제출한다(비로컬 대상: 먼저 동의 — 브라우저 규칙 3). 빈 제출, 잘못된 데이터, 경계 사례(긴 텍스트, 특수 문자)를 테스트한다.
4. **탐색** — 모든 진입/이탈 경로를 확인한다. 현재 위치를 보여 주는 경로 탐색, 뒤로 가기 버튼, 딥 링크, 모바일 메뉴.
5. **상태** — 빈 상태, 로딩 상태, 오류 상태, 가득 참/오버플로 상태를 확인한다.
6. **콘솔** — 상호작용 후 `CONSOLE_ERRORS=`를 출력한다. 새 JS 오류나 실패한 요청이 있는가?
7. **반응형** — 해당하는 경우 모바일과 태블릿 뷰포트를 확인한다.
8. **인증 경계** — 사용자를 직접 로그아웃시키거나 계정을 전환하지 않는다. 로그아웃 상태 또는 다른 역할 보기가 중요하면, 사용자에게 Aside에서 로그아웃 / 전환한 뒤 페이지 스크립트를 다시 실행하도록 요청한다.
