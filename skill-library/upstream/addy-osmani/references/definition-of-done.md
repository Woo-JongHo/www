# 완료 정의

모든 변경이 완료로 인정되기 전에 충족해야 하는, 프로젝트 전반에 상시 적용되는 기준이다. 작업마다 달라지며 "올바른 것을 만들었는가?"에 답하는 수용 기준과 달리, 완료 정의는 매번 동일하며 "우리 기준에 맞게 끝났는가?"에 답한다. `planning-and-task-breakdown`, `incremental-implementation`, `shipping-and-launch`에서 최종 관문으로 사용한다.

## 완료 정의와 수용 기준의 차이

| | 수용 기준 | 완료 정의 |
|---|---|---|
| 범위 | 하나의 작업이나 명세에 한정 | 모든 증분에 적용 |
| 변경 | 항목마다 다름 | 고정하여 재사용 |
| 답변 | "*이것*을 만들었는가?" | "*준비되었는가*?" |
| 소유자 | 작업을 계획할 때 정의 | 프로젝트에서 한 번 정의 |
| 예시 | "사용자가 이메일 링크로 비밀번호를 재설정할 수 있음" | "테스트 통과, 회귀 없음, 문서 갱신됨" |

둘은 상호 보완적이다. 작업은 **해당 작업의** 수용 기준을 충족하고 **동시에** 상시 적용되는 완료 정의를 만족할 때만 완료된다. 둘 중 하나라도 건너뛰면 겉보기에는 끝났지만 실제로는 끝나지 않은 작업이 남는다.

## 상시 체크리스트

완료를 선언하기 전에 모든 변경에 이를 적용한다.

### 정확성
- [ ] 작업의 모든 수용 기준을 충족함
- [ ] 코드가 실행되고 의도대로 동작하며, 컴파일이나 타입 검사만이 아니라 런타임에서 검증됨
- [ ] 변경이 없으면 실패하고 변경이 있으면 통과하는 테스트로 새 동작을 다룸
- [ ] 기존 테스트가 계속 통과하고 회귀가 발생하지 않음
- [ ] 정상 경로뿐 아니라 경계 사례와 오류 경로도 처리함

### 품질
- [ ] 이름과 구조를 통해 코드가 의도를 드러내며, *무엇을* 하는지 설명하는 주석이 필요하지 않음
- [ ] 중복된 비즈니스 로직이 없음
- [ ] 죽은 코드, 디버그 출력, 주석 처리된 블록이 남아 있지 않음
- [ ] 변경 범위가 해당 작업으로 한정되며 관련 없는 리팩터링이 끼어들지 않음
- [ ] 린트와 포매팅을 통과함

이 항목들의 상세 기준은 `code-review-and-quality`(5축 검토)와 `code-simplification`(동작을 바꾸지 않고 복잡성 줄이기)에 있다.

### 통합
- [ ] 변경이 격리된 환경에서만이 아니라 시스템의 나머지 부분과 함께 동작함
- [ ] 데이터베이스 마이그레이션, 구성 변경, 기능 플래그를 고려함
- [ ] 공개 인터페이스나 API 변경에서 하위 호환성을 고려함

### 문서화
- [ ] 공개 인터페이스, API, 사용자 대상 동작을 문서화함
- [ ] 보존할 가치가 있는 아키텍처 결정을 기록함(`documentation-and-adrs` 참조)
- [ ] 문서가 변경 이력이 아니라 현재 상태를 시점에 구애받지 않는 언어로 설명함

### 출시 준비
- [ ] 신뢰하지 않는 입력, 인증, 데이터 처리의 보안 영향을 검토함(`security-and-hardening` 참조)
- [ ] 새로운 핵심 경로에 관측성(로그, 메트릭, 추적)을 마련함(`observability-and-instrumentation` 참조)
- [ ] 위험한 모든 항목에 롤백 경로가 있음(`shipping-and-launch` 참조)
- [ ] 병합이나 배포 전에 사람이 검토하고 승인함

## 적용 방법

- **작업별**: 작업을 완료로 표시하기 전에 정확성과 품질 섹션을 확인한다.
- **기능별**: 기능 완료로 보기 전에 통합과 문서화를 확인한다.
- **릴리스별**: 전체 체크리스트가 최소 기준이며, `shipping-and-launch`가 그 위에 배포별 관문을 추가한다.

목록은 프로젝트에 맞게 한 번 조정한 다음 변경 없이 재사용한다. 스프린트마다 다시 협상하는 완료 정의는 완료 정의가 아니다.

## 위험 신호

- "끝났는데 아직 실행은 안 해봤어요": 검증되지 않은 작업은 완료된 것이 아니다.
- 문서, 회귀, 런타임 검증을 건너뛰면서 "테스트 통과"를 완료의 동의어로 사용함.
- 마감 압박에 따라 서로 다른 기준을 적용함.
- 상시 적용되는 최소 품질 기준 없이 수용 기준을 전체 기준으로 취급함.
- 사람의 검토가 필요한 변경에서 검토 전에 "완료"를 선언함.
