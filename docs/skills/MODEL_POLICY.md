# WWW Skills 모델·추론 노력 권고

## 정책의 적용 범위

사용자와 논의한 Sol·Terra·Luna 혼합 사용을 권장 정책으로 기록한다. 이는 실행 라우터나 계정 설정이 아니다. 세션의 상위 모델·검토 규율과 [공통 계약](WORKFLOW.md#독립-검토의-책임)이 우선하며, 이 문서는 단계별 보조 후보만 설명한다. 클라이언트가 스킬별 모델·추론 노력 전환을 지원하는지, 계정에서 모델과 요청한 effort 값을 사용할 수 있는지는 적용 전에 확인한다. 이 문서는 `.gjc`나 Native 실행 설정을 자동 변경하지 않는다.

## 스킬별 역할

| 스킬 | 주 모델 후보 | 주 모델 기본 effort | 보조 모델의 역할 |
|---|---|---|---|
| `www-spec` | Sol | high | Terra로 화면 흐름과 사용자 시나리오 구체화 |
| `www-design` | Sol | high | Terra로 시각 자료와 상호작용 검토 |
| `www-build` | Sol | medium | Luna로 범위·기대 결과가 명확한 반복 수정 |
| `www-diagnose` | Sol | high | Terra로 화면 문제 관찰, Luna로 로그 분류·요약 |
| `www-verify` | Sol | medium | Terra로 UI 실동작 확인, Luna로 검증 결과 정리 |
| `www-commit` | Sol | medium | Luna는 확인된 diff의 메시지 초안만 보조하며 범위·권한·검증 판정은 맡기지 않음 |

모델 식별자 후보는 Sol=`gpt-6.1-sol`, Terra=`gpt-6.1-terra`, Luna=`gpt-6-luna`다. 이는 계정 가용성이나 설치된 클라이언트의 실제 지원을 확인한 값이 아니다.

단순 문구·템플릿 정리처럼 범위와 기대 결과가 명확한 반복 작업은 공식 [모델 안내](https://learn.chatgpt.com/docs/models?surface=cli)가 설명하는 Luna의 focused high-volume tasks·summary·extraction 용도에 맞는 후보로 삼는다. 구조나 동작에 미치는 영향을 판단하는 문서 갱신은 해당 소스를 작성한 Codex가 같은 작업 맥락에서 수행하며, 매번 별도 모델 호출을 추가하지 않는다. 이 배치는 비용 절감량이나 성능 우위를 실측한 주장이 아니다.

보조 Terra는 지원될 경우 medium, Luna의 단순 추출·요약은 지원될 경우 low를 시작 후보로 둔다. 지원하지 않는 effort를 다른 값으로 조용히 바꾸지 않고 제한을 알린다. 상태·IPC·보안·동시성처럼 위험한 구현·검증은 Sol high를 검토한다. 이미 같은 가정에 기반한 수정이 반복 실패했다면 노력만 올리지 말고 가정을 판별할 검사를 먼저 만든다. `xhigh`를 일괄 요구하지 않는다.

## 모델 간 인계

- 모든 작업에 세 모델을 호출하지 않는다. 단순한 변경은 한 모델로 끝내며 필요한 역할만 분리한다.
- 같은 작업 ID와 명세·수용 기준·기존 결정을 전달한다. 대상 파일과 수정 권한, 관측한 사실, 미확인 사항, 증거 위치를 함께 전달한다.
- Sol이 핵심 계약과 통합 판단을 맡는다. Terra는 화면을 볼 실제 도구가 있어야 UI를 확인했다고 할 수 있다. Luna는 핵심 권한·상태 계약을 임의 변경하거나 요약만으로 완료를 판정하지 않는다.
- 보조 결과는 원본과 diff·실행 증거로 확인한다. 서로 의존하거나 같은 파일을 쓰는 작업을 무조건 병렬 실행하지 않는다. 필요한 공유 변경은 담당자를 정해 순서대로 처리한다.
- 저작·통합과 읽기 전용 검토를 별도 패스로 수행한다. 검토 기본 모델과 대체 조건의 정본은 [프로젝트 검토 정책](../../agents/www/review-policy.json)이며 [공통 계약](WORKFLOW.md#독립-검토의-책임)이 책임과 미실행 처리를 설명한다. 이 문서의 보조 모델 후보를 근거로 검토 모델을 임의 선택하지 않는다. 모델이 다르다는 사실만으로 검증의 정확성이나 실제 독자의 승인을 보장하지 않는다.
- 검증 기록에는 요청한 모델·effort와 실제 관측한 값을 구분한다. 실제값이 보이지 않으면 미확인으로 남기며 요청값을 실제값으로 쓰지 않는다.

## Chat 적용 예시

Sol이 Native 흐름·승인·중단·실행 상태의 명세를 정리하고, 필요한 경우 Terra가 실행 박스와 읽기 흐름을 검토한다. 구현 승인 후 Sol이 핵심 연결을 구현하고, 실제 UI 검증에는 Terra와 화면 도구를 사용할 수 있다. Luna는 확보된 검사 결과를 양식에 정리할 수 있지만 테스트를 수행하지 않은 채 성공을 생성할 수 없다.

이 모델 분담은 WWW 자체를 개발하는 절차다. 사용자가 WWW Chat에서 사용하는 Native의 모델을 자동 전환한다는 뜻이 아니다. 실제 추가 호출과 라우팅은 아직 구현·실행하지 않았다.

## 근거와 한계

공식 [모델 선택 안내](https://developers.openai.com/codex/models/)는 2026-11-11 조회에서 Sol을 복잡한 코드·문서 작업의 후보, Terra를 글쓰기·시각·컴퓨터 사용, Luna를 집중적 반복 작업 후보로 설명했다. 여기의 스킬별 배치와 effort는 WWW의 권고이며 성능 비교 실험·가격·계정 가용성·지원 effort의 검증 결과가 아니다. 결정론적 검사 명령은 effort를 높이는 대신 실제로 실행하고 결과를 읽어야 한다.
