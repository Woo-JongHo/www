# WWW 작업 내부 모델 배분

## 책임과 선택

Sol이 작업의 수용 기준·공통 계약·위험한 연결부·최종 통합을 소유한다. 품질과 독립 검토를 유지하면서 작업 완료까지의 총 토큰을 효율화하는 것이 목적이다. 작업 내부는 실패 위험과 판단 난도에 따라 분해한다. 이 문서는 실행 절차이며 계정 기본 모델 설정이 아니다.

| 내부 단위 | 기본 후보 | 맡길 범위 |
|---|---|---|
| 수집·축자 대조·확정 패턴의 작은 구현 | Luna | 로그 분류·목록·단일 파일 반복 수정 |
| 조사·일상 검증·경계가 분명한 기능 | Terra | 화면·필터·순수 변환·행동 테스트·도구를 사용한 UI 확인 |
| 상태·권한·동시성·실행 수명·통합 | Sol | 공통 계약·실패 원인 판단·위험한 연결부 |

모델 ID는 실행 표면의 가용성을 확인해 요청한다. 이번 협업 도구의 후보는 `gpt-6.1-sol`, `gpt-6.1-terra`, `gpt-6-luna`다. 과거 `gpt-5.6-*` 단계 표를 지원 확인 없이 호출하지 않는다. 설정·요청·관측 모델은 서로 다른 사실이며 응답에 없으면 관측 미확인으로 남긴다. effort도 지원하는 표면에서만 지정한다.

## 분해와 실행

1. Sol이 기준별 단위와 인터페이스를 정하고 입력·소유/제외 파일·의존 작업·통과 기준·실제 명령·결과 파일을 전달한다.
2. 인계 비용보다 이득이 있는 단위만 나눈다. 작은 작업은 적합한 모델 하나로 끝내며 세 모델을 의무 호출하지 않는다.
3. 소유 파일이 겹치지 않는 작업은 외부 협업 실행으로 병렬 진행하고, 공통 파일은 담당자 하나가 소유한다. 같은 작업 트리 저작은 하나의 선언된 전체 쓰기 범위와 저작 하네스에 묶고 최종 검사 전에 저작을 동결한다. 현재 공식 CLI의 같은 UUID 단위 호출은 execution lock으로 직렬화한다. 여러 allocation 호출을 같은 UUID에 동시에 실행하는 스케줄러로 설명하지 않는다.
4. Luna·Terra의 구현을 실제 동작과 diff·근거로 확인해 통합한다. Sol이 모든 결과를 다시 작성하는 패스를 추가하지 않는다.
5. 실패하면 원인과 가설을 먼저 확인한다. 범위가 복잡해지거나 상태·권한 경계가 드러나면 상향하며 같은 가정의 호출을 반복하지 않는다. 성공한 단위의 인계에는 실패 원인을 만들지 않는다.

## 하네스와 근거

공식 경로는 [개발 안내](../DEVELOPMENT.md#typescript-작성-및-하네스)를 따른다. 단위별 배분은 기존 UUID·직접 요청·입력·쓰기 권한 안에서 범위를 좁히며 실행·게시 권한을 확대하지 않는다. 배분의 쓰기 경로는 실제 실행 계획과 같은 집합이어야 한다. 일반 업무 모델 선택과 독립 검토자 선택은 분리한다.

단위의 선택 이유·요청 모델·이전 시도/인계를 연결하고 결과에는 관측 모델 또는 미확인 사유·실행/주입 구분·실패/미실행·제공된 usage를 남긴다. 전문은 Git 제외 증거 경로에 저장하고 주 대화에는 3~5줄과 원본 경로만 회수한다. 계획만 작성한 단위는 실행 완료가 아니다.

dependency는 검증된 영수증의 선행 호스트 정상 종료를 뜻한다. 업무 수용·단위 테스트 통과·작성자 외 독립 승인은 별도 근거다. 영수증 해시와 runtime 사건을 대조하되 같은 저장소 전체를 수정할 수 있는 주체에 대한 암호학적 신뢰 경계나 OS 격리로 주장하지 않는다. 파일 쓰기 한계의 강제 범위는 TypeScript 작성 하네스와 advisory 지침을 구분한다.

협업 도구의 실제 모델 호출과 하네스에 외부 결과를 주입하는 실행은 별도 표면이다. 주입된 영수증을 실제 Codex 프로세스 호출·호스트 수용으로 보고하지 않고 실제 호출 근거를 별도 연결한다.

작업 총 토큰은 분류·맥락 전달·저작·위임·재시도·검토를 포함한다. 시도별 원문을 보존하고 누락된 호출은 0으로 세지 않는다. 캐시·추론이 입출력의 부분집합이면 중복 합산하지 않는다. 같은 완료 조건의 실측 비교 전에는 절감률이나 비용 절감을 확정하지 않는다.

## 독립 검토

필수 완료 검토의 일반 정책은 [공통 계약](WORKFLOW.md#독립-검토의-책임)과 `agents/www/review-policy.json`이 소유한다. 공유 core의 기본은 Opus이며, 일반 정책에는 입증된 Opus 사용량 소진에 한정한 Terra 대체 기능이 있다.

읽기 전용 Claude Sonnet 교차검증은 역할이 외부 CLI로 별도 수행하고 실제 모델·원문·한계를 회수하는 보조 검토다. 현재 공유 core에 자동 Sonnet 단계가 구현됐다는 뜻이 아니며 이 보조 결과를 필수 완료 감사로 승격하지 않는다.

2026-11-16 최신 사용자 결정은 **Claude를 사용할 수 없으면 Terra로 감사를 이어간다**는 것이다. 이전의 이번 세션 Opus 고정·대체 금지는 이 결정으로 대체한다. 사용량 소진은 공유 core의 검증된 quota fallback을 사용한다. 그 밖의 실제 호출 불가 또는 사용자가 Terra를 직접 지정한 경우에는 이 직접 요청을 근거로 `reviewAuthority`의 읽기 전용 Terra 경로를 사용하고 원문·요청 해시·소스·기준·정책과 실제 관측 모델을 연결한다. 같은 대체를 다시 승인받지 않는다.

공유 core의 일반 자동 대체 조건은 여전히 `primary_quota_exhausted`이며 모든 장애가 자동 분류됐다고 주장하지 않는다. 검토 불합격은 호출 불가가 아니므로 모델을 바꿔 통과시키지 않고 지적을 수정한 뒤 재검토한다. 일반 업무의 모델 배분으로 독립 검토를 대체하지 않는다.

## 제품 Chat과의 관계

개발 세션에서 모델을 나누어 호출하는 절차와 WWW Chat의 자동 배치는 별도다. 이 절차만 적용하고 제품 자동 라우터가 구현됐다고 표시하지 않는다. 제품 배치는 작업 원본·실행·실패·복원 계약과 실제 호출 검증을 갖춘 별도 기능이다.
