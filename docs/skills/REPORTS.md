# 작업 종료 보고서 계약

WWW 개발 역할은 작업을 마치고 사용자에게 반환하기 전에 저작 작업 보고서를 남긴다. 오류 조사뿐 아니라 기능 구현·설계·진단·검증과 부분 완료·감사 대기도 포함한다. 단순 정보 질문에 신규 작업 등록을 의무화하지는 않는다.

## 저작 절차

1. 같은 작업 UUID와 실제 변경·검증·검토·한계를 읽는다.
2. 사람이 읽는 summary, before, after, changes, decisions, limitations, next를 한국어로 직접 작성한다. 변경 전후는 같은 사용자 행동을 비교하고 이유는 실제 판단에 연결한다. 수행하지 않은 대안·검사·감사를 성공으로 쓰지 않는다. 민감한 원문과 인증 정보는 넣지 않는다.
3. 문서 영향 검토와 독립 검토의 실행 결과가 기록된 뒤 `node scripts/workflow.ts '<JSON>'`의 `action: "report"`, `workId`, `narrative`로 저장한다. 서술 배열에 항목이 없으면 빈 배열로 전달하고 자료를 발명하지 않는다. 보고서 출력 디렉터리는 검증 inputs에 포함하지 않는다.
4. 반환한 report ID를 앱 목록·읽기 또는 같은 작업 폴더 reports의 HTML에서 확인한다. 완료 조건을 충족하면 기존 report-complete action을 호출한다. 감사 대기나 실패라면 업무 상태를 그대로 보존하고 보고서에서 다음 행동을 설명한다.

보고서는 `docs/work/<영역>/<번호-작업명>/reports/report-UUID.json`과 같은 이름의 `.html`이다. JSON이 저작과 근거 사본의 정본이며 HTML은 안전한 파생 보기다. 예전 보고서는 덮어쓰지 않는다. 같은 사건·같은 내용의 재실행은 중복을 억제한다. 앱에서 내보낸 HTML은 독립적인 오프라인 사본이다.

## 자동 기록과 완료

검증·검토·개발 호스트 종료·업무 완료에는 공유 core와 하네스의 수명주기 훅이 자동 기록을 생성한다. 자동 기록은 저자가 선택 이유를 작성한 보고서와 구분한다. 보고서 생성 실패는 핵심 작업 기록 저장 결과와 별도 reportHook.status로 반환하며 이미 실행한 작업을 자동 재실행하지 않는다.

공식 typed 개발 실행과 저작 보고서 작성은 workflow.reportingRequired를 설정한다. 완료 판정은 현재 소스·기준과 작업 기록에 일치하는 저작 보고서를 요구하며 기존 검사·문서 검토·독립 검토를 대체하지 않는다. 기존 레코드의 과거 완료 이력은 일괄 변환하지 않는다. complete 훅은 기존 저작 서술을 유지하고 완료 상태와 근거를 새 이력에 반영한다.

실제 파일에 등록된 전역 호스트 Stop 훅은 이 기능의 전제가 아니다. 보장 범위는 공식 typed 개발 경로와 아래 Native 종료 사건이며, 독립 개발 세션은 역할 지침으로 저작을 수행한다. 강제 종료로 콜백이 실행되지 않았다면 재개 후 `action: "report-snapshot"`, `workId`, `event: "resume_after_interruption"`으로 자동 기록을 복구하고 저작 보고서를 이어 작성한다. 훅을 실행했다는 사실과 앱에서 결과를 읽었다는 사실을 각각 검증한다.

## 보기와 현재성

작성 보고서와 자동 기록은 앱의 리포트에서 구분해 읽는다. 저장 시점의 사실과 현재의 사실을 구분하고, 소스·기준·작업 기록이 바뀌면 저장 당시 보고서임을 표시한다. 오래된 보고서를 삭제하거나 새 통과 결과로 조용히 바꾸지 않는다.

보고서는 HTML 오류 보고서의 밝은 종이·SVG 전후 비교·읽기 쉬운 근거 표현을 사용하되 일반 작업의 목표와 선택을 설명한다. 오류 원인 확정이나 실험을 모든 작업에 발명하지 않는다. 정적 본문만으로 목표·전후·변경·선택·검증·한계·다음 행동을 읽을 수 있어야 한다. 스크립트·외부 폰트·원격 자료 없이 오프라인에서 읽고 인쇄할 수 있다.

공식 진입점은 scripts/workflow.ts와 앱의 개발 상태·완료 서비스다. work.ts/run.ts는 내부 실행부이며 보고서 조건을 새로 강제하는 위치로 설명하지 않는다. 공식 status·complete는 report-status·report-complete action 또는 같은 typed 모듈을 사용한다.

## Native 답변 뒤 자동 저작

정상 앱에서는 자동 보고서를 기본으로 켠다. Native의 공개 최종 답변과 turn/completed를 함께 관찰한 뒤, 별도 Codex app-server의 일시적인 읽기 전용 스레드에서 LLM이 보고할 규모인지 판단한다. 짧은 인사·사실 응답은 생략하고, 의미 있는 변경·설계·조사·실패와 그 근거가 있는 작업은 구조화 서술을 작성한다. 고정 글자 수만으로 필요 여부를 결정하지 않는다. 모델의 판단과 이유를 앱에 표시하며 필요하면 사용자가 자동 처리를 끌 수 있다.

입력은 같은 턴의 공개 사용자 요청·최종 답변·관찰한 명령 상태·파일 이름뿐이다. 추론·명령 출력 원문은 포함하지 않는다. 크기를 제한하고 잘린 입력은 표시한다. 판단 프로세스는 별도 임시 폴더·읽기 전용 정책·승인 금지로 실행하며 도구 사용을 지시하지 않는다. 도구 시도와 승인 요청이 관찰되면 실패 처리하지만 호스트의 모든 내장 도구를 강제로 비활성화했다는 보장은 하지 않는다. 설정된 기본 모델을 사용하며 주 대화와 유효 모델이 같다고 단정하지 않는다.

판단과 저장은 원래 대화를 막지 않는 직렬 큐에서 처리한다. thread/turn별 멱등 키로 중복을 억제하며 저장 프로젝트는 종료 사건 당시 폴더에 고정한다. 큐는 10개, 재시도용 메모리는 최근 20개이고 직렬화 입력은 96 KiB 이하다. 디스크 작업 메타데이터에는 요청·답변 원문을 저장하지 않는다. 재시작한 미완료 항목은 interrupted로 표시한다. 실패는 명시 재시도하며 메모리에서 입력이 사라졌으면 재시도할 수 없음을 안내한다.

필요하다고 판단한 경우에만 docs/work/Native에 작업과 저작 보고서를 저장한다. Native 턴 종료는 업무 수용·테스트 통과가 아니므로 기준을 미검증으로 남긴다. 이 자동 저작은 위 개발 경로의 사실 스냅샷과 구분한다. 앱 리포트에는 판단 중·생략·저장·실패 상태와 이유, 보고서 열기·재시도를 제공한다. 외부 Codex 세션 전체에 전역 Stop 훅을 설치하는 기능은 아니다.

판단기의 입력·응답 형식·시간 초과·취소는 REPORT_JUDGE_* 오류 코드로 구분한다. 저장 하네스는 메시지 문구로 종류를 추측하지 않고 코드와 실행 단계로 고정 안내를 선택한다. 앱에는 원문이 남아 실제 재시도가 가능한 실패에만 재시도 버튼을 표시한다.

## 독자가 판단하는 보고서 양식

본문의 순서는 결론과 현재 상태 → 요구사항과 결과 → 중요한 판단과 선택(실제 있었을 때) → 검증 방법과 결과 → 남은 일과 다음 행동(있을 때) → 근거와 관련 자료다. 상단에는 왜 시작했고 무엇이 달라졌으며 어디까지 확인했는지를 3~5문장의 자연스러운 이야기로 이어 쓴다. 상태 표시는 이 저자 서술과 구분하며 필수 차단과 단순 환경 미확인을 같은 판정으로 묶지 않는다.

선택적인 narrative.reader가 story, requirements, checks, decisions, references, nextActions를 소유한다. requirements는 요구·보고된 결과·연결 근거·남은 한계를, checks는 대상·방법·기대·관측·미확인을 설명한다. 실제 근거가 없으면 null 또는 빈 배열로 두고 미기록으로 보인다. 종료 코드만으로 수행한 사용자 시나리오를 지어내지 않는다. 근거 필드는 저장 당시 기록에 연결하며 저자 서술이 검증의 새 원장이 되지 않는다.

중요 결정은 결정할 문제·확인한 근거·실제 검토한 대안·선택 이유·감수한 불리함을 필요한 만큼 쓴다. 대안 개수·모든 시행착오·인용구를 강제하지 않는다. 다음 행동에는 확인된 담당자와 관찰 가능한 완료 조건·미해결 영향이 있을 때 기록하고 미확인 담당자를 추측하지 않는다. 관련 자료는 경로보다 무엇을 확인할 수 있는지 목적을 먼저 보여준다.

구형 보고서는 기존 저작 문장만 재배치하고 부족한 요구 대응·검사 시나리오를 미기록으로 보인다. 과거 통과는 실패로 바꾸지 않으며 현재 적용 가능이라는 당시 원문도 현행 판정으로 보이지 않게 원시 상세로 내린다. 보고서의 현재성, 각 검사 시도의 현행 적용성, 독립 검토와 업무 완료는 별개다. 해시·UUID·명령·환경·원시 이력은 펼침 상세에 둔다. 자료 표시 한계는 실제 생략이 있을 때만 알리며 생략된 실패·차단·미확인 존재를 요약한다. 이전 JSON·HTML을 덮어쓰지 않고 새 읽기 보기를 적용한다.
