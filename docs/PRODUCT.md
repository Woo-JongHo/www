# WWW 제품 기준

## 목적과 사용자

WWW는 유지자가 직접 사용하는 개인용 AI 개발 작업 공간이다. 사용자는 로컬 프로젝트에서 AI에게 작업을 요청하고, 공개 작업 설명·명령 실행·파일 변경·승인·중단·결과를 하나의 데스크톱 앱에서 읽고 통제한다. 화면과 사람이 읽는 개발 기록의 기본 언어는 한국어다.

제품의 중심 가치는 실행 근거와 개입 지점을 이해하는 것이다. AI의 답변, 실제로 관찰된 사건, 검사 결과, 사용자가 요구한 업무의 수용을 각각 구분한다.

## 현재 제품 범위

현재 기준은 Electron + TypeScript와 React로 만든 로컬 데스크톱 앱이다. 첫 AI 실행 엔진인 Native는 PATH의 로컬 `codex app-server`다. 사용자는 첫 스레드 전에 작업 폴더를 선택하고 요청을 보낸다. 앱은 응답과 공개 설명을 표시하고, 명령·파일 변경 사건을 읽을 수 있는 블록으로 표현하며 지원되는 승인 응답과 턴 중단을 연결한다.

화면 사건은 탭마다 메모리에서 최근 2,000개만 보관한다. 대화 목록·재열기·동일 Native 스레드 재개는 Codex의 저장 원장을 사용하며 WWW의 별도 메시지 DB를 만들지 않는다. 답변은 Markdown·코드 복사·인용으로 읽고 현재 창에서 탭·대화별 초안·읽기 위치·펼침을 보존한다. 계정 로그인과 자격 증명 저장·전달, 원격 실행은 현재 제공 범위에 포함하지 않는다. 현재 범위라는 설명이 각 동작의 실제 Native·플랫폼별 검증 완료를 뜻하지는 않는다. 확인한 실제 동작과 한계는 해당 소스 상태의 작업 검증 기록에서 판단한다.

## 독립 Codex 대화 탭

여러 Codex 대화 탭에서 동시에 작업할 수 있다. 새 탭은 현재 탭의 프로젝트에서 빈 대화로 시작하며 각 탭이 프로젝트·Native 연결·thread·turn·출력·승인·중단을 따로 소유한다. 탭 전환 중에도 다른 탭의 실행은 계속된다. 탭에는 프로젝트와 실행·승인·실패 관측을 표시하고 방향키·Home·End로 이동한다. 일반 셸이나 PTY 터미널은 제공하지 않는다.

같은 프로젝트의 같은 Native thread는 한 탭에서만 연다. 실행·요청 준비·승인 중인 탭과 마지막 탭은 닫을 수 없다. 화면은 미전송 초안·실패 원문이 남은 경우도 먼저 처리하도록 안내한다. 닫기는 해당 탭의 Native 프로세스를 정리하고 다른 탭을 유지한다. 앱을 다시 열면 View Page의 새 탭으로 시작한다. 탭 목록·초안·화면 상태를 자동 복구하거나 작업을 자동 재전송하지 않으며 저장된 대화는 Native 원장에서 명시적으로 다시 연다. 상세 계약은 [Chat 명세](specs/chat.md#chat-sessions-01)를 따른다.

## View Page와 작업 보드

앱의 첫 화면은 프로젝트 선택 전 View Page다. RPA의 기존 로컬 폴더와 별도 WWW를 선택한 뒤 대상별 대시보드·대화·생태계·리포트로 이동한다. 전체 보기로 돌아가도 실행을 중단하지 않으며 실제 실행 컨텍스트 전환은 기존 전송·실행·승인 보호를 따른다. 대화 목록은 대화 화면에서 읽고, 대화 진입 전에는 보드 조회를 위해 Native를 시작하지 않는다.

칸반은 main이 승인한 등록 프로젝트의 `docs/work/**/work.json`을 읽는 보기다. 원본 상태·UUID·차단 이유를 유지하고 수집 실패·부분 자료·빈 자료를 구분한다. 응답 종료로 작업을 완료 처리하거나 보드에서 원장을 수정하지 않는다. 현재 WWW 고정 대상은 실행 앱의 개발 checkout이며 패키지 배포에는 소스 작업 기록이 포함되지 않아 같은 자료를 보장하지 않는다. 보드 수집과 탭의 실시간 실행 관측은 구분하며 프로젝트별 자동 코드 분석이나 제품 자동 모델 라우팅은 제공하지 않는다. [대시보드 명세](specs/dashboard.md)와 Home002 작업 기록에서 실제 검증 범위를 확인한다.

## 핵심 사용 흐름

오른쪽 기본 사이드바는 WWW Agent와 spec/design/build/diagnose/verify 다섯 스킬, 실제 관측한 Subagent 트리를 표시한다. 개요에는 현재 요청의 Native Plan과 활성 계획 항목에 연결된 공개 Progress를 둔다. 명시 선택·문서 읽기·실제 Subagent 상태를 구분하고 자료가 없으면 미제공으로 남긴다. 전체 Skills·Hooks 카탈로그·누적 리소스·상세 사건·스레드 모델·토큰·계정 한도는 별도 상세 모니터에서 확인한다. 기본바에는 관측 원장의 누락·저장 실패 경고만 보조로 남긴다. 반복 핸들러 ID만 제공되는 Hook은 상세에서 상태를 읽고 정확 호출 횟수를 만들지 않는다. 패널을 바꿔도 초안과 읽기 위치를 유지한다.

최근 로컬 프로젝트와 즐겨찾기를 탐색하고 해당 탭이 실행·전송·승인 중이 아닌 때 그 탭의 프로젝트를 바꾼다. 다른 탭으로의 이동은 이 전환 제한과 구분한다. 프로젝트별 대화·초안·리소스는 격리한다. WWW는 앱 데이터에 프로젝트 인덱스와 최소 리소스 메타데이터만 원자 저장하며 대화 본문·명령·출력·비공개 reasoning을 새 원장에 저장하지 않는다. 저장 실패·누락·불완전 이력은 표시하고 복원된 관측을 새 호출로 재생하지 않는다. 현재 구현·실제 Electron 검증·남은 통합 수용은 [Chat/009 작업](work/Chat/009-채팅과%20실시간%20사이드바%20및%20프로젝트%20Node%20Map%20개편/verification.md)에서 구분한다.

1. 작업 폴더를 확인하고 대화로 요청한다.
2. Native가 제공한 공개 응답과 계획·설명·공개 추론 요약을 시간순으로 읽는다. 중요한 행동 이유·확인 결과·실패와 방향 전환은 자연스러운 한국어 진행 설명으로 요청하며 고정 단계 라벨은 붙이지 않는다. 제공하지 않은 설명이나 내부 사고를 만들어 표시하지 않는다.
3. 실행 박스와 파일 변경에서 실제 명령·출력·상태·출처를 확인한다.
4. 승인·거절 또는 중단으로 개입하고, 요청 전송과 실제 결과 확인을 구분한다.
5. 변경·실행·검증·미해결을 대조하고 후속 요청을 보낸다.

이 흐름의 현행 요구는 [Chat 기능 명세](specs/chat.md)가 소유한다. 전체 실행 구조와 상태 소유는 [아키텍처](ARCHITECTURE.md), 실행 환경과 검사 방법은 [개발 안내](DEVELOPMENT.md)가 소유한다.

## 후속 방향

장기 방향은 하나의 WWW 데스크톱 앱에서 로컬 Native 실행·승인과 공유 개발 기록의 Roadmap·Node·Canvas 보기를 연결하는 것이다. 각 컴퓨터는 로컬 브랜치에서 개발하고 GitHub에 게시한 코드·구조화된 작업 기록을 공유 원본으로 삼는다. Mac mini가 지정 브랜치를 수집·검증·색인해 재현 가능한 API 보기를 제공하는 방향이다.

서버·DB·색인·해당 보기는 후속 목표다. 원격 실행, 소스 자동 동기화, 다중 팀 오케스트레이션은 현재 구현 완료로 기술하지 않는다. Canvas의 쓰기는 저장소에 기록하거나 별도 결정을 거쳐야 하며 파생 DB를 경쟁 원본으로 만들지 않는다. push 성공과 서버 색인 성공은 별개 사실이다.

## 개발 프로세스와 제품의 관계

WWW 개발 에이전트(`www-dev`)는 이 제품을 개발하는 역할이다. 제품이 연결하는 Native와 구분한다. 개발 역할의 스킬 선택이나 검증은 제품 Chat에 자동 주입되거나 사용자의 Native 모델을 바꾸지 않는다.

개발용 스킬·하네스에는 Sol이 통합을 소유하고 내부 작업을 Luna·Terra·Sol에 배분하는 계약과 실행 근거 기록이 있다. 제품 Chat이 요청을 자동 분류해 모델을 선택하는 라우터는 구현하지 않았다. 여러 탭의 동시 실행이나 모델 관측 표시도 자동 모델 배치를 뜻하지 않는다.

제품 목적·사용자·주요 기능 범위가 달라질 때 이 문서를 갱신한다. 적용 시점과 정보별 정본, 요구·관측·목표가 다를 때의 처리는 [공통 작업 계약](skills/WORKFLOW.md#현행-기준과-정보별-정본)을 따른다.

## 로컬 생태계 지도

사이드바의 생태계에서 WWW TypeScript 소스에 근거한 코드 설계도를 연다. 안정 구조 ID를 따라 전체에서 하위 책임으로 내려가고 breadcrumb로 복귀한다. ID·요구·제목·파일을 검색해 역할·책임·하위 구성·담당 코드를 읽고 같은 책임의 명세 요구·구현 선언·검증 참조 위치를 확인한다. 구성 관계와 코드 의존 관계를 나눠 보고 책임별 참조 방향을 좁혀 살펴본다. 실제 import는 현재 단계의 책임 사이 방향으로 축약하고 원문 근거를 상세에 둔다. 등록된 검증 참조는 테스트 실행 통과와 구분한다. 지도는 화면 전환 rail과 중앙 캔버스를 기본으로 사용한다. 선택한 노드의 역할 요약은 지도에서 읽고 자세히 보기를 눌러 상세를 연다. 프로젝트·대화 탐색도 필요할 때 펼친다. 별도 생태계 안내에서는 앱 실행·개발 절차·기록과 검토·후속 방향을 탐색한다. 빌드에 포함된 소스 snapshot과 수동 안내이며 선택한 작업 폴더 분석이나 실시간 실행 상태가 아니다. 상세 동작은 [생태계 명세](specs/ecosystem.md), 추출 범위와 코드 구조는 [코드 설계도](CODE_BLUEPRINT.md)가 소유한다. 후속 서버 색인과 공유 보기는 별도 목표로 유지한다.

## 작업 보고서

사이드바 리포트에서 저자가 남긴 작업 설명과 자동 실행 기록을 구분해 읽는다. 목표·변경 전후·선택 이유·검증·남은 일을 독립 HTML로 보존하며 저장 당시의 사실과 현재성을 표시한다. 보고서를 읽는 프로젝트는 실행 중 대화와 별도로 선택하고 HTML 사본으로 저장할 수 있다. [리포트 명세](specs/reports.md)를 따른다.

Native 답변이 끝나면 별도 LLM이 보고할 규모인지 판단한다. 필요한 작업은 자동 저작해 리포트에 남기고 작은 대화는 생략 이유를 표시한다. 자동 보고서 토글·상태·재시도는 리포트에서 제공하며 원래 대화는 계속 사용할 수 있다. 답변 종료와 검증된 업무 완료는 구분한다.

보고서 첫 화면은 작업의 이유·결과·확인 범위를 자연스러운 이야기로 읽고 현재 결론과 차단·다음 행동을 구분한다. 요구별 결과와 구체적인 검사 방법을 중심으로 판단하며, 중요한 선택만 실제 근거와 감수한 한계를 설명한다. 해시·UUID·원시 실행 이력은 상세에서 확인한다.

## Chat 읽기와 모니터 표현

Chat 007은 명령 출력의 10줄 미리보기와 보관 출력 펼침, 최신 작업 상태와 과거 질문의 동시 읽기, 세션 모니터 접힘, 입력 영역을 보존하는 본문 스크롤을 다룬다. 기능별 실제 검증·남은 한계는 해당 작업 기록이 소유하며 디자인 표현 규칙은 [디자인 시스템](design-system.md)을 따른다.

오른쪽 기본 화면은 고정 WWW Agent·다섯 개발 스킬·실제 Subagent와 Plan/Progress 개요가 중심이다. 문서 요청·읽기는 선택·적용·완료와 구분해 근거로 표시한다. Hook·전체 카탈로그·누적 리소스와 스레드 모델·토큰은 상세 모니터에서 읽으며 역할의 실제 적용 여부를 문서 읽기만으로 단정하지 않는다.
