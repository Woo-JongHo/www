# WWW 제품 기준

## 목적과 사용자

WWW는 유지자가 직접 사용하는 개인용 AI 개발 작업 공간이다. 사용자는 로컬 프로젝트에서 AI에게 작업을 요청하고, 공개 작업 설명·명령 실행·파일 변경·승인·중단·결과를 하나의 데스크톱 앱에서 읽고 통제한다. 화면과 사람이 읽는 개발 기록의 기본 언어는 한국어다.

제품의 중심 가치는 실행 근거와 개입 지점을 이해하는 것이다. AI의 답변, 실제로 관찰된 사건, 검사 결과, 사용자가 요구한 업무의 수용을 각각 구분한다.

## 현재 제품 범위

현재 기준은 Electron + TypeScript와 React로 만든 로컬 데스크톱 앱이다. 첫 AI 실행 엔진인 Native는 PATH의 로컬 `codex app-server`다. 사용자는 첫 스레드 전에 작업 폴더를 선택하고 요청을 보낸다. 앱은 응답과 공개 설명을 표시하고, 명령·파일 변경 사건을 읽을 수 있는 블록으로 표현하며 지원되는 승인 응답과 턴 중단을 연결한다.

제품 사건은 메모리에서 최근 2,000개만 보관한다. 대화 영속 저장·목록·재열기, 계정 로그인과 자격 증명 저장·전달, 원격 실행은 현재 제공 범위에 포함하지 않는다. 현재 범위라는 설명이 각 동작의 실제 Native·플랫폼별 검증 완료를 뜻하지는 않는다. 확인한 실제 동작과 한계는 해당 소스 상태의 작업 검증 기록에서 판단한다.

## 핵심 사용 흐름

1. 작업 폴더를 확인하고 대화로 요청한다.
2. Native가 제공한 공개 응답과 계획·설명을 읽는다. 제공하지 않은 설명이나 내부 사고를 만들어 표시하지 않는다.
3. 실행 박스와 파일 변경에서 실제 명령·출력·상태·출처를 확인한다.
4. 승인·거절 또는 중단으로 개입하고, 요청 전송과 실제 결과 확인을 구분한다.
5. 변경·실행·검증·미해결을 대조하고 후속 요청을 보낸다.

이 흐름의 현행 요구는 [Chat 기능 명세](specs/chat.md)가 소유한다. 전체 실행 구조와 상태 소유는 [아키텍처](ARCHITECTURE.md), 실행 환경과 검사 방법은 [개발 안내](DEVELOPMENT.md)가 소유한다.

## 후속 방향

장기 방향은 하나의 WWW 데스크톱 앱에서 로컬 Native 실행·승인과 공유 개발 기록의 Roadmap·Node·Canvas 보기를 연결하는 것이다. 각 컴퓨터는 로컬 브랜치에서 개발하고 GitHub에 게시한 코드·구조화된 작업 기록을 공유 원본으로 삼는다. Mac mini가 지정 브랜치를 수집·검증·색인해 재현 가능한 API 보기를 제공하는 방향이다.

서버·DB·색인·해당 보기는 후속 목표다. 원격 실행, 소스 자동 동기화, 다중 팀 오케스트레이션은 현재 구현 완료로 기술하지 않는다. Canvas의 쓰기는 저장소에 기록하거나 별도 결정을 거쳐야 하며 파생 DB를 경쟁 원본으로 만들지 않는다. push 성공과 서버 색인 성공은 별개 사실이다.

## 개발 프로세스와 제품의 관계

WWW 개발 에이전트(`www-dev`)는 이 제품을 개발하는 역할이다. 제품이 연결하는 Native와 구분한다. 개발 역할의 스킬 선택이나 검증은 제품 Chat에 자동 주입되거나 사용자의 Native 모델을 바꾸지 않는다.

제품 목적·사용자·주요 기능 범위가 달라질 때 이 문서를 갱신한다. 적용 시점과 정보별 정본, 요구·관측·목표가 다를 때의 처리는 [공통 작업 계약](skills/WORKFLOW.md#현행-기준과-정보별-정본)을 따른다.
