# WWW 제품 기준

## 목적과 사용자

WWW는 유지자가 직접 사용하는 개인용 AI 개발 작업 공간이다. 사용자는 로컬 프로젝트에서 AI에게 작업을 요청하고, 공개 작업 설명·명령 실행·파일 변경·승인·중단·결과를 하나의 데스크톱 앱에서 읽고 통제한다. 화면과 사람이 읽는 개발 기록의 기본 언어는 한국어다.

제품의 중심 가치는 실행 근거와 개입 지점을 이해하는 것이다. AI의 답변, 실제로 관찰된 사건, 검사 결과, 사용자가 요구한 업무의 수용을 각각 구분한다.

## 현재 제품 범위

현재 기준은 Electron + TypeScript와 React로 만든 로컬 데스크톱 앱이다. 첫 AI 실행 엔진인 Native는 PATH의 로컬 `codex app-server`다. 사용자는 첫 스레드 전에 작업 폴더를 선택하고 요청을 보낸다. 앱은 응답과 공개 설명을 표시하고, 명령·파일 변경 사건을 읽을 수 있는 블록으로 표현하며 지원되는 승인 응답과 턴 중단을 연결한다.

화면 사건은 메모리에서 최근 2,000개만 보관한다. 대화 목록·재열기·동일 Native 스레드 재개는 Codex의 저장 원장을 사용하며 WWW의 별도 메시지 DB를 만들지 않는다. 답변은 Markdown·코드 복사·인용으로 읽고 현재 창에서 대화별 초안·읽기 위치·펼침을 보존한다. 계정 로그인과 자격 증명 저장·전달, 원격 실행은 현재 제공 범위에 포함하지 않는다. 현재 범위라는 설명이 각 동작의 실제 Native·플랫폼별 검증 완료를 뜻하지는 않는다. 확인한 실제 동작과 한계는 해당 소스 상태의 작업 검증 기록에서 판단한다.

## 핵심 사용 흐름

오른쪽 Native 활동 패널은 현재 작업공간에서 app-server가 열거한 Skills와 Hooks를 고정 목록으로 보여 주고, 구조화된 Skill 문서 읽기나 동기 Hook 시작을 새로 관측한 해당 행만 짧게 반응시키는 보조 보기다. 반응은 사용 성공이나 작업 완료가 아니라 읽기·시작 관측이다. 전체 목록을 얻지 못하면 감지된 목록으로 구분한다. 계획·모델·시간·토큰·계정 한도·긴 실행 타임라인은 기본 사이드바에 함께 넣지 않는다. 기존 대화·명령·파일·승인·리포트·생태계 보기는 유지한다. 이 최소 화면의 구현·검증 상태는 [해당 작업 기록](work/Chat/005-Skills%EC%99%80%20Hook%20%ED%99%9C%EB%8F%99%20%EC%82%AC%EC%9D%B4%EB%93%9C%EB%B0%94/spec.md), 넓은 활동·사용량 투영의 과거 범위와 증거는 [기존 작업 기록](work/Chat/003-Native%20실시간%20작업%20흐름과%20사용량/spec.md)에서 구분해 확인한다.

1. 작업 폴더를 확인하고 대화로 요청한다.
2. Native가 제공한 공개 응답과 계획·설명·공개 추론 요약을 시간순으로 읽는다. 중요한 행동 이유·확인 결과·실패와 방향 전환은 자연스러운 한국어 진행 설명으로 요청하며 고정 단계 라벨은 붙이지 않는다. 제공하지 않은 설명이나 내부 사고를 만들어 표시하지 않는다.
3. 실행 박스와 파일 변경에서 실제 명령·출력·상태·출처를 확인한다.
4. 승인·거절 또는 중단으로 개입하고, 요청 전송과 실제 결과 확인을 구분한다.
5. 변경·실행·검증·미해결을 대조하고 후속 요청을 보낸다.

이 흐름의 현행 요구는 [Chat 기능 명세](specs/chat.md)가 소유한다. 전체 실행 구조와 상태 소유는 [아키텍처](ARCHITECTURE.md), 실행 환경과 검사 방법은 [개발 안내](DEVELOPMENT.md)가 소유한다.

## 후속 방향

장기 방향은 하나의 WWW 데스크톱 앱에서 로컬 Native 실행·승인과 공유 개발 기록의 Roadmap·Node·Canvas 보기를 연결하는 것이다. 각 컴퓨터는 로컬 브랜치에서 개발하고 GitHub에 게시한 코드·구조화된 작업 기록을 공유 원본으로 삼는다. Mac mini가 지정 브랜치를 수집·검증·색인해 재현 가능한 API 보기를 제공하는 방향이다.

서버·DB·색인·해당 보기는 후속 목표다. 원격 실행, 소스 자동 동기화, 다중 팀 오케스트레이션은 현재 구현 완료로 기술하지 않는다. Canvas의 쓰기는 저장소에 기록하거나 별도 결정을 거쳐야 하며 파생 DB를 경쟁 원본으로 만들지 않는다. push 성공과 서버 색인 성공은 별개 사실이다.

## 개발 프로세스와 제품의 관계

WWW 개발 에이전트(`www-dev`)는 이 제품을 개발하는 역할이다. 제품이 연결하는 Native와 구분한다. 개발 역할의 스킬 선택이나 검증은 제품 Chat에 자동 주입되거나 사용자의 Native 모델을 바꾸지 않는다.

제품 목적·사용자·주요 기능 범위가 달라질 때 이 문서를 갱신한다. 적용 시점과 정보별 정본, 요구·관측·목표가 다를 때의 처리는 [공통 작업 계약](skills/WORKFLOW.md#현행-기준과-정보별-정본)을 따른다.

## 로컬 생태계 지도

사이드바의 생태계에서 WWW TypeScript 소스에 근거한 코드 설계도를 연다. 계층 개요에서 모듈 상세로 이동하고 실제 참조의 파일·행·원문을 읽는다. 별도 생태계 안내에서는 앱 실행·개발 절차·기록과 검토·후속 방향을 탐색한다. 빌드에 포함된 소스 snapshot과 수동 안내이며 선택한 작업 폴더 분석이나 실시간 실행 상태가 아니다. 상세 동작은 [생태계 명세](specs/ecosystem.md), 추출 범위와 코드 구조는 [코드 설계도](CODE_BLUEPRINT.md)가 소유한다. 후속 서버 색인과 공유 보기는 별도 목표로 유지한다.

## 작업 보고서

사이드바 리포트에서 저자가 남긴 작업 설명과 자동 실행 기록을 구분해 읽는다. 목표·변경 전후·선택 이유·검증·남은 일을 독립 HTML로 보존하며 저장 당시의 사실과 현재성을 표시한다. 보고서를 읽는 프로젝트는 실행 중 대화와 별도로 선택하고 HTML 사본으로 저장할 수 있다. [리포트 명세](specs/reports.md)를 따른다.

Native 답변이 끝나면 별도 LLM이 보고할 규모인지 판단한다. 필요한 작업은 자동 저작해 리포트에 남기고 작은 대화는 생략 이유를 표시한다. 자동 보고서 토글·상태·재시도는 리포트에서 제공하며 원래 대화는 계속 사용할 수 있다. 답변 종료와 검증된 업무 완료는 구분한다.

보고서 첫 화면은 작업의 이유·결과·확인 범위를 자연스러운 이야기로 읽고 현재 결론과 차단·다음 행동을 구분한다. 요구별 결과와 구체적인 검사 방법을 중심으로 판단하며, 중요한 선택만 실제 근거와 감수한 한계를 설명한다. 해시·UUID·원시 실행 이력은 상세에서 확인한다.
