# Chat 현행 기능 명세

## 목적과 적용 범위

Chat은 사용자가 로컬 Native와 대화하면서 공개 설명·명령·파일 변경·승인·중단·결과를 읽고 개입하는 작업 공간이다. 제품 목적과 장기 범위는 [제품 기준](../PRODUCT.md), 모듈과 사건 흐름은 [아키텍처](../ARCHITECTURE.md)가 소유한다.

이 문서는 현재 적용할 요구를 정한다. 구현에서 관찰한 사실이나 모든 플랫폼의 검증 완료 선언이 아니다. 이번에 바꿀 목표는 해당 작업 명세에서 관리하고, 검사한 소스 상태·결과·한계는 해당 작업의 검증 시도에서 확인한다. 적용과 충돌 처리 규칙은 [공통 계약](../skills/WORKFLOW.md#현행-기준과-정보별-정본)을 따른다.

## 요구와 주요 시나리오

<a id="chat-sessions-01"></a>

### CHAT-SESSIONS-01 — 독립 Codex 대화 탭과 동시 실행

상단에서 여러 Codex 대화 탭을 추가·선택·닫을 수 있다. 새 탭은 현재 프로젝트의 빈 대화에서 시작하고 Native는 대화 조회·요청이 필요할 때 연결한다. 일반 셸/PTY 터미널은 제공하지 않는다. 각 탭의 프로젝트·Native subprocess/RPC·thread·turn·입력·출력·승인·중단·오류를 격리하고 서로 다른 대화를 동시에 실행한다. 실행 중 다른 탭으로 이동해도 실행을 중단하거나 새 탭의 출력에 섞지 않는다. 탭 제목·프로젝트·실행·승인·실패 상태를 읽고 방향키·Home·End로 탭을 선택한다.

같은 실제 프로젝트의 같은 Native thread는 한 탭에서만 연다. 대화 재개 중의 예약도 중복 소유로 취급하며 실패하면 예약을 회수한다. 사건·리소스·조회는 sessionId와 프로젝트·process/selection 세대로 해당 탭에 귀속한다. 같은 JSON-RPC ID를 서로 다른 탭이 받아도 세션에 묶인 승인 token을 원래 ID와 함께 응답하며, 중단은 지정 탭의 현재 thread/turn에만 적용한다.

실행·요청/대화 준비·미결 승인이 남은 탭과 마지막 탭은 backend에서 닫기를 거부한다. 화면은 미전송 초안·미해결 실패 원문이 남은 탭도 닫지 못하게 하고 먼저 보내거나 비우거나 복원/버리도록 안내한다. 거부 이유를 표시하며 닫기를 강제 중단의 성공으로 표현하지 않는다. 닫을 수 있는 탭은 해당 Native child를 정리하고 제거하며 다른 탭을 유지한다. 비활성 탭도 화면 상태와 구독을 유지하여 초안·읽기 위치를 잃지 않는다.

탭 목록·활성 탭·초안·읽기 상태는 현재 앱 메모리다. 재시작은 새 기본 탭의 View Page에서 시작하며 이전 탭·진행 중 실행·초안을 자동 복구하거나 자동 재전송하지 않는다. 최근 프로젝트·최소 리소스 원장은 앱 데이터에서 복원하고, 저장 대화는 CHAT-HISTORY-01에 따라 Native 원장에서 명시적으로 다시 연다. 확인할 시나리오는 두 탭의 동시 요청·늦은 사건·출력 격리, 승인 ID 재사용·다른 탭 응답 거부, 탭별 중단, 프로젝트 전환, 같은 thread 중복 재개, busy/승인/초안/실패/마지막 탭 닫기와 재시작이다. 실제 Electron·합성 Native·실제 모델 검증을 각각 기록한다.

### CHAT-INPUT-01 — 요청과 전송 결과

사용자는 첫 스레드 전에 작업 폴더를 확인하고 비어 있지 않은 요청을 보낸다. 같은 요청의 전송 중 중복 제출을 막고, 전송 중·접수됨·전송 실패를 구분한다. 전송 실패 시 입력을 조용히 잃지 않으며, 전달 결과가 불명확한 변경 요청을 자동 재전송하지 않는다.

전송을 기다리며 새 초안을 작성한 경우 실패한 이전 요청의 원문과 새 초안을 함께 보존한다. 충돌한 실패 원문은 공백과 줄바꿈을 유지해 표시하고, 입력창을 비운 뒤 명시적으로 복원하거나 사용자가 버릴 수 있다. 해결 전에는 해당 탭의 다음 전송과 대화·프로젝트 전환을 막아 실패 원문을 덮지 않으며, 다른 화면에서도 대화로 돌아가 해결할 수 있게 안내한다. 다른 독립 탭으로 이동할 수 있고 실패 원문은 원래 탭에 남는다. 복원과 재전송은 구분하며 자동 재전송하지 않는다.

확인할 시나리오는 일반 입력, 빈 입력, 빠른 반복 전송, 요청 실패와 입력 초안 보존이다. 실제 모델 대화와 합성 서버의 입력·전송 검증은 각각 기록한다.

<a id="CHAT-SLASH-01"></a>

### CHAT-SLASH-01 — 모델, 대화 압축과 사이드 질문 명령

입력창에서 `/`를 입력하면 `/model`, `/compact`, `/btw`, `/theme` 명령 목록을 즉시 표시하고, 이어 입력한 접두어로 후보를 좁힌다. 방향키 또는 마우스로 고르고 Escape로 목록을 닫을 수 있으며, 고른 명령은 일반 메시지를 전송하지 않고 기존 명령 동작을 실행한다. `/model`을 단독 제출하면 현재 탭의 모델 선택기가 열린다. 선택한 모델은 해당 탭의 이후 일반 요청에 적용된다. 취소하면 기존 선택과 입력창 초점을 유지한다.

`/compact`를 단독 제출하면 이력이 있는 현재 대화에 압축을 요청한다. 접수, 진행, 완료와 실패를 구분해 표시한다. 응답, 시작 또는 완료가 2분간 확인되지 않으면 해당 탭의 Native 연결을 닫고 같은 저장 대화를 다시 열도록 안내한다.

`/btw <질문>`은 현재 대화에서 공개된 최근 질문과 답변만 참고하는 짧은 별도 답변을 같은 탭의 사이드 질문 영역에 표시한다. 인자 없는 명령은 사용법을 안내한다. 기본 대화의 실행과 승인 상태는 유지하며, 별도 응답은 기본 대화 이력에 저장하거나 일반 새 턴·추가 지시로 보내지 않는다. 읽기 전용 임시 Codex 프로세스를 시작할 수 없으면 그 이유를 해당 탭에 표시하고, 다른 대화로 이동하면 진행 중인 요청을 취소한다.

두 명령은 새 턴이나 추가 지시 텍스트로 보내지 않는다. 실행 중이거나 대화 이력이 없으면 이유를 표시한다. 일반 메시지, 추가 지시와 다른 탭의 상태는 기존 동작을 유지한다.

### CHAT-THEME-01 — 채팅 테마 선택과 복원

`/theme`를 단독 제출하면 현재 테마가 표시된 선택기가 열린다. 기본 프리셋 Terminal Basic은 어두운 무채색 배경과 밝은 글자를 쓰며, WWW Mint는 민트색 강조를 쓰는 선택 프리셋이다. 선택한 테마는 같은 앱 프로필의 채팅 본문, 입력창, 코드·명령 카드와 모니터링 패널에 적용되며 새 탭과 재시작 뒤 복원된다. 저장값이 없거나 지원하지 않으면 Basic이 적용된다. 저장 실패 시 기존 테마를 보존하고 입력창에 알려 준다. 키보드로 선택·취소할 수 있고 닫을 때 입력창에 초점이 돌아간다. ### CHAT-STEER-01 — 같은 턴에 추가 지시

현재 입력창은 Native 세션이 제공하는 연결과 활성 턴을 사용한다. 처음 연결과 턴 시작 사건이 제한된 이력에서 사라져도 현재 턴을 제어할 수 있다. 이전 연결, 다른 탭, 복원된 과거 턴을 추가 지시 대상으로 삼지 않는다.

활성 턴이 확인된 작업 중 입력창은 일반 새 턴 전송과 Steer를 구분한다. session/selection/thread/expectedTurnId와 clientUserMessageId로 대상과 중복을 확인하고, turn/steer 응답의 turnId가 같을 때 접수를 확정한다. Native userMessage의 clientId는 같은 입력의 이력 병합 근거이며 API 응답 전 접수 성공을 대신하지 않는다.

시작 대기·승인·중단 확인·연결 미확인에서는 이유를 표시한다. 전송 중 새 초안을 편집할 수 있으며 실패한 추가 지시의 원문과 새 초안을 함께 보존한다. 응답 불일치·시간 초과·연결 종료·턴 종료 경합의 불확실한 접수를 성공으로 만들거나 자동 재전송·새 턴으로 바꾸지 않는다. API 접수와 실제 모델의 후속 행동 반영은 별도로 관찰하며 전자를 후자의 보장으로 표시하지 않는다.

<a id="chat-observe-01"></a>

### CHAT-OBSERVE-01 — 공개 설명과 실제 사건의 출처

Native의 공개 답변·설명·계획과 명령·파일 변경을 출처와 thread/turn/item 연결을 보존해 표시한다. 명령은 동일 실행의 출력·상태를 갱신하며, 실패·결과 미확인·미제공·절단을 구분한다. 내부 사고를 생성하거나 다른 턴의 과거 사건을 현재 결과로 합치지 않는다.

새 Native 스레드에는 자연스러운 한국어 진행 설명을 요청하는 `developerInstructions`를 추가한다. 즉시 답할 짧은 질문이 아니면 첫 도구 호출 전에 확인 대상을 알리고, 여러 도구를 연속 사용하거나 오래 기다릴 때는 같은 말을 반복하지 않는 범위에서 확인 결과와 다음 행동을 중간에 설명하도록 요청한다. 중요한 행동·결정의 이유, 확인 결과, 실패와 방향 전환의 근거를 충분히 설명하고 최종 답변에는 해당하는 결론·실제 행동·확인 결과·남은 문제를 간결하게 정리하도록 요청하되 고정 단계 라벨이나 매 도구 호출마다 반복 문구를 강제하지 않는다. `baseInstructions`·모델·effort·전역 설정을 바꾸지 않고 턴의 `summary: "detailed"`로 공개 요약을 요청한다. 실제 설명 빈도는 모델 동작이며 지침 전달만으로 보장하지 않는다.

채팅은 `item/reasoning/summaryTextDelta`·`summaryPartAdded`와 reasoning 항목 시작·완료의 `summary: string[]`만 공개 추론 요약으로 허용한다. 원문 `content`·reasoning `textDelta`·analysis는 표시하지 않으며 잘못된 summary를 원문으로 대체하지 않는다. 공개 설명·요약은 수신 시간순의 본문으로 읽고 출처는 접근성 이름으로 구분한다. 실제 요약이 없으면 빈 자리표시를 만들지 않는다.

요약 A, 다른 공개 설명 B, 같은 요약의 추가 조각 C를 받으면 본문은 A/B/C 순서로 읽는다. 공개 설명과 publicPlan도 다른 항목을 건너뛰어 이전 위치에 이어 붙이지 않는다. 바로 인접한 같은 항목·섹션의 조각만 합칠 수 있다. 유효한 요약 항목 시작·완료 snapshot과 공개 설명·계획의 완료 snapshot은 해당 항목의 기존 조각 표시 위치를 유지해 이전 본문을 정산한다. 기존 조각이 없으면 snapshot 수신 위치에 새 본문을 표시하고, 빈 snapshot은 이전 본문을 제거한다. 여러 조각으로 표시한 내용이 정정되면 다른 항목과의 기존 표시 순서는 유지하되, 정정된 각 조각과 시간 위치의 대응은 미확인이라는 경고를 표시한다. 완료·EOF 뒤의 늦은 시작은 본문을 되돌리지 않는다. 조각으로 나뉘어도 요약 항목별 32,768 UTF-16 코드 단위 예산과 종료 경계를 유지한다. 최종 답변은 기존 항목별 전체 본문 처리를 유지한다.

요약은 thread/turn/item과 섹션 index를 격리하고 중복 seq를 억제한다. 완료 snapshot은 이전 요약을 대체하며 턴 종료·EOF 뒤에는 스트리밍을 닫고 늦은 델타로 재시작하지 않는다. 빈 섹션 알림은 배열을 확장하지 않으며 index는 0 이상 32,768 미만의 안전한 정수만 받는다. 본문은 문단 구분자를 포함해 앞 32,768 UTF-16 코드 단위로 제한하고 절단 안내를 표시한다. 요약은 모델이 제공한 설명이며 실제 실행·검증의 증거를 대신하지 않는다.

확인할 시나리오는 응답·요약 스트리밍, 공개 설명 미제공, 섹션·중복·완료 snapshot·잘못된 입력·원문 미노출, 명령 출력과 파일 변경, 다른 턴의 늦은 사건, 종료·EOF·긴 출력의 제한 표시다. 실행 종료와 업무 수용·실제 검증은 별개다.

<a id="chat-approval-01"></a>

### CHAT-APPROVAL-01 — 지원되는 승인과 단일 응답

지원되는 명령·파일 승인 요청은 원래 문자열 또는 숫자 ID로 응답한다. 열린 요청, 응답 전송 중, 응답됨, 결과 미확인을 구분하고 같은 요청의 중복 응답을 막는다. 지원하지 않는 구조화 요청은 그렇게 표시하며 임의로 승인하지 않는다. UI는 관찰된 요청을 표현하며 OS sandbox 보장이 아니다.

요청 ID는 이후 다른 승인과 다른 탭에서 재사용될 수 있다. main의 해당 native-session이 대기 요청마다 발급한 로컬 token에 세션 접두부를 붙여 표시 카드와 응답에 연결한다. 다른 탭·이전 카드·연결의 늦은 응답이 새 승인을 처리하지 못하게 한다. Native params의 token을 신뢰하지 않고 token 없는 과거 요청은 응답할 수 없다. 서버가 요청 해결을 알리면 해당 대기 항목을 닫으며 불확실한 응답을 새 연결에서 자동 재전송하지 않는다.

확인할 시나리오는 숫자·문자열 ID, 허용·거절·중단, 반복 클릭, EOF 중 미결 승인, 미지원 요청이다.

<a id="chat-stop-01"></a>

### CHAT-STOP-01 — 중단 요청과 확인의 구분

실행 중인 턴에 중단을 요청할 수 있다. 요청 중·호스트의 접수·최종 턴 결과를 구분하고, 요청 중 반복 클릭이 중복 제출로 이어지지 않게 한다. 전송 실패나 연결 끊김은 중단 성공으로 표시하지 않는다.

요청을 보낸 `requested`와 호스트가 접수한 `accepted`는 모두 중복 제출을 막는다. 실제 현재 턴의 `interrupted` 종료를 받으면 이전 요청의 결과가 불확실했어도 중단 확인으로 표시한다. 정상·실패·알 수 없는 종료와 연결 끊김은 중단 성공으로 추정하지 않는다. 종료 뒤 도착한 접수·요청 사건과 다른 턴의 사건이 확인한 결과를 덮어쓰지 않아야 한다.

확인할 시나리오는 실행 중 중단, 요청 중 반복 입력, 중단 응답 실패, 최종 `interrupted` 결과와 접수만 된 상태의 구분이다. 구체적인 개선 여부와 회귀 검증은 이 요구를 참조하는 Chat 작업에서 기록한다.

<a id="chat-error-01"></a>

### CHAT-ERROR-01 — 실패와 읽기 상태

연결 끊김·명령 실패·결과 불확실·승인 대기를 사용자가 찾을 수 있게 표시한다. 사건이 추가돼도 사용자가 읽던 위치·직접 펼친 상태·입력 초안을 보존하고 새 내용으로 돌아갈 수 있게 한다. 보관 한계를 넘은 원본을 복원할 수 있다고 표시하지 않는다.

확인할 시나리오는 EOF·오류, 실패한 명령, 과거 내용 읽기 중 새 출력, 긴 출력, 키보드·한국어 입력·포커스다. 실제 GUI·플랫폼 검사를 수행하지 않았다면 합성 테스트 통과와 구분한다.

<a id="chat-activity-01"></a>

### CHAT-ACTIVITY-01 — Skills·Hooks 실시간 활동

기본 사이드바는 고정 WWW Agent·다섯 개발 스킬·실제 Subagent와 현재 요청의 Plan/Progress 개요를 보여 준다. 누적 리소스·Hook·전체 Skills 카탈로그는 별도 상세 모니터에서 읽고, 기본바에는 관측 원장의 누락·저장 실패 경고만 보조로 남긴다. 다음 목록 계약은 그 상세 모니터의 카탈로그에 적용한다. app-server의 `skills/list`와 `hooks/list`를 목록 원본으로 사용하고 등록 순서를 유지한다. 응답의 cwd와 필수 배열·항목 shape가 정확하지 않거나 오류·경고가 있으면 전체 목록으로 수용하지 않고 감지된 목록임을 제목에서 구분한다. 최신 등록 snapshot은 최근 2,000개 사건 이력과 독립해 유지하고, 선택 thread의 Hook 목록은 workspace 목록보다 우선하며 같은 범위의 새 요청이 시작된 뒤에는 그보다 오래된 요청의 응답을 게시하지 않는다. 실제 transport 연결 세대와 대화 복원용 연결 표시를 구분해, 같은 연결에서 대화를 전환하거나 복원해도 카탈로그 반응의 Hook 중복 방지 상태를 초기화하지 않는다. 활동 때문에 행을 재정렬하거나 사용자의 읽기 위치를 움직이지 않는다. 기존 대화·명령·파일·승인·리포트·생태계 보기와 입력 초안을 유지한다. 모델·토큰·계정 한도·긴 타임라인은 기본 사이드바가 아닌 상세에서 읽는다.

Skill 입력은 명시 요청이며 적용 성공 증거가 아니다. 명령의 구조화 commandActions에서 read와 정확한 `SKILL.md` 경로를 수신하면 해당 Skill 행이 읽기 시작에서 한 번 반응하고, 한 사건에 여러 읽기가 있으면 각 행을 모두 반응시킨다. 이름 언급·임의 명령 문자열·`skills/changed` 자체는 반응 근거가 아니다. 동기 Hook은 `hook/started`에서 해당 행이 반응하고 같은 run ID의 완료는 새 호출로 반응하지 않는다. 완료가 먼저 관측된 뒤 늦게 온 시작, 중복 시작, 비동기 Hook, 다른 스레드와 명시 thread가 없는 사건을 현재 행에 추정해 켜지 않는다. 읽기와 Hook run의 중복 억제는 절단 가능한 화면 이력이 아니라 연결 수명주기에 두고 새 연결에서만 초기화한다. 등록 Hook과 실행의 event name·source path·display order·handler type이 정확히 하나로 매핑되지 않으면 기존 행에 임의 귀속하지 않는다.

사건 seq는 각 native-session이 renderer에 게시하는 세션 내부 단조 증가 순서를 처리 기준으로 사용하며 모든 과거 seq를 집합으로 보관하지 않는다. 연결 세대 안의 Skill 읽기 key와 thread별 Hook handler·관측 turn의 key 문자열을 정확히 보존한다. 해시는 고정된 64개 bucket 중 복사할 bucket을 고르는 데만 쓰고 중복 판정에는 쓰지 않으므로 새 활동을 충돌로 누락하지 않는다. 이 정확한 상태는 연결 세대의 고유 읽기·handler·관측 turn 수에 비례해 증가하며 실제 transport 연결 세대가 바뀔 때 회수한다. 같은 연결의 대화 복원·전환에서는 회수하지 않는다. 최근 관측·pulse·thread별 Hook 목록 cache는 각각 512·512·32개로 제한하며, 제거된 thread 목록은 그 thread를 다시 열 때 실제 목록 요청으로 복구한다.

Hook의 `run.id`는 재사용될 수 있으므로 개별 실행의 고유 ID로 가정하지 않는다. 완료→시작, 다른 turn의 첫 시작과 제공된 시작 시각으로 실행 경계를 관측한다. 개별 Hook 완료가 빠져도 새 turn의 시작은 반응시키며 이전 Hook의 성공·완료를 합성하지 않는다. 완료를 먼저 본 turn의 늦은 시작과 이미 전환을 마친 과거 turn 재수신은 재반응시키지 않는다. 같은 turn·handler·시각 등 모든 metadata가 동일한 완료→시작은 새 실행과 재전송을 구별할 정보가 없어 수신 lifecycle 전이를 수용한다.

새 활동이 생긴 행의 표시점과 배경만 약 0.7초 반응하며 같은 항목의 빠른 연속 활동은 반응 시간을 연장해 합칠 수 있다. renderer는 bootstrap·대화 전환 snapshot이 끝날 때까지 같은 경계에 도착한 live 사건을 보류하고, snapshot과 seq 순서로 병합한다. snapshot에 실제 포함된 사건은 관측 상태만 복원하고, 큐에만 있는 live 사건은 snapshot의 최대 seq보다 낮아도 새 반응을 만든다. 실패·재진입·취소에서도 보류한 live 사건을 잃거나 다른 thread에 섞지 않는다. 이력 snapshot, 리렌더, 패널 재진입만으로 반응을 재생하지 않는다. 모션 축소 환경에서는 애니메이션 없이 최근 관측 상태를 정적으로 구분한다. 반응은 시작·읽기 관측이며 실행 성공이나 업무 완료를 뜻하지 않는다. 확인할 시나리오는 등록/부분 목록, 구조화 Skill 읽기, 이름 언급, Hook 시작/완료·중복·늦은 시작, 불명확 매핑, 다른 thread, 이력 복원·재진입, snapshot 중 live 도착·실패·StrictMode 재진입, 고정 순서와 모션 축소다. 실제 GUI·Native와 합성 투영 검증을 구분한다.

<a id="chat-usage-01"></a>

### CHAT-USAGE-01 — 모델·토큰·계정 한도의 근거

현재 요청의 Plan/Progress는 기본 Agent 개요에서 읽는다. 스레드 모델·시간·토큰·계정 한도는 상세 모니터의 관측으로 구분하며 다음 의미 경계를 유지한다. thread 시작 응답의 모델은 설정값이며 실제 모든 요청의 실행 모델로 단정하지 않는다. model/rerouted를 받으면 해당 턴의 관측된 전환으로 구분한다. tokenUsage.total은 스레드 누적 snapshot이며 반복 수신값을 더하지 않는다. last는 최근 모델 요청 사용량으로 별도 취급하고 턴 합계로 쓰지 않는다. 턴 토큰은 새 스레드의 명시적 영점 또는 안전한 이전 턴 누적값과의 차이만 제공한다. 기준이 없거나 누적값이 감소하거나 이력이 절단되거나 늦은 이전 턴 갱신으로 기준이 불확실해지면 미제공으로 둔다. 사용량의 reasoning은 제공된 토큰 숫자만 사용한다. 채팅의 공개 추론 요약 허용 범위는 CHAT-OBSERVE-01을 따른다.

계정 quota는 실제 account/rateLimits 조회·갱신에서 받은 bucket과 사용 비율·기간·재설정 시점만 표시한다. sparse 갱신의 미제공 메타데이터를 새 관측으로 꾸미지 않으며 턴 또는 모델별 청구액으로 해석하지 않는다. 모델별 비용·금액은 추정하지 않는다. 최근 2,000개 사건 보관 한계와 미제공을 명시하고 잘린 원본을 복원했다고 표시하지 않는다.

확인할 시나리오는 같은 누적값 재수신, 여러 모델 요청의 last와 턴 차분 구분, 기준 없는 이력·감소·음수/비정상 값 거부, 늦은 이전 턴 사용량, 구성/전환 모델 표시와 계정 bucket sparse 갱신이다. 실제 Native가 제공한 자료와 합성 fixture 결과는 별도로 기록한다.

## 현재 확인 범위와 후속 범위

현재 코드는 Electron 화면·전송·사건 투영과 위 요구를 다루는 기반을 제공한다. 기존 Chat 작업에는 실제 Codex 단문 응답과 실제 Electron 창에 합성 서버를 연결한 검증 기록이 있다. 실제 Native의 변경·승인 왕복 전체, Windows와 한국어 IME 실기를 모두 확인한 것으로 기술하지 않는다.

서버·별도 공유 DB·Roadmap·Node·Canvas, 원격 실행, 자동 게시와 Native 모델 자동 전환은 이 명세의 현재 범위가 아니다. 개발 역할·스킬·하네스의 내부 모델 배분과 영수증 기록은 별도 개발 기능이며 제품 Chat의 요청을 자동 분류하는 모델 라우터가 아니다. 탭별 동시 실행·모델 표시만으로 자동 배치나 토큰 절감을 주장하지 않는다. Native 원장을 이용한 대화 목록·재열기·재개는 CHAT-HISTORY-01을 따른다.

## 작업·검증과의 연결

변경 작업의 수용 기준은 `work.json`이 정의하고 해당 기준이 위 요구의 어느 부분을 바꾸거나 확인하는지 연결한다. 작업 `spec.md`는 기준 ID와 변경 배경·시나리오를 설명한다. 검증 시도는 실제 소스·기준·명령·관찰·한계를 남긴다. 요구 참조가 있다는 사실만으로 해당 동작이 검증된 것은 아니다.

과거 Chat 작업의 기준선과 판단은 당시 기록으로 보존한다. 현행 요구와 코드가 다르면 버그인지 요구 변경·명세 누락인지 조사하고, 파일 수정 시각만으로 어느 한쪽을 정답 처리하지 않는다.

<a id="chat-render-01"></a>

### CHAT-RENDER-01 — 오픈소스 채팅 표현과 입력

답변·공개 설명은 Markdown/GFM의 제목·목록·표·코드블록으로 읽는다. HTML을 실행하지 않고 이미지 URL을 자동 요청하지 않는다. 코드와 답변을 복사하고 답변을 인용해 초안에 추가할 수 있으며 인용은 자동 전송하지 않는다. 외부 링크는 main이 검증한 HTTP(S)만 연다.

입력은 Native 한도인 100,000 UTF-16 코드 단위를 넘기지 않고 붙여넣기 초과를 알린다. 두벌식으로 입력 중 일반 Enter를 한 번 누르면 마지막 음절을 확정한 뒤 메시지를 한 번 전송한다. Shift+Enter는 줄바꿈하며, 조합 취소와 키 반복은 전송을 추가하지 않는다. 전송 실패 시 초안을 보존한다. Ovis에서 개작한 입력·인용·논리 행 상태는 [코드 사용 고지](../third-party/ovis.md)를 따른다.

<a id="chat-history-01"></a>

### CHAT-HISTORY-01 — 프로젝트 대화 목록과 동일 Native 스레드 재개

선택한 cwd에 속하고 originator가 www인 Native 대화를 Native 원장에서 조회하고 페이지를 더 불러올 수 있다. 목록 검색은 이미 불러온 대화의 제목·미리보기 범위이며 전체 서버 검색으로 표시하지 않는다. 새 대화는 현재 선택을 해제하고 첫 전송에서 Native 스레드를 만든다. 저장된 대화를 읽고 같은 thread ID로 resume한 뒤 후속 요청을 보낸다. 앱 재시작 뒤에도 Native가 보존한 목록에서 다시 열 수 있다. 별도의 WWW 메시지 DB를 경쟁 원본으로 만들지 않는다.

저장된 공개 사용자 입력·답변·설명·공개 summary·명령·파일 변경만 historical snapshot으로 복원한다. 비공개 reasoning과 과거 승인 요청을 재생하지 않고 복원만으로 자동 보고서나 Skill/Hook live 반응을 발행하지 않는다. 저장된 실행 중 항목은 현재 실행 성공으로 만들지 않는다. 최근 표시 사건 한도와 불완전 이력을 구분하며 제공되지 않은 원본의 복원을 약속하지 않는다.

Native 프로세스가 끊긴 뒤 같은 대화를 계속할 때도 새 프로세스에서 실제 resume/read를 마쳐야 다음 턴을 시작한다. 재연결 snapshot은 기존 이력을 교체하고 경계 중 도착한 새 live 사건만 병합한다. 재연결을 반복해도 과거 본문을 중복 추가하거나 과거 활동 반응을 재생하지 않는다. 복원 실패와 결과가 불확실한 변경 요청은 성공이나 자동 재시도로 처리하지 않는다.

복원 중 live RPC는 현재 연결·선택·thread에 묶인 최대 2,000건·4 MiB 큐로 보류하고 snapshot과 marker 뒤 한 번만 처리한다. 한도 초과는 명시 실패로 알리고 새 요청을 보내지 않는다. terminal snapshot의 같은 turn/item에 속한 늦은 started/delta는 내용과 관계없이 억제하며 스트리밍을 다시 열지 않는다. 공개 완료 내용이 다른 authoritative `item/completed`, 새 turn/item과 현재 승인 요청은 보존한다. 큐 처리 중 실행·승인·중단 대기가 확인되면 이를 해소하기 전 새 사용자 입력이나 turn/start를 발행하지 않는다. 프로세스가 이미 잃은 사건이나 전환 경계 이전 연결의 사건까지 복구했다고 표시하지 않는다.

해당 탭의 실행·요청 전송·승인 대기·전환 중에는 그 탭 안의 다른 대화 선택과 새 대화를 차단한다. 다른 독립 탭으로의 이동은 허용한다. 다른 session/thread의 늦은 사건과 이전 전환 응답을 현재 대화에 합치지 않는다. 새 대화와 저장 대화 재개는 Bypass를 기본으로 하며 `approvalPolicy: "never"`, `sandbox: "danger-full-access"`를 명시한다. 재개할 때 저장된 Native 모델 설정은 덮어쓰지 않는다. 초안·읽기 위치·따라가기·도구 및 diff 펼침은 현재 창의 탭·대화별 메모리에 보존한다. 창 종료 후 초안까지 영속 복구하는 기능으로 확대하지 않는다.

## Chat 007 구현 경계

명령 카드는 실제 상태·명령·제공된 경로와 경과 시간을 표시한다. completed는 ‘실행 종료’로 표시하며 업무 완료와 구별한다. 명령의 따옴표 문자열과 옵션은 색상으로 구별하고 긴 명령은 내부에서 가로 스크롤한다. 실행 중 최근 10개 논리 줄, 종료 뒤 앞 10개 논리 줄을 기본 미리보기로 보이며 접어도 미리보기는 남는다. 보관된 출력을 펼치고 들여쓰기·탭을 보존하며 긴 줄은 출력 영역 안에서 가로로 읽는다. 실패는 기본 펼침으로 안내하되 사용자의 수동 펼침·접힘을 새 출력이나 종료로 바꾸지 않는다. stdout/stderr 구분이 제공되지 않으면 만들어 나누지 않는다. 시작 시각 없는 실행·복원 이력은 경과 시간을 추정하지 않는다.

공개 응답·설명의 늦은 시작 사건은 이미 누적한 본문을 덮어쓰지 않는다. 항목 완료·턴 종료·연결 종료 뒤의 늦은 델타는 스트리밍을 다시 열지 않으며 완료 snapshot은 정식 본문으로 수용한다. 답변 본문 자체에 명령 출력의 32,768자 한도를 적용하지 않는다. 채팅 본문에는 현재 턴의 공개 설명·명령·파일 변경·답변 수신 여부를 묶는 작업 흐름을 항상 두고, 공개 설명이 아직 없으면 내용을 만들지 않은 채 첫 작업 소식을 기다리는 상태와 실제 관측 수만 표시한다. 현재 턴의 경과 시간과 마지막 활동을 과거 턴과 격리하고 15초 이상 새 사건이 없으면 실패로 단정하지 않은 채 새 활동 대기로 표현한다. 승인·중단·연결 이상은 일반 무활동보다 우선해 표시한다. 종료·중단·실패·결과 미확인 뒤에는 최종 답변 수신, 명령·파일 변경, 식별된 검사, 실패·미확인을 실제 관측 범위에서 요약하며 응답 종료를 업무 검증 완료로 승격하지 않는다.

오른쪽 모니터는 선택한 과거 질문과 독립적으로 최신 작업·연결·마지막 활동·최근 Skill과 Hook을 보여준다. 복원한 이력을 실시간 호출로 표현하지 않는다. 공개 commentary는 질문별 흐름에도 표시하고 미제공 시 안내만 제공한다. 모델·토큰·계정 한도는 보조 상세에서 읽는다.

본문만 내부 스크롤로 늘어나고 입력·안내는 화면 안에 남는다. 본문 크기가 바뀌면 최신을 따라가던 경우 끝 위치를 유지하고, 과거를 읽던 경우 자동 이동하지 않는다. 세션 모니터를 접거나 열 수 있으며 999px 이하에서는 모니터를 겹침 보기로 제공한다. 실제 앱 최소 창 너비는 별도 Electron 설정을 따른다. 디자인 토큰과 상태 규칙은 [디자인 시스템](../design-system.md)에 연결한다. 이 절은 구현 동작이며 플랫폼·실기·독립 검토 통과 여부는 Chat 007 작업 기록에서 구분한다.

명령의 명시 `declined`는 거절로 표시한다. 턴 중단만 관측하고 명령 종료는 받지 못했으면 ‘턴 중단 · 명령 결과 미확인’으로 구별하며 개별 명령의 종료를 추정하지 않는다. 설치된 Native의 CommandExecutionStatus에는 interrupted 값이 없음을 생성 스키마로 확인했다. 보관 한도 초과 뒤의 미리보기는 ‘보관된 출력의 앞/최근 10줄’과 보관 범위 안 생략 수를 안내하고, 중간 줄에서 시작할 수 있음과 제거된 원본 줄 수 미확인을 표시한다. 자동 펼침 기본값은 사용자 선택 메모리에 기록하지 않고 사용자의 직접 조작만 보존한다.

## WWW 전용 역할·스킬의 관측

### CHAT-STAGE-01 — 구조화된 역할 단계 선언

문서 읽기·이름 언급·역할의 단계 선언·실제 하네스 실행·업무 수용을 구분한다. 명시적인 대기 사건이 없는 스킬은 미관측 또는 선택 미확인으로 표시하고 복수 요청에서 현재 항목이 모호하면 임의로 하나를 선택하지 않는다. 계획 자료 미제공·빈 계획·해석 실패를 구별하며, 공개 진행 설명은 활성 계획이 없어도 계획 미연결 설명으로 읽는다. 늦게 받은 계획이 이전 설명을 새 항목에 재귀속하지 않는다.

설치 Codex 0.169.0의 공식 실측에서 새 thread/start는 experimentalApi와 dynamicTools를 지원하지만 thread/resume에는 같은 등록 필드가 없다. 새 WWW 스레드에만 www_development_stage 도구와 사용 지침을 제공한다. 기존 대화 재개·다른 프로젝트·외부 개발 세션에 연결된 것으로 표시하지 않는다. 모델이 도구를 실제 호출했는지는 별도 관측이며 등록·사용 지침 전달이 호출을 보장하지 않는다.

단계 선언 도구는 공개 workId·phase(spec/design/build/diagnose/verify)·status(selected/running/completed/failed/interrupted)·attemptId만 받는다. main은 같은 연결·thread·turn, 지원된 도구 등록과 현재 승인 WWW 원장의 UUID·유일성을 검사한다. 과거 복원·다른 턴·종료 뒤 재개·중복 호출을 새 실행으로 만들지 않는다. completed는 역할 저자의 절차 종료 선언이다.

선택 또는 진행 선언으로 받은 실행 ID를 승인된 공식 WWW CLI의 eventId에 연결하고 프로세스가 종료하면, 같은 턴의 `www_observe_harness`가 로컬 영수증을 확인할 수 있다. 해당 작업의 최신 단계 시도에서만 공식 실행의 성공·실패와 시각을 역할 선언 옆에 표시한다. 해당 근거가 없으면 미연결로 표시한다. 호스트 실행 결과와 업무 수용·게시 상태는 각각 별도 근거를 사용한다.

기본 오른쪽 바는 WWW Agent와 spec/design/build/diagnose/verify 다섯 항목을 항상 표시한다. 설치·읽기·이름 언급은 실제 단계 실행과 구분하고, 구조화된 명시 선택 근거가 있을 때만 해당 항목을 강조한다. 실제 Subagent 사건의 식별자·부모·상태를 표시하며 도구 호출 종료만으로 작업 완료를 추정하지 않는다. agentsStates의 완료 상태가 확인되면 같은 항목을 유지하며 완료 표시등을 켠다. 복원 자료에 해당 사건이 없으면 자료 미제공으로 표시한다.

개요의 Plan은 Native 계획의 작업 항목·상태와 수신 시각을 표시한다. 새 WWW 대화의 첫 요청이나 실행 중 추가 지시의 첫 줄에 `/plan <작업 UUID>`를 입력하면 `www_link_plan`으로 해당 작업의 `tasks.md` 버전을 연결할 수 있다. main은 활성 턴과 사용자가 지정한 유일한 작업 UUID로 범위를 제한하고 문서 원문의 SHA-256을 확인한다. 작업 후보가 여러 개거나 역할 선언과 충돌하면 문서를 특정할 수 없다고 표시한다. Plan은 해당 버전의 경로·확인 시각·원문과 문서 없음·읽기 실패·버전 변경을 구분한다. 확인한 문서는 연결 시점의 스냅샷이다. 갱신판을 확인하려면 새 버전을 연결한다.

Progress는 Native 계획의 현재 활성 항목에 연결된 공개 진행 설명이다. 계획 변경·활성 항목 전환 뒤의 늦은 설명을 새 항목으로 임의 귀속하지 않는다. 연결한 파일이 Native 계획의 상태를 바꾸거나 공개 진행을 파일 체크리스트에 귀속시키지 않는다. Hook 목록·실행 현황과 범용 리소스 목록은 기본바에서 제외하고 별도 상세 모니터에 보존한다.

오른쪽 기본 사이드바의 고정 다섯 스킬·Agent/개요와 선택 대화의 누적 관측을 구분한다. 누적 관측, `www-dev`·`www-design-agent`와 여섯 `www-*` 스킬의 전체 정의 목록 및 선택한 질문의 상세 관측은 별도 상세 모니터에서 읽는다. 필요할 때 사용하는 절차이며 모든 스킬을 순서대로 실행한다고 표시하지 않는다. 요청, 구조화된 정본 파일 읽기, 엄격한 리터럴 cat의 정본 참조 명령, 실제 적용 확인은 서로 다른 근거다. 현재 구현에는 실제 역할 적용을 확인하는 구조화 사건이 없으므로 문서 읽기를 적용 완료로 표시하지 않는다. 선택 저장소와 명령 cwd를 기준으로 정확한 경로를 확인하며 다른 저장소·이름 언급·셸 확장·연쇄는 사용 관측으로 만들지 않는다.

범용 Hook·전체 명령 흐름과 모델·토큰은 기본 접힘 상세다. Hook 실패 관측과 신뢰 검토 필요 여부는 접힌 요약에서도 확인하고 정확 호출·실패 횟수를 만들지 않는다. 펼치면 sourcePath·statusMessage 및 제공된 error/warning/stop 항목을 제한된 범위로 읽는다. context 등 지침 내용은 오류 상세에 포함하지 않는다. Hook 실패는 개별 사건의 실제 상태이며 WWW 역할·스킬 적용 실패나 요청 전체의 실패를 추정하는 근거로 쓰지 않는다. 응답 종료와 업무 완료를 구별한다.

## 대화 누적 관측과 로컬 프로젝트

main의 단일 인스턴스 소유자만 사용자 앱 데이터의 `activity-v1/<workspaceKey>/<hash(threadId)>.json`에 검증한 리소스 관측 메타데이터를 저장한다. 채팅 원문의 별도 DB가 아니며 명령·출력·메시지·비공개 reasoning을 저장하지 않는다. 안정 관측 ID로 시작·완료·복원을 합치고 저장 상태와 `revision`/`durableRevision`, 부분 이력·손상·한도·저장 실패를 구분한다. renderer는 원장을 저장하거나 파일 경로·관측 내용·revision을 지정해 쓰지 않는다.

미등록 `SKILL.md`의 실제 구조화 읽기도 표시 이름만으로 합치지 않는다. main이 command cwd와 경로를 정규화해 SHA256 identity를 제공하고 비공개 원문 경로는 원장에 쓰지 않는다. 식별 콜백이 없거나 안전한 식별값을 만들지 못하면 `native-missing`으로 드러낸다. 알려진 WWW 문서는 정본 ID·상대 경로를 유지한다.

Native가 호출별 안정 식별을 제공하지 않으면 정확 횟수를 만들지 않는다. 확인한 Codex 0.167.2의 Hook `run.id`는 반복되는 핸들러 식별자이므로 실제 Hook 상태는 표시하되 호출 횟수 미제공과 `unstable-id`를 명시한다. 턴 없는 Hook은 현재 요청의 성공으로 귀속하지 않는다. 합성 provider namespace의 저장 테스트는 실제 Native의 식별 유일성 증거가 아니다.

같은 eventName의 서로 다른 제공 handler ID는 각각 마지막 상태를 유지한다. ID 미제공 시 합침 가능성을 표시하고 늦은 시작과 진짜 새 호출을 임의 구분하지 않는다. 새 요청 전송 중 이전 요청의 plan·호출은 현재 요청으로 표시하지 않으며 새 자료가 없으면 미제공으로 남긴다.

상세 모니터도 같은 handler 행의 최신 실행 상태를 유지한다. 비교 가능한 `run.startedAt`이 더 새로우면 이전 완료 상태와 타이머를 새 실행으로 갱신하고, 과거 시각·복원 사건은 최신 실시간 상태를 덮지 않는다. 시각이 같거나 없어서 새 호출과 재전송을 구분할 수 없으면 완료된 행을 다시 열지 않는다. 시작 시각이 확인된 실행에 시각 없는 완료가 오면 해당 실행의 완료로 단정하지 않으며, 턴 종료 시 남은 실행은 결과 미확인으로 표시한다. 이 상태 갱신을 정확한 호출 횟수의 근거로 사용하지 않는다.

최근 프로젝트·즐겨찾기는 로컬 앱 데이터의 공유 프로젝트 인덱스로 복원한다. 프로젝트 키는 선택한 디렉터리의 실제 경로를 SHA256으로 계산하며 별칭은 합치고 다른 실제 경로는 분리한다. 탭별 idle 상태에서 첫 스레드 이후에도 전환할 수 있지만 해당 탭의 실행·전송·승인·다른 전환 중에는 거부한다. 준비·flush 후 동기 커밋 직전에 선택과 busy 상태를 다시 검사한다. 성공하면 새 프로젝트의 대화를 명시적으로 다시 선택하며 과거 프로세스·연결·선택의 지연 응답을 합치지 않는다. 같은 thread 문자열이라도 프로젝트별 원장·초안·읽기 상태를 격리한다. Native subprocess도 해당 탭이 선택한 실제 디렉터리에서 시작한다. 다른 탭의 프로젝트와 실행은 유지한다.

열린 원장들의 flush가 일부 실패해도 전환할 수 있으나 실제 실패한 workspace/thread 목록을 전환 시점 저장 미확정 진단으로 별도 반환하고 화면 상태에 보존한다. 전체 실패를 현재 선택 프로젝트·대화의 실패로 추정하지 않는다. 새 프로젝트 목록/일반 오류 초기화로 진단을 지우거나 이전 원장 snapshot을 새 scope의 리소스로 수용하지 않는다.

### 명령 카드의 구조화 출력

명령 출력은 카드 안의 한 영역에서 미리보기와 보관된 전체 출력 사이를 전환한다. 숨긴 줄이 있을 때만 펼침 버튼을 표시하고 카드 안에 포커스가 있는 Ctrl+T는 해당 카드만 전환한다. JSON 보기·원문 복사·보관 한도와 실패 기본 펼침을 유지하고 대화별 수동 선택을 보존한다. 미리보기와 전체 출력의 두 영역을 중복 렌더링하지 않는다.

앱 프레임은 viewport에 고정하고 본문·목록·출력만 내부 스크롤한다. 여백·빈 내용·스크롤 끝에서 부모 페이지로 스크롤을 넘기지 않으며 입력 접근과 과거 읽기 위치를 보존한다. 실제 플랫폼 휠·키보드 검증은 작업 기록에서 구분한다.

초기 준비는 연결·초기화·대화 생성/재개·턴 전달과 첫 의미 있는 Native 사건의 main 단조 시간으로 계측한다. trace·종류·시각·출처만 관측하고 본문·명령·출력·추론을 계측 원장에 쓰지 않는다. renderer 수신부터 두 번째 animation frame까지의 근사는 main 시간과 별개로 기록한다. 앱이 표시하는 준비·진행 설명에는 앱 관측 출처를 붙이고 실제 Native 공개 판단 이유를 만들어내지 않는다. 계측 도입을 과거 지연 원인 확정이나 지연 해결로 승격하지 않는다.

종료된 명령의 절단되지 않은 완전한 JSON 객체·배열은 보기에서만 2칸 정렬하고 키·문자열·숫자·리터럴을 구별한다. 원문 숫자 표기·중복 키·이스케이프 토큰은 그대로 유지한다. 원문 보기와 원문 복사는 수신 문자열을 사용하며 보관 한도 밖 내용을 복구하지 않는다. 정렬 보기의 10줄·생략 수는 정렬된 표시 줄 기준이다. 실행 중·혼합 로그·NDJSON·불완전/절단 출력과 입력 32,768 단위·깊이 24·정렬 결과 131,072 단위 한도 초과는 원문으로 표시한다. 일반 출력의 공백·탭과 기존 펼침 정책은 유지한다.

완전한 종료 JSON의 review- 접두 ID·provider·model·verdict가 식별되면 pass/fail/not_run을 ‘출력의 검토 판정’ 보고값으로 표시한다. 프로세스 상태·종료 코드를 바꾸거나 업무 완료·검토 수용을 보증하지 않는다. 출력의 문구만으로 일반 로그의 업무 결과를 추정하지 않는다. 전환·복사 버튼은 키보드 접근과 복사 성공/실패 안내를 제공한다.
