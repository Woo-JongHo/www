# Chat 현행 기능 명세

## 목적과 적용 범위

Chat은 사용자가 로컬 Native와 대화하면서 공개 설명·명령·파일 변경·승인·중단·결과를 읽고 개입하는 작업 공간이다. 제품 목적과 장기 범위는 [제품 기준](../PRODUCT.md), 모듈과 사건 흐름은 [아키텍처](../ARCHITECTURE.md)가 소유한다.

이 문서는 현재 적용할 요구를 정한다. 구현에서 관찰한 사실이나 모든 플랫폼의 검증 완료 선언이 아니다. 이번에 바꿀 목표는 해당 작업 명세에서 관리하고, 검사한 소스 상태·결과·한계는 해당 작업의 검증 시도에서 확인한다. 적용과 충돌 처리 규칙은 [공통 계약](../skills/WORKFLOW.md#현행-기준과-정보별-정본)을 따른다.

## 요구와 주요 시나리오

<a id="chat-input-01"></a>

### CHAT-INPUT-01 — 요청과 전송 결과

사용자는 첫 스레드 전에 작업 폴더를 확인하고 비어 있지 않은 요청을 보낸다. 같은 요청의 전송 중 중복 제출을 막고, 전송 중·접수됨·전송 실패를 구분한다. 전송 실패 시 입력을 조용히 잃지 않으며, 전달 결과가 불명확한 변경 요청을 자동 재전송하지 않는다.

확인할 시나리오는 일반 입력, 빈 입력, 빠른 반복 전송, 요청 실패와 입력 초안 보존이다. 실제 모델 대화와 합성 서버의 입력·전송 검증은 각각 기록한다.

<a id="chat-observe-01"></a>

### CHAT-OBSERVE-01 — 공개 설명과 실제 사건의 출처

Native의 공개 답변·설명·계획과 명령·파일 변경을 출처와 thread/turn/item 연결을 보존해 표시한다. 명령은 동일 실행의 출력·상태를 갱신하며, 실패·결과 미확인·미제공·절단을 구분한다. 내부 사고를 생성하거나 다른 턴의 과거 사건을 현재 결과로 합치지 않는다.

새 Native 스레드에는 자연스러운 한국어 진행 설명을 요청하는 `developerInstructions`를 추가한다. 중요한 행동·결정의 이유, 확인 결과, 실패와 방향 전환의 근거를 충분히 설명하도록 요청하되 고정 단계 라벨이나 매 도구 호출마다 반복 문구를 강제하지 않는다. `baseInstructions`·모델·effort·전역 설정을 바꾸지 않고 턴의 `summary: "detailed"`로 공개 요약을 요청한다. 실제 설명 빈도는 모델 동작이며 지침 전달만으로 보장하지 않는다.

채팅은 `item/reasoning/summaryTextDelta`·`summaryPartAdded`와 reasoning 항목 시작·완료의 `summary: string[]`만 공개 추론 요약으로 허용한다. 원문 `content`·reasoning `textDelta`·analysis는 표시하지 않으며 잘못된 summary를 원문으로 대체하지 않는다. 공개 설명·요약은 수신 시간순의 본문으로 읽고 출처는 접근성 이름으로 구분한다. 실제 요약이 없으면 빈 자리표시를 만들지 않는다.

요약은 thread/turn/item과 섹션 index를 격리하고 중복 seq를 억제한다. 완료 snapshot은 이전 요약을 대체하며 턴 종료·EOF 뒤에는 스트리밍을 닫고 늦은 델타로 재시작하지 않는다. 빈 섹션 알림은 배열을 확장하지 않으며 index는 0 이상 32,768 미만의 안전한 정수만 받는다. 본문은 문단 구분자를 포함해 앞 32,768 UTF-16 코드 단위로 제한하고 절단 안내를 표시한다. 요약은 모델이 제공한 설명이며 실제 실행·검증의 증거를 대신하지 않는다.

확인할 시나리오는 응답·요약 스트리밍, 공개 설명 미제공, 섹션·중복·완료 snapshot·잘못된 입력·원문 미노출, 명령 출력과 파일 변경, 다른 턴의 늦은 사건, 종료·EOF·긴 출력의 제한 표시다. 실행 종료와 업무 수용·실제 검증은 별개다.

<a id="chat-approval-01"></a>

### CHAT-APPROVAL-01 — 지원되는 승인과 단일 응답

지원되는 명령·파일 승인 요청은 원래 문자열 또는 숫자 ID로 응답한다. 열린 요청, 응답 전송 중, 응답됨, 결과 미확인을 구분하고 같은 요청의 중복 응답을 막는다. 지원하지 않는 구조화 요청은 그렇게 표시하며 임의로 승인하지 않는다. UI는 관찰된 요청을 표현하며 OS sandbox 보장이 아니다.

확인할 시나리오는 숫자·문자열 ID, 허용·거절·중단, 반복 클릭, EOF 중 미결 승인, 미지원 요청이다.

<a id="chat-stop-01"></a>

### CHAT-STOP-01 — 중단 요청과 확인의 구분

실행 중인 턴에 중단을 요청할 수 있다. 요청 중·호스트의 접수·최종 턴 결과를 구분하고, 요청 중 반복 클릭이 중복 제출로 이어지지 않게 한다. 전송 실패나 연결 끊김은 중단 성공으로 표시하지 않는다.

요청을 보낸 `requested`와 호스트가 접수한 `accepted`는 모두 중복 제출을 막는다. 실제 현재 턴의 `interrupted` 종료를 받으면 이전 요청의 결과가 불확실했어도 중단 확인으로 표시한다. 정상·실패·알 수 없는 종료와 연결 끊김은 중단 성공으로 추정하지 않는다. 종료 뒤 도착한 접수·요청 사건과 다른 턴의 사건이 확인한 결과를 덮어쓰지 않아야 한다.

확인할 시나리오는 실행 중 중단, 요청 중 반복 입력, 중단 응답 실패, 최종 `interrupted` 결과와 접수만 된 상태의 구분이다. 구체적인 개선 여부와 회귀 검증은 이 요구를 참조하는 Chat 작업에서 기록한다.

<a id="chat-error-01"></a>

### CHAT-ERROR-01 — 실패와 읽기 상태

연결 끊김·명령 실패·결과 불확실·승인 대기를 사용자가 찾을 수 있게 표시한다. 사건이 추가돼도 사용자가 읽던 위치·직접 펼친 상태·입력 초안을 보존하고 새 내용으로 돌아갈 수 있게 한다. 보관 한계를 넘은 원본을 복원할 수 있다고 표시하지 않는다.

확인할 시나리오는 EOF·오류, 실패한 명령, 과거 내용 읽기 중 새 출력, 긴 출력, 키보드·한국어 입력·포커스다. 실제 GUI·플랫폼 검사를 수행하지 않았다면 합성 테스트 통과와 구분한다.

<a id="chat-activity-01"></a>

### CHAT-ACTIVITY-01 — 답변 턴별 실시간 활동

오른쪽 Native 활동 패널은 수신 사건을 답변 턴별로 묶어 요청·공개 답변·계획 단계·도구 상태를 표시한다. 과거 턴 선택을 새 사건 때문에 바꾸지 않으며 최신 턴으로 돌아갈 수 있다. 기존 대화·명령·파일·승인·리포트·생태계 보기와 입력 초안을 유지한다. 경과 시간은 진행 중에만 갱신하고 종료 뒤에는 종료 시점으로 고정한다. thread/turn·clientRequestId를 보존하고 seq와 item/run ID의 중복을 억제하며, 늦은 ACK·과거 턴 사건을 현재 턴 결과로 합치지 않는다. 도구 종료가 없으면 턴 종료만으로 성공을 추정하지 않는다.

Skill 입력은 명시 요청이며 적용 성공 증거가 아니다. 명령의 구조화 commandActions에서 read와 SKILL.md 경로를 수신하면 읽기 시도를 시작부터 표시하고, 완료 성공·실패·결과 미확인을 구분한다. 이름 언급·임의 명령 문자열·skills/changed는 사용 증거가 아니다. 동기 Hook의 시작·완료·실패·차단·중단은 실제 run으로 표시하며 명시 turn이 없는 Hook은 세션 활동으로 둔다. 비동기 Hook, 누락된 사건과 비공개 reasoning 본문을 만들어 보충하지 않는다.

확인할 시나리오는 순서 재생·중복 수신·늦은 ACK·후속 턴 분리, 정상/실패/중단/종료 누락, Skill 이름만 언급한 입력, 명시 요청과 읽기 관측, turn 없는 Hook, 과거 턴 읽기와 키보드 조작이다. 실제 GUI와 합성 투영 검증을 구분한다.

<a id="chat-usage-01"></a>

### CHAT-USAGE-01 — 모델·토큰·계정 한도의 근거

thread 시작 응답의 모델은 설정값이며 실제 모든 요청의 실행 모델로 단정하지 않는다. model/rerouted를 받으면 해당 턴의 관측된 전환으로 구분한다. tokenUsage.total은 스레드 누적 snapshot으로 표시하며 반복 수신값을 더하지 않는다. last는 최근 모델 요청 사용량으로 별도 표시하고 턴 합계로 쓰지 않는다. 턴 토큰은 새 스레드의 명시적 영점 또는 안전한 이전 턴 누적값과의 차이만 제공한다. 기준이 없거나 누적값이 감소하거나 이력이 절단되거나 늦은 이전 턴 갱신으로 기준이 불확실해지면 미제공으로 표시한다. 사용량의 reasoning은 제공된 토큰 숫자만 사용한다. 채팅의 공개 추론 요약 허용 범위는 CHAT-OBSERVE-01을 따른다.

계정 quota는 실제 account/rateLimits 조회·갱신에서 받은 bucket과 사용 비율·기간·재설정 시점만 표시한다. sparse 갱신의 미제공 메타데이터를 새 관측으로 꾸미지 않으며 턴 또는 모델별 청구액으로 해석하지 않는다. 모델별 비용·금액은 추정하지 않는다. 최근 2,000개 사건 보관 한계와 미제공을 명시하고 잘린 원본을 복원했다고 표시하지 않는다.

확인할 시나리오는 같은 누적값 재수신, 여러 모델 요청의 last와 턴 차분 구분, 기준 없는 이력·감소·음수/비정상 값 거부, 늦은 이전 턴 사용량, 구성/전환 모델 표시와 계정 bucket sparse 갱신이다. 실제 Native가 제공한 자료와 합성 fixture 결과는 별도로 기록한다.

## 현재 확인 범위와 후속 범위

현재 코드는 Electron 화면·전송·사건 투영과 위 요구를 다루는 기반을 제공한다. 기존 Chat 작업에는 실제 Codex 단문 응답과 실제 Electron 창에 합성 서버를 연결한 검증 기록이 있다. 실제 Native의 변경·승인 왕복 전체, Windows와 한국어 IME 실기를 모두 확인한 것으로 기술하지 않는다.

서버·별도 공유 DB·Roadmap·Node·Canvas, 원격 실행, 자동 게시와 Native 모델 자동 전환은 이 명세의 현재 범위가 아니다. Native 원장을 이용한 대화 목록·재열기·재개는 CHAT-HISTORY-01을 따른다.

## 작업·검증과의 연결

변경 작업의 수용 기준은 `work.json`이 정의하고 해당 기준이 위 요구의 어느 부분을 바꾸거나 확인하는지 연결한다. 작업 `spec.md`는 기준 ID와 변경 배경·시나리오를 설명한다. 검증 시도는 실제 소스·기준·명령·관찰·한계를 남긴다. 요구 참조가 있다는 사실만으로 해당 동작이 검증된 것은 아니다.

과거 Chat 작업의 기준선과 판단은 당시 기록으로 보존한다. 현행 요구와 코드가 다르면 버그인지 요구 변경·명세 누락인지 조사하고, 파일 수정 시각만으로 어느 한쪽을 정답 처리하지 않는다.

<a id="chat-render-01"></a>

### CHAT-RENDER-01 — 오픈소스 채팅 표현과 입력

답변·공개 설명은 Markdown/GFM의 제목·목록·표·코드블록으로 읽는다. HTML을 실행하지 않고 이미지 URL을 자동 요청하지 않는다. 코드와 답변을 복사하고 답변을 인용해 초안에 추가할 수 있으며 인용은 자동 전송하지 않는다. 외부 링크는 main이 검증한 HTTP(S)만 연다.

입력은 Native 한도인 100,000 UTF-16 코드 단위를 넘기지 않고 붙여넣기 초과를 알린다. 기존 Enter/Shift+Enter·한국어 조합 입력·전송 중복 방지·실패 초안 보존을 유지한다. Ovis에서 개작한 입력·인용·논리 행 상태는 [코드 사용 고지](../third-party/ovis.md)를 따른다.

<a id="chat-history-01"></a>

### CHAT-HISTORY-01 — 프로젝트 대화 목록과 동일 Native 스레드 재개

선택한 cwd에 속하고 originator가 www인 Native 대화를 Native 원장에서 조회하고 페이지를 더 불러올 수 있다. 목록 검색은 이미 불러온 대화의 제목·미리보기 범위이며 전체 서버 검색으로 표시하지 않는다. 새 대화는 현재 선택을 해제하고 첫 전송에서 Native 스레드를 만든다. 저장된 대화를 읽고 같은 thread ID로 resume한 뒤 후속 요청을 보낸다. 앱 재시작 뒤에도 Native가 보존한 목록에서 다시 열 수 있다. 별도의 WWW 메시지 DB를 경쟁 원본으로 만들지 않는다.

저장된 공개 사용자 입력·답변·설명·공개 summary·명령·파일 변경만 historical snapshot으로 복원한다. 비공개 reasoning과 과거 승인 요청을 재생하지 않고 복원만으로 자동 보고서나 Skill/Hook live 반응을 발행하지 않는다. 저장된 실행 중 항목은 현재 실행 성공으로 만들지 않는다. 최근 표시 사건 한도와 불완전 이력을 구분하며 제공되지 않은 원본의 복원을 약속하지 않는다.

실행·요청 전송·승인 대기·전환 중에는 다른 대화 선택과 새 대화를 차단한다. 다른 thread의 늦은 사건과 이전 전환 응답을 현재 대화에 합치지 않는다. 재개할 때 저장된 Native 모델·승인·sandbox 설정을 임의로 덮어쓰지 않는다. 초안·읽기 위치·따라가기·도구 및 diff 펼침은 현재 창의 대화별 메모리에 보존한다. 창 종료 후 초안까지 영속 복구하는 기능으로 확대하지 않는다.
