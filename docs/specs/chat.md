# Chat 현행 기능 명세

## 목적과 적용 범위

Chat은 사용자가 로컬 Native와 대화하면서 공개 설명·명령·파일 변경·승인·중단·결과를 읽고 개입하는 작업 공간이다. 제품 목적과 장기 범위는 [제품 기준](../PRODUCT.md), 모듈과 사건 흐름은 [아키텍처](../ARCHITECTURE.md)가 소유한다.

이 문서는 현재 적용할 요구를 정한다. 구현에서 관찰한 사실이나 모든 플랫폼의 검증 완료 선언이 아니다. 이번에 바꿀 목표는 해당 작업 명세에서 관리하고, 검사한 소스 상태·결과·한계는 해당 작업의 검증 시도에서 확인한다. 적용과 충돌 처리 규칙은 [공통 계약](../skills/WORKFLOW.md#현행-기준과-정보별-정본)을 따른다.

## 요구와 주요 시나리오

<a id="chat-input-01"></a>

### CHAT-INPUT-01 — 요청과 전송 결과

사용자는 첫 스레드 전에 작업 폴더를 확인하고 비어 있지 않은 요청을 보낸다. 같은 요청의 전송 중 중복 제출을 막고, 전송 중·접수됨·전송 실패를 구분한다. 전송 실패 시 입력을 조용히 잃지 않으며, 전달 결과가 불명확한 변경 요청을 자동 재전송하지 않는다.

확인할 시나리오는 일반 입력, 빈 입력, 빠른 반복 전송, 요청 실패와 입력 초안 보존이다. 실제 모델 대화와 합성 서버의 입력·전송 검증은 각각 기록한다.

<a id="chat-observe-01"></a>

### CHAT-OBSERVE-01 — 공개 설명과 실제 사건의 출처

Native의 공개 답변·설명·계획과 명령·파일 변경을 출처와 thread/turn/item 연결을 보존해 표시한다. 명령은 동일 실행의 출력·상태를 갱신하며, 실패·결과 미확인·미제공·절단을 구분한다. 내부 사고를 생성하거나 다른 턴의 과거 사건을 현재 결과로 합치지 않는다.

확인할 시나리오는 응답 스트리밍, 공개 설명 미제공, 명령 출력과 파일 변경, 다른 턴의 늦은 사건, 긴 출력의 제한 표시다. 실행 종료와 업무 수용·실제 검증은 별개다.

<a id="chat-approval-01"></a>

### CHAT-APPROVAL-01 — 지원되는 승인과 단일 응답

지원되는 명령·파일 승인 요청은 원래 문자열 또는 숫자 ID로 응답한다. 열린 요청, 응답 전송 중, 응답됨, 결과 미확인을 구분하고 같은 요청의 중복 응답을 막는다. 지원하지 않는 구조화 요청은 그렇게 표시하며 임의로 승인하지 않는다. UI는 관찰된 요청을 표현하며 OS sandbox 보장이 아니다.

확인할 시나리오는 숫자·문자열 ID, 허용·거절·중단, 반복 클릭, EOF 중 미결 승인, 미지원 요청이다.

<a id="chat-stop-01"></a>

### CHAT-STOP-01 — 중단 요청과 확인의 구분

실행 중인 턴에 중단을 요청할 수 있다. 요청 중·호스트의 접수·최종 턴 결과를 구분하고, 요청 중 반복 클릭이 중복 제출로 이어지지 않게 한다. 전송 실패나 연결 끊김은 중단 성공으로 표시하지 않는다.

확인할 시나리오는 실행 중 중단, 요청 중 반복 입력, 중단 응답 실패, 최종 `interrupted` 결과와 접수만 된 상태의 구분이다. 구체적인 개선 여부와 회귀 검증은 이 요구를 참조하는 Chat 작업에서 기록한다.

<a id="chat-error-01"></a>

### CHAT-ERROR-01 — 실패와 읽기 상태

연결 끊김·명령 실패·결과 불확실·승인 대기를 사용자가 찾을 수 있게 표시한다. 사건이 추가돼도 사용자가 읽던 위치·직접 펼친 상태·입력 초안을 보존하고 새 내용으로 돌아갈 수 있게 한다. 보관 한계를 넘은 원본을 복원할 수 있다고 표시하지 않는다.

확인할 시나리오는 EOF·오류, 실패한 명령, 과거 내용 읽기 중 새 출력, 긴 출력, 키보드·한국어 입력·포커스다. 실제 GUI·플랫폼 검사를 수행하지 않았다면 합성 테스트 통과와 구분한다.

## 현재 확인 범위와 후속 범위

현재 코드는 Electron 화면·전송·사건 투영과 위 요구를 다루는 기반을 제공한다. 기존 Chat 작업에는 실제 Codex 단문 응답과 실제 Electron 창에 합성 서버를 연결한 검증 기록이 있다. 실제 Native의 변경·승인 왕복 전체, Windows와 한국어 IME 실기를 모두 확인한 것으로 기술하지 않는다.

대화 영속 저장·재열기·동일 Native thread 복구, 서버·DB·Roadmap·Node·Canvas, 원격 실행, 자동 게시와 Native 모델 자동 전환은 이 명세의 현재 범위가 아니다.

## 작업·검증과의 연결

변경 작업의 수용 기준은 `work.json`이 정의하고 해당 기준이 위 요구의 어느 부분을 바꾸거나 확인하는지 연결한다. 작업 `spec.md`는 기준 ID와 변경 배경·시나리오를 설명한다. 검증 시도는 실제 소스·기준·명령·관찰·한계를 남긴다. 요구 참조가 있다는 사실만으로 해당 동작이 검증된 것은 아니다.

과거 Chat 작업의 기준선과 판단은 당시 기록으로 보존한다. 현행 요구와 코드가 다르면 버그인지 요구 변경·명세 누락인지 조사하고, 파일 수정 시각만으로 어느 한쪽을 정답 처리하지 않는다.
