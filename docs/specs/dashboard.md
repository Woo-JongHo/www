# View Page와 프로젝트 작업 보드

## DASHBOARD-ENTRY-01 — 진입과 대상 선택

첫 기본 탭의 진입은 프로젝트 미선택의 View Page다. 왼쪽 RPA 목록·기존 폴더 추가와 별도 WWW, 중앙 전체 대시보드를 제공한다. 0개 프로젝트에서도 진입할 수 있다. 대상 선택 후 대시보드·대화·생태계·리포트 순서로 이동하고 전체 보기로 돌아갈 수 있다. 화면 탐색 자체는 실행 중단이 아니며 해당 탭의 다른 실제 프로젝트로 전환할 때는 기존 전송·실행·미결 승인 보호를 지킨다. 같은 프로젝트의 보기를 여는 동작은 대시보드 수집 완료에 의존하지 않는다. 추가 Codex 대화 탭은 현재 프로젝트에서 시작하고 독립 실행 상태를 가지며 [Chat 탭 계약](chat.md#chat-sessions-01)을 따른다.

대화 목록·새 대화·검색은 대화 안에서 읽는다. View Page/보드 조회만으로 Native 프로세스를 시작하지 않는다. 현재 WWW 고정 경로는 app.getAppPath의 실제 개발 checkout이다. 패키지에 없는 소스 작업 기록이나 사용자가 선택한 임의 프로젝트의 WWW 구조 자동 분석을 약속하지 않는다.

## DASHBOARD-DATA-01 — 원본과 수집

main의 해당 native-session이 공유 등록 인덱스와 WWW 실제 경로를 정하고 같은 경로는 중복 집계하지 않는다. renderer가 임의 경로를 지정해 읽을 수 없다. `docs/work/**/work.json`만 한도 내에서 읽고 심볼릭 링크·잘못된 경로·잘못된 JSON·동일 프로젝트의 중복 UUID·초과 자료를 오류로 남긴다. 사용자 폴더의 코드·설정 스크립트를 실행하지 않는다. 한도는 전체 프로젝트 100개, 프로젝트당 기록 500개·탐색 항목 5,000개·깊이 5, 단일 파일 4 MiB·전체 읽기 32 MiB다. 다른 프로젝트의 같은 UUID는 프로젝트 key로 구분한다.

원본의 draft/ready/in_progress/verifying/done/cancelled 상태와 blockedReason을 보존한다. 대기·진행 중·검토 필요·완료와 선택적 취소 보기는 원본 상태의 파생 보기다. blockedReason만으로 사용자 응답 필요를 추정하지 않는다. 실제 대응 근거가 없는 응답 필요 카드는 만들지 않는다. 기준 통과 수는 원장에 기록된 수이며 현재 재검증 성공이 아니다.

전체/대상 범위를 필터하고 UUID·원본 경로·상태·차단 이유를 상세로 읽는다. 실제 thread 연결이 없는 카드는 임의 대화로 열지 않는다. 보드 이동으로 원장 상태·Git·프로젝트 파일을 변경하지 않는다. 정상/빈 자료/부분 실패/전체 실패와 수집 시각을 구분하고 일부 수집 실패의 숫자는 확인한 건수로 표시한다.

## 구현과 검증의 경계

최근 수집은 화면의 15초 갱신과 명시적 새로고침에 따른 읽기 snapshot이며 모든 프로젝트의 실시간 실행 상태를 의미하지 않는다. 실제 Codex 탭의 실행·승인·실패는 상단 탭의 세션 관측에서 구분한다. 탭 실행 종료를 작업 카드의 완료로 승격하거나 thread 근거 없이 카드와 대화를 연결하지 않는다.

사용자는 여러 터미널의 범위를 독립 Codex 대화 탭과 동시 실행으로 확정했고 일반 셸/PTY는 포함하지 않았다. 개발용 스킬·하네스의 내부 모델 배분은 제품 Chat의 자동 모델 라우터와 구분한다. 제품 자동 라우터와 토큰 절감 실측은 구현·검증한 것으로 표시하지 않는다. 기능 구현과 실제 Electron·독립 검토의 수용은 Home002 UUID의 작업 레코드와 검증 기록이 소유한다.
