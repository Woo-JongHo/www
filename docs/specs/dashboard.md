# View Page와 프로젝트 작업 보드

## DASHBOARD-ENTRY-01 — 진입과 대상 선택

첫 기본 탭의 진입은 프로젝트 미선택의 View Page다. 왼쪽 RPA 목록·기존 폴더 추가와 별도 WWW, 중앙 전체 대시보드를 제공한다. 0개 프로젝트에서도 진입할 수 있다. 대상 선택 후 대시보드·대화·생태계·리포트·모니터링 순서로 이동한다. 프로젝트 목록 탐색은 중앙 화면과 분리하며 목록 열기·닫기·현재 프로젝트 재선택이 현재 대화·보고서·지도 선택을 초기화하지 않는다. 전체 대시보드는 목록의 명시적 조작으로 연다. 화면 탐색 자체는 실행 중단이 아니며 해당 탭의 다른 실제 프로젝트로 전환할 때는 기존 전송·실행·미결 승인 보호를 지킨다. 같은 프로젝트의 보기를 여는 동작은 대시보드 수집 완료에 의존하지 않는다. 추가 Codex 대화 탭은 현재 프로젝트에서 시작하고 독립 실행 상태를 가지며 [Chat 탭 계약](chat.md#chat-sessions-01)을 따른다.

대화 목록·새 대화·검색은 대화 안에서 읽는다. View Page/보드 조회만으로 Native 프로세스를 시작하지 않는다. 현재 WWW 고정 경로는 app.getAppPath의 실제 개발 checkout이다. 패키지에 없는 소스 작업 기록이나 사용자가 선택한 임의 프로젝트의 WWW 구조 자동 분석을 약속하지 않는다.

## DASHBOARD-DATA-01 — 원본과 수집

main의 해당 native-session이 공유 등록 인덱스와 WWW 실제 경로를 정하고 같은 경로는 중복 집계하지 않는다. renderer가 임의 경로를 지정해 읽을 수 없다. `docs/work/**/work.json`만 한도 내에서 읽고 심볼릭 링크·잘못된 경로·잘못된 JSON·동일 프로젝트의 중복 UUID·초과 자료를 오류로 남긴다. 사용자 폴더의 코드·설정 스크립트를 실행하지 않는다. 한도는 전체 프로젝트 100개, 프로젝트당 기록 500개·탐색 항목 5,000개·깊이 5, 단일 파일 8 MiB·전체 읽기 64 MiB다. 같은 Git 공통 디렉터리를 사용하며 Git에 등록된 WWW 연결 체크아웃은 하나의 보드 범위로 묶는다. 같은 작업 UUID는 앱의 고정 WWW 경로를 우선하며, 그 경로에 없는 UUID는 연결 체크아웃의 경로 순서에서 먼저 확인한 출처를 표시한다. 원격 URL이 같은 별도 클론과 독립 프로젝트는 자체 key로 집계한다. Git 메타데이터를 확인할 수 없는 프로젝트도 기존 독립 범위로 읽는다.

원본의 draft/ready/in_progress/verifying/done/cancelled 상태와 blockedReason을 보존한다. 대기·진행 중·검토 필요·완료와 선택적 취소 보기는 원본 상태의 파생 보기다. 검토 필요 카드와 상세는 원본 `verifying`을 유지하며 `workflow.nextAction`에 따라 검증·리뷰·수정·완료 처리 대기를 구분한다. 이전 Native 실행 요약과 이전 형식 원장은 각각 표시하고, 다음 단계가 비어 있는 현행 원장은 미기록으로 표시한다. blockedReason만으로 사용자 응답 필요를 추정하지 않는다. 실제 대응 근거가 없는 응답 필요 카드는 만들지 않는다. 기록된 필수 통과 수와 현재 적용 가능한 필수 근거 수를 함께 표시한다.

전체, WWW 연결 체크아웃 또는 각 독립 프로젝트 범위를 필터한다. 카드와 상세에 원본 프로젝트 또는 연결 체크아웃의 출처를 표시한다. 보드 범위 필터와 카드 열기는 현재 대화의 작업 폴더를 전환하지 않는다. UUID·원본 경로·상태·차단 이유를 상세로 읽는다. 실제 thread 연결이 없는 카드는 임의 대화로 열지 않는다. 보드 이동으로 원장 상태·Git·프로젝트 파일을 변경하지 않는다. 정상/빈 자료/부분 실패/전체 실패와 수집 시각을 구분하고 일부 수집 실패의 숫자는 확인한 건수로 표시한다.

WWW 보드의 GitHub 열린 이슈 수는 저장소 전체의 외부 조회 결과다. 업무 단계별 카드 수는 현재 보드 범위의 로컬 `work.json`에서 집계한다. `docs/github-issues.json`은 이슈 번호와 작업 UUID의 명시 연결을 소유한다. 연결 근거가 없는 카드는 미연결로 표시한다. 선택적으로 `node scripts/dashboard-github.ts`를 실행하면 GitHub GET으로 모든 페이지를 조회해 로컬 `.www/github-issues.snapshot.json`을 갱신한다. 앱은 저장소 ID가 일치하는 기록과 조회 시각을 표시한다. 기록 없음·실패·오류는 수치 미확인으로 표시한다. 조회와 집계 기능은 로컬 업무 상태와 GitHub 이슈를 각각 보존한다.

## DASHBOARD-RECONCILIATION-01 — GitHub 이슈·작업 원장 감시 설계

감시의 입력은 GitHub 이슈 상태와 기본 브랜치의 `docs/work/**/work.json`·`docs/github-issues.json`이며, 두 원본을 어느 한쪽으로 자동 변경하지 않는다. 현재 앱의 15초 갱신과 수동 새로고침은 이미 저장한 로컬 snapshot과 원장만 다시 읽는다. GitHub webhook 수신기나 백그라운드 스케줄러는 아직 제품에 등록하지 않았으므로, 이 화면 갱신을 외부 이슈 감시로 표시하지 않는다.

후속 감시 실행의 트리거는 다음 세 가지다. GitHub `issues`의 `opened`·`reopened`·`closed` 이벤트는 해당 저장소의 이슈 snapshot 갱신과 대조를 요청한다. 기본 브랜치에 원장 또는 연결 설정이 바뀌는 push는 원장 대조를 요청한다. 두 이벤트가 없더라도 1시간마다 주기 대조해 전달 실패나 직접 변경을 찾는다. 각 실행은 `node scripts/dashboard-github.ts`로 전체 페이지를 다시 조회하고, 같은 실행에서 읽은 기본 브랜치 원장과 snapshot의 조회 시각·커밋 식별을 함께 보고한다.

상태 대응은 `draft`·`ready`·`in_progress`·`verifying` 작업에는 GitHub `open`, `done`·`cancelled` 작업에는 GitHub `closed`를 기대값으로 둔다. 감시는 이슈를 열거나 닫지 않는다. 성공한 조회에서만 연결 없는 열린 이슈, 존재하지 않는 이슈·작업을 가리키는 연결, 그리고 기대값과 다른 연결 상태를 불일치로 보고한다. 보고 항목에는 트리거, 조회 시각, 기본 브랜치 커밋, 이슈 번호, 작업 UUID·원본 경로, 로컬 상태, GitHub 실제·기대 상태와 해소 담당을 포함한다. 반대로 GitHub 조회 실패·저장소 ID 불일치·손상된 snapshot은 `조회 실패` 또는 `조회 기록 오류`로만 보고하고 실제 상태 불일치 건수에 합산하지 않는다.

## DASHBOARD-WORK-01 — 작업 계획과 검증 근거 읽기

카드 선택은 같은 projectKey와 UUID의 기준·다음 단계·명세·설계·계획·검증 근거를 보드 안에서 연다. 상세 요약과 기준은 같은 상세 원장 응답을 사용한다. schema2의 다음 단계는 workflow.nextAction이 소유한다. WWW 개발 체크아웃의 필수 기준은 공식 하네스와 같은 기준 정의·최신 시도·실행 환경·소스·원문 비교로 현재 적용성을 평가한다. 기준마다 현재 유효, 유효하지 않음, 검증 시도 없음, 미평가 및 사유를 표시한다. 외부 프로젝트, 이전 원장, 읽기 한도와 지원하지 않는 환경 입력은 미평가로 표시한다. 조회는 검증 명령을 실행하지 않는다. 파일 지문과 실행 파일 지문은 한 조회에서 공유한다.

main이 승인 프로젝트에서 UUID 유일성을 확인한 뒤 같은 작업 폴더의 spec.md·design.md·tasks.md·verification.md만 읽는다. renderer가 파일 경로를 보내지 않는다. 문서당 256 KiB·합계 1 MiB, 일반 파일·UTF-8·링크·읽기 전후 교체 검사를 적용하고 상한 초과를 잘라 성공으로 표시하지 않는다. 개별 문서 누락·빈 본문·읽기 실패는 구분하며 정상 기준과 다른 문서를 보존한다. Markdown의 HTML·활성 링크·이미지는 실행하지 않는다.

다른 카드·프로젝트 범위·닫기 뒤 늦은 응답은 숨기고 같은 작업의 재수집 중에는 펼친 문서와 읽기 상태를 유지한다. 갱신 실패 시 이전 수집 내용과 시각을 표시한다. 키보드로 상세를 열고 닫으며, 카드가 다른 열로 이동해도 현재 카드로 초점을 복귀한다. 명세·계획 작성이나 문서 조회는 실행·검증·업무 완료 사건을 만들지 않는다.

## 구현과 검증의 경계

최근 수집은 화면의 15초 갱신과 명시적 새로고침에 따른 읽기 snapshot이며 모든 프로젝트의 실시간 실행 상태를 의미하지 않는다. 실제 Codex 탭의 실행·승인·실패는 상단 탭의 세션 관측에서 구분한다. 탭 실행 종료를 작업 카드의 완료로 승격하거나 thread 근거 없이 카드와 대화를 연결하지 않는다.

사용자는 여러 터미널의 범위를 독립 Codex 대화 탭과 동시 실행으로 확정했고 일반 셸/PTY는 포함하지 않았다. 개발용 스킬·하네스의 내부 모델 배분은 제품 Chat의 자동 모델 라우터와 구분한다. 제품 자동 라우터와 토큰 절감 실측은 구현·검증한 것으로 표시하지 않는다. 기능 구현과 실제 Electron·독립 검토의 수용은 Home002 UUID의 작업 레코드와 검증 기록이 소유한다.
