# 이슈에서 검증 완료까지 공개 개발 루프 비교

조사 기준일은 2026-11-22다. WWW의 실행 경로는 공개 `main`의 `939c7ef`를 기준으로 대조했다. 목표는 사용자가 이슈나 고칠 증상을 한 번 넣으면 WWW가 같은 작업 UUID로 조사, 구현, 검증, 검토, 실패 수정과 완료까지 이어가는 것이다. 공개 명세와 구현을 대조했으며 각 시스템을 설치하거나 동일 이슈에서 실행한 벤치마크는 포함하지 않는다.

## WWW에서 채울 연결

현재 `runDevelopmentWorkflow`는 호출 의도에 맞춰 한 단계를 수행한다. 개발 실행에 검증기가 제공되면 같은 호출에서 검증까지 이어갈 수 있다. 실행 잠금, 이벤트 ID, 결과 영수증, 같은 UUID의 `resume`, 증거의 적용성을 다시 확인하는 `complete`도 이미 있다. 확인한 공식 진입점에서 남는 일은 이 단계들을 이슈 한 건의 실행으로 묶고, 결과를 읽은 호출자가 다음 단계를 자동으로 이어가게 하는 것이다. [단계별 진입점](../../../scripts/workflow/run.ts#L317), [잠금과 중복 처리](../../../scripts/workflow/run.ts#L407), [개발 실행과 검증 연결](../../../scripts/workflow/run.ts#L460), [재개와 완료](../../../scripts/workflow/work.ts#L509)

첫 적용은 재현 가능한 버그 한 건으로 충분하다. 접수에서 기대 동작과 재현 방법을 확정하고 이슈별 작업 공간을 배정한다. 수정 전에 재현 실패를 보존하고 같은 검사를 수정 뒤 실행한다. 그 결과로 관련 회귀 검사와 독립 감사를 이어가고, 통과 여부와 이유를 기존 원장에 기록한다. 보고서를 작성한 뒤 기존 `complete`가 현재 증거로 완료를 판정한다. [기존 검증 전이](../../../scripts/workflow/work.ts#L412), [보고서와 완료 경로](../../skills/REPORTS.md#자동-기록과-완료), [리만 가설 사례의 독립 검증](003-수학%20가설%20검증%20공개%20하네스.md#제출-증명을-판정하는-검증-시스템)

- 기능 검사 실패는 해당 기준, 후보 식별값, 실패 관측을 포함해 구현으로 돌려보낸다. 필수 감사의 수정 요구도 구체적 지적과 함께 전달한다.
- 실행 환경이나 모델 호스트 오류는 단계의 실패 이유를 기록하고, 재실행해도 안전하며 일시적일 때 그 단계만 재시도한다. 증거가 이미 기록된 단계는 현재 적용성이 맞으면 재사용한다.
- 같은 관측에서 새 진전이 없거나 실제 판단과 권한이 필요해지면 그 상태와 재개 조건을 사용자에게 보여준다. 재시도에서 기준이 약해지지 않도록 기준과 검증기 정책은 변경 후보 바깥에서 관리한다.

이 설계의 첫 확인 항목은 한 번 접수한 이슈가 검토 지적 뒤 수정으로 자동 복귀하는지, 단계 사이 강제 종료 뒤 중복 없이 재개하는지, 기준이나 후보가 바뀌면 예전 결과로 완료할 수 없는지다. 이를 기존 코드로 한 흐름에서 확인한 뒤 동시 이슈 수나 실행 환경을 늘리는 편이 도입 비용이 작다.
