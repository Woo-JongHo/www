JavaScript 전체 TypeScript 이관

직접 관리하던 mjs33개를 TS로 이관했다. 실행 경로와 타입·테스트를 정리했으며 검사 명령은 정상 종료했다. BoxBox의 병행 파일 수정으로 현재 소스에 대한 증거 확정과 Opus 재감사는 대기 중이다.

실행 도구·workflow core·테스트와 fixture가 mjs와 TS로 나뉘고 구현과 별도 d.mts 선언이 공존했다. 직접 관리하는 mjs는 TS로 통일했고 d.mts7개를 구현 타입으로 흡수했다. npm·CLI·앱 import·패키징·Rust fixture 경로를 연결했으며 현재 완료 판정은 보류했다.

보고서 자료 현재성 · 검사 유효성과 별개발행 시점 스냅샷

저장 당시 업무 상태차단 사항 남음

다음 행동 BoxBox 파일 수정 종료 후 같은 UUID의 verify 단계에서 다섯 검증 명령을 재실행한다.

남은 차단 사항 AC-1: source_changed; AC-2: verification_failed, source_changed; AC-3: source_changed; 문서 검토 후 소스 변경; review_not_passed; source_changed; receipt_context_mismatch

저장 당시 기준 중 3개가 실패·차단·미검증 또는 미확인으로 남았습니다.

기록된 변경

  • mjs33개를 TS로 이관하고 공용 작업·증거·실행·검토 타입을 정의했다.
  • allowJs/checkJs 예외와 JavaScript legacy 허용 항목을 제거했다.
  • Node 전용 테스트와 기존 Bun 테스트를 원래 실행기로 실행하고 test:comparison도 이를 재사용한다.
  • POSIX fixture의 원래 100755 모드를 복구하고 직접 실행 JSON-RPC 회귀 테스트를 추가했다.
  • 현행 구조·개발·Windows·작업 계약의 모듈 경로를 갱신했다.
일부 원본 항목이 이 보고서에 보관되지 않았습니다.

기준 근거 전체 34개 중 28개 표시 (6개 제외), 검사 이력 전체 25개 중 20개 표시 (5개 제외), 명령 인자 전체 50개 중 40개 표시 (10개 제외). 제외된 당시 기록 중 실패·차단·미확인 항목이 2건 있습니다. 더 넓은 기록은 근거의 작업 파일과 대조해야 합니다.

요구와 결과

구조화된 요구·결과 설명이 없어 저장된 수용 기준과 당시 상태를 그대로 보여 줍니다.

직접 관리하는 mjs 실행 소스·테스트·fixture가 TS로 이관되고 legacy JavaScript 허용 항목과 실행 참조가 제거된다.
미검증으로 기록
이관 소스가 strict 타입 검사를 통과하고 우회 지시문·any 도배·검사 완화 없이 기존 테스트가 통과한다.
미검증으로 기록
공식 CLI·Node fixture와 Electron 번들이 전환 경로로 동작하고 현행 구조·개발 문서가 일치한다.

기록에 남은 주요 선택

  • 생성물·vendor·과거 실행 근거는 변환하지 않고 직접 관리하는 소스를 이관했다.
  • Electron의 CommonJS 번들을 유지하고 scripts·test·비교 도구의 ESM 경계를 별도로 명시했다.
  • 첫 Opus 감사의 비교 명령·실행 비트 지적은 수정했지만 현재 소스의 재감사 PASS를 주장하지 않는다.
  • 사용자가 BoxBox 작업의 진행 중 상태를 확인했으므로 다른 변경을 되돌리지 않고 source_changed 증거를 보존했다.

무엇을 어떻게 확인했나요

당시 관측과 현재 적용성은 다릅니다. 발행 당시 기록입니다. 이 HTML 사본은 현재 파일 상태를 조회하지 않습니다.

구체적인 검증 대상·방법·기대·관측 설명이 기록되지 않았습니다. 명령이나 종료 코드만으로 사용자 행동을 확인했다고 추정하지 않습니다.

저장된 검사 이력의 당시 결과: 통과 16건, 실패 4건. 실제 프로세스 실행과 실제 모델·GUI·플랫폼 확인 범위는 각 검사 설명에서 구분합니다.

확인하지 못한 범위

  • BoxBox 병행 수정이 계속돼 최종 소스의 검증 증거와 재감사는 아직 확정하지 못했다.
  • 실제 Windows 데스크톱·원격 배포·패키지 앱 GUI의 새 실기는 수행하지 않았다.
  • 커밋·push는 수행하지 않았다.

남은 일과 해소 행동

  • BoxBox 파일 수정 종료 후 같은 UUID의 verify 단계에서 다섯 검증 명령을 재실행한다.
  • 현재 지문에 맞는 문서 영향 검토와 실제 Opus 재감사를 수행한다.
  • 저작 보고서를 갱신하고 적용 가능한 증거와 감사가 모두 충족할 때만 완료 처리한다.
