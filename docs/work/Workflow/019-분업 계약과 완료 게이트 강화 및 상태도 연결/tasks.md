작업 UUID는 `work-048bfa71-3960-4ad0-a8fe-e6217100d6df`다. [work.json](work.json)의 상태·기준·권한이 정본이다. 현재는 문서 작성만 허용됐으며 제품 구현·배포·커밋·push는 실행하지 않았다. 다음 직접 구현 요청이 오면 기존 UUID에 요청과 정확한 허용 경로·검증 명령을 연결한다.

## 공개와 후속 검증 계획

아래는 후속 인계이며 본 작업의 구현 요청만으로 자동 배포·공개하지 않는다.

| 단계 | 수행 전에 정할 것 | 확인할 결과 |
|---|---|---|
| Deploy | 설치 대상·산출물 식별·자료 보존·이전 버전 복구 경로 | 설치/시작 성공과 실제 빌드 확인 |
| Release | 내부 사용→제한 공개→안정 공개 범위와 중단 기준 | 노출된 기능과 실제 대상 일치 |
| Post-release | 관찰 기간·실패 지표·책임자·중단/복구 조건 | 세션·자료 보존·핵심 여정·회귀 확인 |
| Testing in production | 전용 작업·허용 조작·정리 범위·관측 방법 | 실제 설치 환경의 결과. 사용자 작업에 결함 주입하지 않음 |

후속 후보는 별도 범위로 판단한다. Runtime verification은 실제 사건 누락을 표시하는 읽기 전용 재생 실험부터, TLA+는 잠금·재시도·동시 완료의 순서 오류부터, Lean은 명확한 작은 판정 규칙부터 검토한다. 도구 이름 자체를 도입 성과로 삼지 않는다.
