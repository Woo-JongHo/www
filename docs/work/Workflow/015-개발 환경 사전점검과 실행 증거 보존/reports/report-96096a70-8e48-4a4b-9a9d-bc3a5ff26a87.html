개발 환경 사전점검과 실행 증거 보존

개발 환경 문제를 모델과 검증 실행 전에 식별하고, 큰 출력의 원문과 제한된 요약·종료·사용량을 구분해 보존하도록 환경 검증 경계를 구축했다. 고정 3be2942 코드에서 전체 1045개 검사와 실제 Electron GUI 213개 확인을 수행한 근거를 보존했다. 마지막 Terra 읽기 전용 검토가 통과했고 현재 검토·문서·기능 증거가 적용 가능한지 실제 ENV4 verifier로 확인하여 네 수용 기준을 모두 충족했다. liveRelease와 Root 게시 상태는 별도 범위다.

PATH를 덮어쓴 실행, Git 이력/index가 없는 검증 복사본, 저장소 루트 설치기 오염, 1MiB 출력 절단 때문에 실행 실패와 완료·사용량 증거 누락이 뒤늦게 드러났다. 환경 실패가 legacy eventId를 소비하거나 직접 Codex 호출이 원문 보존 없이 실행되는 누락도 독립 검토에서 발견됐다. 기본 검증 시작 전에 실행파일/PATH·필요 Git 기준·로컬 설정·출력·기존 소스 정책을 읽기 전용으로 확인한다. 선언된 verify 환경의 실패는 실제 verifier를 시작하지 않으며 일반 비Git 작업 계약은 유지한다. 직접 Codex는 안전한 명시 원문 경로 없이는 시작하지 않고, legacy 환경 실패는 eventId를 소비하지 않아 복구 후 한 번만 실행된다.

기록된 변경

  • 기본 doctor를 npm check 앞에 배선하고 루트 설치기 17JS를 기존 source-policy API로 탐지한다.
  • 모델 환경 overrides와 실제 verifier 상속 환경을 구분하고 실패·복구·중복 실행을 실제 프로세스 카운터로 확인했다.
  • Git 제외 출력과 명시 비Git 임시 출력에서 0600 원문 spool·bounded 요약·종료·usage를 보존하며 미등록 waiter는 거부하고 caller child를 종료하지 않는다.
  • 실제 Terra 검토와 현재 문서·기능 증거 적용성을 검사하는 ENV4 실제 receipt를 같은 UUID에 연결했다.
