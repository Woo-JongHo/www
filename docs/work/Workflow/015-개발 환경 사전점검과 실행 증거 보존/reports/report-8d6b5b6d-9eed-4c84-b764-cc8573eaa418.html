개발 환경 사전점검과 실행 증거 보존

환경 문제의 남은 두 원인을 보강해 npm check 전에 기본 진단과 기존 소스 정책을 실행하고, 선언된 verify 환경이 실패하면 실제 검증 프로세스 시작을 막는다. 루트 설치기 17JS와 verifier 카운터 회귀를 먼저 실패로 확인한 뒤 구현했다. 전체 검사에서 드러난 비Git 작업 계약 회귀는 최소 수정하고 영향 검사·Node 전체·빌드로 확인했으며, 전체 npm check가 최종 소스에서 exit 0이었다고 주장하지 않는다. 통합과 독립 검토를 기다린다. 같은 최종 소스의 실제 Electron 통합 확인도 205개 통과했고 관리 코드·설정 140파일의 전후 지문이 일치했다.

첫 구현은 명시한 설치 경로와 모델 시작 경계만 검사해 루트의 새 JavaScript 오염과 verify intent의 선언 환경을 자동 차단하지 못했고 환경 Node 테스트도 기본 실행기에서 잘못 분류됐다. 무인자 기본 doctor가 Git·설정·실행파일·출력·기존 소스 정책을 먼저 검사하고, environment를 선언한 verify가 실패하면 실제 verifier 카운터를 0으로 유지한다. 환경 선언이 없는 비Git 일반 검증과 모델용 env 계약은 보존한다.

기록된 변경

  • npm check 첫 단계 기본 doctor와 source-policy API 재사용으로 옵션 없는 루트 17JS 오염 탐지를 구현했다.
  • 선언 verify 환경의 실행 전 guard·실제 카운터 회귀와 Node 목록 등록을 구현했다.
  • 실제 host 후 inherited verifier 환경·일반 비Git 작업 계약·구조 단일 edge delta를 적용하고 따로 검증했다.
  • 같은 고정 후보의 실제 Electron DOM·IPC·stdio·합성 Native·재시작 흐름 205개를 확인하고 소스 지문 일치를 보존했다.

요구와 결과

구조화된 요구·결과 설명이 없어 저장된 수용 기준과 당시 상태를 그대로 보여 줍니다.

모델 실행 전에 상속 환경과 overrides를 병합하고 실행파일·PATH 문제를 구조화 진단하며 실패 시 호스트를 시작하지 않는다.

기록에 남은 주요 선택

  • build의 기존 소스·타입 오류 advisory 정책은 강화하지 않고 기본 검증 doctor 경계에 소스 정책을 연결했다.
  • 전체 검사 실패 원문을 보존한 뒤 변경 영향 회귀와 미실행 Node 전체·빌드로 합성 증거를 만들었고 같은 전체검사를 반복하지 않았다.

확인하지 못한 범위

  • 추가 typed 하네스는 BoxBox와 당시 미허용 의존성으로 false였다. 실제 host 이후 구조와 작은 계약 delta의 검사 근거는 분리했다.
  • npm check 1차는 Bun 850 통과/1 실패였고 수정 후 전체 npm check를 반복하지 않았다. 최종 근거는 영향 24개·Node 전체 177개·빌드·타입·소스·canonical 성공의 합성이다.
  • root off와 clone check 차이를 보존했다. 독립 Terra 검토·최종 문서 적용·업무 수용·목적별 게시를 저자가 승인하지 않는다.
  • Electron 통합의 Native는 합성 원장이며 실제 모델·Windows·실제 한국어 IME는 확인하지 않았다.

남은 일과 해소 행동

  • 통합 담당이 baseline SHA를 확인해 공유 patch와 구조 edge·canonical·문서 addendum을 적용한다.
  • 최신 root 소스의 증거와 독립 검토를 연결하고 같은 UUID의 현재 기준·보고서를 갱신한 뒤 목적별 commit·push를 수행한다.
