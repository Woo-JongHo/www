# 구현과 게시 작업

## 활동·대화·승인 경계

- `FIX-1`: Hook handler ID와 개별 실행을 구분하고, 대화 전환 중 도착한 live 사건을 유실하지 않는다. 재전송·늦은 사건·같은 초의 반복 실행을 구분하는 회귀 검사를 추가한다.
- Native 프로세스 재시작 뒤 저장된 대화를 실제로 복원한 후 다음 턴을 시작한다. 재연결 snapshot은 기존 사건을 교체하며 과거 사건의 강조를 재생하지 않는다.
- 승인 요청마다 신뢰된 로컬 token을 발급하고 main→preload→renderer→응답까지 연결한다. 재사용된 request ID에 과거 카드의 응답이 적용되지 않아야 한다. 불확실한 변경 명령은 자동 재시도하지 않는다.

## 공개 본문·구조도·공식 proof

- `FIX-2`: 공개 요약과 commentary가 교차하면 수신 순서대로 fragment를 표시한다. 완료 snapshot의 대체·빈 본문·32K 예산·종료 경계를 유지한다.
- 구조도 목록 실패는 UI 상태와 키 입력 드라이버를 분리해 재현한다. UI가 정상인 경우 잘못된 입력을 고치고 기존 assertion과 전체 시나리오를 보존한다.
- 기존 승인 DB와 규칙을 변경하지 않고 공식 BoxBox proof의 실제 실패 원인을 해결한다. 프로젝트 mode off와 작성 형식 통과를 혼동하지 않는다.

## 실제 검토와 기록의 내구성

- `FIX-3`: 이번 사용자의 명시 Terra 선택을 요청 근거에 연결한 CLI 전용 검토 경로로 처리한다. 기본 Opus 정책은 보존한다.
- 실제 app-server 요청·응답의 모델, 읽기 전용 sandbox, 최종 출력과 입력 식별을 검증한다. CLI stdout을 꾸며 영수증으로 만들지 않는다.
- 검증·검토 결과는 원장 lock을 얻기 전에 내구성 있게 보존하고, lock 충돌 후 결과만 재등록한다. 유료 실행을 재호출하거나 살아 있는 lock을 삭제하지 않는다.
