# 수정 경계와 통합 판단

## 고정 검토와 현재 수정본

이전 검토 사본의 입력을 유지하고, 현재 소스에서 소유 경로가 겹치지 않는 구현을 별도 사본으로 진행한다. 통합은 사본 생성 시 hash와 현재 원본을 대조한 뒤 수행한다. 과거 검토의 pass와 이번 수정 후 검증은 별도 시도다.

## 승인과 재연결

Native가 각 대기 승인에 로컬 `approvalToken`을 부여한다. token은 Native params에서 신뢰하지 않고 `AppEvent`의 별도 최상위 필드로 전달한다. renderer는 표시한 카드의 token을 응답에 포함하고 main은 현재 대기 항목의 token·연결·thread 경계를 대조한다. 같은 request ID를 나중에 다시 사용하는 정상 요청은 허용하고 과거 카드의 늦은 응답은 거부한다. token 없는 과거 승인은 다시 실행할 수 없다.

프로세스가 끊긴 뒤에는 실제 thread 복원을 마쳐야 다음 턴을 시작한다. 복원된 사건은 이전 EventLog를 교체하고 `conversation/reconnected`의 scoped snapshot으로 renderer에 알린다. snapshot 안에 알림 자신을 넣지 않는다. renderer는 snapshot과 새 live 사건을 병합하되 복원만으로 활동 반응이나 변경 요청을 재실행하지 않는다.

## 공개 본문

공개 summary·commentary·publicPlan은 도착 위치에 fragment를 추가하며 바로 인접한 같은 항목만 합친다. 항목 완료 snapshot은 해당 항목의 이전 fragment를 모두 치우고 수신 위치에서 대체한다. 항목별 예산·비공개 원문 차단·종료 뒤 delta 억제는 그대로 유지한다. 최종 답변의 기존 처리와 구분한다.

## 검토 수용과 기록 복구

이번 Terra 선택은 직접 사용자 요청에 연결한 예외다. 전역 정책의 기본 모델을 바꾸지 않으며 renderer 입력으로 예외를 만들 수 없게 한다. app-server transport의 실제 thread/start 모델·sandbox와 turn 최종 출력을 별도 영수증으로 검사한다. 다른 transport의 stdout 형식으로 위장하지 않는다.

비싼 실행 결과와 원장 반영을 분리한다. 결과를 먼저 내구성 있게 보존하고 원장 lock 충돌에서는 보존 결과의 등록만 재시도한다. 복구는 같은 결과를 중복 반영하지 않아야 하며, 검사 입력이 바뀌었으면 과거 결과로 현재 완료를 만들지 않는다.

## 실측에서 수정된 판단

구조도 목록의 첫 실패는 UI의 open 상태가 바뀌지 않은 상태였다. CDP Enter 입력에 실제 keypress를 생성하는 값을 포함한 비교 실행에서는 제품 변경 없이 전체 84개 시나리오가 통과했다. UI 결함 판정은 철회하고 입력 드라이버 수정 후 원래 assertion으로 공식 재검증한다. 진단 실행만으로 최종 수정본 통과를 선언하지 않는다.

Windows와 Mac mini의 기존 저장소는 현재 소스와 다른 HEAD이며 기존 변경도 존재한다. 기존 작업 트리에 동기화하지 않고 새 격리 대상을 사용한다. 자동 GUI·합성 입력·과거 사람의 한글 입력은 각각 증거 범위가 다르며 현재 사람의 IME 실측으로 대체하지 않는다.
