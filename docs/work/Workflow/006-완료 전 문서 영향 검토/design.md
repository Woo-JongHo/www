# 완료 전 문서 검토 설계

## 책임과 범위

문서의 의미 판단은 작성자가 수행하고 공유 core는 필수 범위·상대 Markdown 경로·이유·내용 지문의 적용성을 확인한다. 호스트 훅 설치는 이번 범위에 포함하지 않는다. 앱은 기존 공유 완료 API를 사용하므로 별도 renderer 권한이나 새 모델 호출 경로를 만들지 않는다.

## 적용성과 비용

문서 검토 이력은 append-only이며 schema1과 과거 완료 레코드의 읽기를 유지한다. schema2의 현재 완료 판단에는 유효한 문서 검토를 요구한다. 최종 감사 소스는 검사 입력과 검토 대상 문서의 합집합이다. 검사 시도는 원래 입력 범위를 유지하므로 무관한 보고·문서 수정이 제품 검사를 의례적으로 반복시키지 않는다. 문서 의미를 자동으로 고치거나 모든 정본을 강제 수정하지 않는다.

문구와 템플릿의 정해진 변경은 Luna에 위임했고 구조와 완료 판정은 Codex가 통합했다. 최종 감사는 기존 Opus 정책을 적용한다. 비용 절감량·모델 간 품질 우위는 측정하지 않았다.

## 검증 범위

집중 검사에서 누락·잘못된 경로·빈 이유·소스/기준/문서 변경과 이력 보존, 정상 완료, 재개를 확인한다. 타입 검사와 빌드를 각 1회 실행한다. GUI·Native·Windows 재검증은 제품 동작을 바꾸지 않아 이번 작업에서 반복하지 않는다.
