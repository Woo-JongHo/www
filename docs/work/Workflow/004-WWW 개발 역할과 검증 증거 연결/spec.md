# WWW 개발 역할과 검증 증거 연결

## 요청과 목적

사용자가 승인한 개발 프로세스 아키텍처를 실제 요청 접수·실행·검증·재개에 연결한다. 제품 전체 기준과 작업별 이력을 구분하고, 같은 행동·권한·문서·완료 규칙을 적용한다. 일반 요청의 의미 판단은 WWW 개발 역할이 맡고 실행 코드는 기록과 허용 조건을 확인한다.

사용자의 2026-11-12 후속 결정에 따라 검토는 Opus를 기본으로 하고, 확인된 Opus 토큰·사용량 소진에만 Terra를 사용한다. 인증·연결 오류나 검토 불합격을 대체 사유로 삼지 않는다. 저장소 정책과 앱에 배포하는 정책이 같은 구현으로 판정되도록 한다.

## 범위

- 포함: 제품·구조·Chat 최소 기준, 개발 역할과 공통 계약, 신규 작업 접수·UUID 재개, 권한 승계, 검증 입력·기준 지문과 실제 명령 결과, 현재 증거 적용성, Codex 호스트 연결, 실제 필요한 Chat 변경 파일럿, 독립 검토 정책과 앱 배포 연결.
- 제외: 전역 훅 설치, 자동 commit·push, 범용 에이전트 서버, 모든 제품 대화에 개발 감사 강제, 기존 작업 이력의 일괄 변환, 미래 서버·DB·원격 실행 구현.

## 수용 기준

정의·필수 여부·결과의 정본은 같은 폴더의 `work.json`이다. `AC-1`은 문서와 역할의 일관성, `AC-2`는 신규 접수·재개, `AC-3`은 증거 유효성, `AC-4`는 실제 Codex 역할 수용, `AC-5`는 Chat 파일럿, `AC-6`은 공유 검토 정책, `AC-7`은 현재 변경의 독립 검토를 다룬다.

## 결정과 열린 질문

- 사용자가 이전 대화에서 아키텍처와 구현을 명시 승인했다. 이 범위의 설계·구현·검증과 실패 수정은 반복 승인을 요구하지 않는다.
- 기존 `skills/www/`와 legacy 작업 기록은 유지한다. 신규 역할 접수에 엄격한 스키마를 적용하며 기존 기록을 현재 검증 증거로 자동 승격하지 않는다.
- 시작 시 Claude 인증 상태 조회는 로그인되지 않았다고 응답했으나 이후 실제 Opus 호출과 파일럿 검토는 통과했다. 인증 상태 조회만으로 실행 가능 여부를 단정하지 않으며, 인증 실패는 Terra 대체 사유가 아니다. 전체 변경의 최종 감사는 별도로 기록한다.
- BoxBox의 기존 JSON 작성 안내에는 승인된 열 규칙이 없고 source 검사에는 FIXABLE이 있다. 자동 정렬이나 수동 열 정렬로 우회하지 않으며 구문 검사와 가독성 판단을 구분한다.
