# 설계

## 기준선과 재사용

기존 `route.mjs`, `preflight.mjs`, `run.mjs`, `record.mjs`와 GJC 어댑터를 유지하고 WWW 개발 역할의 접수 경로를 추가한다. 기존 실행의 시작 전 변경 지문과 검증 시점의 입력 지문을 구분한다. 제품 Electron main/preload/renderer 경계는 유지한다.

## 경계와 데이터 흐름

1. 개발 역할이 직접 사용자 요청을 해석해 intent와 기존 작업 또는 신규 작업의 제목·기준을 제시한다. 키워드만으로 구현 권한을 만들지 않는다.
2. `work.mjs`가 신규 작업 UUID·폴더·최소 명세를 만들거나 같은 요청 ID/UUID를 재사용하고 유효한 권한과 기준 참조를 기록한다.
3. `route.mjs`가 역할의 선택과 권한을 검사한다. 기존 직접 스킬 호출은 그대로 지원한다. 단계 전환은 새 권한을 만들지 않는다.
4. Codex 어댑터가 역할·공통 계약·해당 스킬·작업 상태를 실제 호스트에 전달한다. 실제 로딩과 행동은 시험으로 확인한다.
5. `evidence.mjs`가 구현 후 관련 입력과 기준을 식별하고 실제 검증 명령을 실행한다. 완료와 재개 때 현재 내용과 대조한다. 과거 시도는 보존한다.
6. 검토 정책은 저장소 파일을 정본으로 두고 앱 배포물에 포함한다. 앱과 CLI가 같은 검토 core를 사용한다. Opus 인증 실패는 quota 소진으로 취급하지 않는다.
7. 완료는 canonical 작업의 필수 기준·현재 증거·필수 검토로 판정한다. 로컬 실행 프로세스 종료나 runtime 상태를 업무 완료와 혼동하지 않는다.

## 영향 파일

새 역할·기준 문서, 기존 스킬·템플릿·공통 계약, workflow 모듈과 테스트, 앱의 정책 배포·읽기 경로가 대상이다. 실제 Chat 파일럿은 별도 버그 작업으로 등록해 제품 소스와 회귀 검증을 추적한다.

## 위험과 검증 전략

- 신규 요청 중복·번호 충돌: 안정적 접수 ID, UUID·내용 확인, 배타적 파일 생성으로 검사한다.
- 오래된 PASS: 동일 HEAD의 내용 변경, 미추적 파일 추가·삭제, 기준 설명 변경, 검증 중 변경을 검사한다.
- 과도한 무효화: 관련 입력 밖의 보고 문구 변경은 검증 소스 지문에 포함하지 않는다.
- 역할 파일만 존재하는 가짜 연결: 실제 Codex 실행과 새 컨텍스트의 다음 행동을 확인한다.
- 검토 정책 우회: Opus 정상·quota·인증 실패·불합격, Terra 대체 근거와 소스·기준·정책 불일치를 검사한다.
- 기존 기능 회귀: 집중 workflow 검사 후 타입 검사·전체 테스트·빌드를 실행한다.

## 결정하지 않은 미래 범위

모든 호스트 자동 지원, 제품 전체 Chat의 자동 감사, 전역 훅, 공유 서버·DB와 분산 잠금은 포함하지 않는다.
