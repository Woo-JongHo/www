# 보고서 제목 파일명과 생성 관리 통합

## 요청과 목적

사용자는 기존 보고서의 사람이 읽는 제목 파일명 이전과, 이후 보고서를 일관되게 생성·관리하는 하네스·스킬을 요청했다. 이후 “같은 이름이면 여러 개 대신 한 파일에 내용을 합친다”는 요구를 추가했다. 같은 UUID에서 요구를 갱신하며 최초 266쌍의 파일명 이전은 이미 수행한 중간 결과로 보존한다.

## 범위와 선택

같은 작업 UUID와 NFC 제목을 한 묶음으로 관리한다. 묶음마다 JSON 1개와 독립 HTML 1개를 유지하고 신규 사건은 내부 entries에 누적한다. 파일명은 제목과 정규화·절단 충돌 방지용 제목 해시로 안정되게 정하며 생성 시각·종류·entry UUID마다 파일을 늘리지 않는다. 사용자가 “같은 작업 안에서 하나로 합치기 — 작업 UUID별로 이력을 보존”을 선택해 병합 경계를 확정했다.

기존 entry의 ID·서술·검증·semanticHash는 보존하고 모든 예전 UUID로 해당 기록을 읽는다. 병합 전 원본 JSON·HTML bytes는 별도 검증된 사본으로 보관한다. 앱 목록은 같은 작업·제목을 한 항목으로 모으고 최신 저작 기록을 먼저 보여 준다. 독립 HTML 안에서 같은 제목의 나머지 기록도 확인한다.

## 사용자 시나리오

- 같은 작업을 여러 번 검증·저작해도 reports 폴더의 같은 제목 파일 수가 늘지 않는다(AC-1).
- 과거 보고서 UUID로 해당 당시 내용을 읽고 같은 파일의 누적 이력을 확인한다(AC-2, AC-5).
- 관리자가 이전 계획과 백업·entry 의미 지문을 확인하고 적용한 뒤 잔여 이전 항목이 없는지 재실행한다(AC-2, AC-3).
- 동시 작성과 중단 뒤에도 정본 JSON의 entry가 유실되지 않으며 파생 HTML을 복구한다(AC-3).
- 에이전트가 보고서 스킬로 생성·누적·관리·실패 처리의 같은 정본과 공식 경로를 사용한다(AC-4).

## 오류와 보존

충돌·손상·누락 쌍·심볼릭 링크·상한 초과는 실패로 보고하고 기존 정본을 임의로 덮어쓰거나 축약하지 않는다. 병합은 내용의 의미를 보존하는 새 envelope 직렬화이며 과거 파일 bytes 불변과 구분한다. 과거 원문 백업과 초기 파일명 이전의 해시 증거를 유지한다. 당시 판정은 현재 검증으로 승격하지 않는다.

## 제외와 권한

별도 저장소 이전, 다른 작업 UUID의 같은 제목 통합, 기존 본문 재저작, 업무 완료 상태 변경, commit·push는 범위에서 제외한다. 관련 없는 dirty 변경을 보존한다. 수용 기준 정의와 유효한 변경·실행 범위는 work.json이 소유한다.
