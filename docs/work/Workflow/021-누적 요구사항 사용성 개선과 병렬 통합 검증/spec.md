# 누적 요구사항 사용성 개선과 병렬 통합 검증

## 요청과 목적

기존 UUID의 남은 작업을 실패·검증공백 우선으로 병렬 배분하고 명세와 실제사용자여정, 같은칸반의 계획·현재단계·근거를 연결해 통합검증한다. 개별요구와과거증거는기존원장을보존한다.

사용자의 직접 요청으로 접수했다. 요청 식별값은 work.json의 workflow.requestHash에 보존한다.

## 범위

변경 경로·표면·검증 명령과 커밋·게시 권한은 work.json의 workflow.authorization을 따른다. 범위 확대는 기존 권한으로 간주하지 않는다.

## 수용 기준

정의와 필수 여부의 정본은 work.json이다. 관련 기준: `SESSION-PLAN`, `SESSION-INTEGRATION`, `SESSION-USABILITY`, `SESSION-CLOSEOUT`.

## 결정과 열린 질문

작업 접수는 구현 완료가 아니다. 재개 시 같은 UUID와 현재 증거를 확인한다.


## 이번 요청의 구체 목표

사용자는 단순 상태 변경이 아니라 미완료 요구의 실제 구현·검증 완료를 요청했다. 다양한 유스케이스를 명세에 반영하고, 개발 전 Todo·계획을 읽기 쉽게 보여 주며, 기존 칸반에서 작업과 계획·검증 근거를 이어갈 수 있어야 한다. 모델은 난도와 위험에 맞춰 나누고 독립 단위는 병렬로 진행한다. pstack과 gajae-code 공식 원문의 검증·분해 패턴은 출처·고정 revision·라이선스를 확인한 뒤 참고한다.

개별 기능 기준은 원래 작업 UUID가 소유한다. 이 통합 작업은 작업 간 누락, 소유 충돌, 공통 검증과 최종 인계를 관리하며 기존 기준·과거 증거를 복제하거나 자동 통과시키지 않는다. 기존 작업의 요청 권한 변경이 필요한 경우 직접 사용자 요청을 연결하고 이전 원장 bytes를 해당 작업 history에 보존한다.

## 병렬 묶음과 의존

- 첫 묶음: 칸반 상세 reader/API/UI, Chat013 실제 완료 경계, 사용자 여정·칸반 인계 Skills, 오픈소스 조사와 독립 반박을 병렬 수행했다. 실제 집중 검사는 99개 통과이며 실제 GUI는 13개 관찰 뒤 Enter probe에서 실패해 후속 수정·재검증 대상으로 보존한다.
- 둘째 묶음: Home003/Chat014 UI와 입력 성능, Steer backend, Reports003, Workflow019를 파일별 단일 소유로 병렬 구현한다. 같은 generated snapshot은 root만 저작 동결 뒤 생성한다.
- 후속: 둘째 묶음 통합 소스에서 기존 작업의 오래된 증거를 재평가하고 집중·실제 GUI·Native·플랫폼별 누락을 채운다. 미구현 Chat015 등은 단순 문구 변경과 실제 단계 사건 연결을 구별하여 다음 독립 단위로 처리한다.

저작 중 다른 빌드가 dist를 바꾸지 않게 하고 검사 시 실제 입력 내용과 기준 정의를 식별한다. 필수 독립 감사·실제 OS/모델 검사가 실행되지 않으면 그 사유와 다음 행동을 남긴다. 커밋·푸시·배포는 이번 요청에 포함되지 않는다.


## 외부 RPA 범위 확인

사용자는 RPA 대상이 `ssh chacada`에 있다고 알려 주고 현재 작업에 필요한 이유를 확인했다. 이번 통합은 WWW 앱과 공통 개발 기능의 사용성·구현·검증에 집중한다. RPA001의 외부 두 프로젝트 시범 적용·운영 수락은 WWW 로컬 기능의 선행 조건으로 두지 않으며 기존 RPA UUID의 별도 미완료 범위로 보존한다. 이번 확인으로 SSH 접속·외부 코드 변경·운영 실행을 수행하지 않았다.
