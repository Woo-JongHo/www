# 구현·검증 단위

## T1 — 정책과 스킬 연결 (MODEL-PLAN)

Sol/root가 MODEL_POLICY 정본과 스킬 참조를 수정한다. 실제 내부 모델 분담과 단일 모델 종료·실패 원인에 따른 상향을 구분한다. 독립 패스에서 읽고 실제 실행 근거와 비교한다.

## T2 — 배분 검증과 실행 (MODEL-RUN)

Terra는 model-allocation 순수 검증·행동 테스트, Sol은 run 통합과 기존 개발 실행 회귀를 소유한다. 승인 범위·모델 수준·선택 이유·이전 시도·dependencies·usage 누락을 검증한다. root는 typed wrapper의 실제/주입 출처를 연결한다.

## T3 — 통합 검증과 독립 감사 (MODEL-VERIFY)

타입·소스·집중 회귀·빌드를 실제 실행하고 원문을 보존한다. 공식 하네스의 전후 검사와 실제 모델 호출을 구분한다. Sonnet 독립 리뷰와 Opus 최종 감사 결과를 회수하고 사용 불가면 blocker를 남긴다. 변경 파일에서 자리표시·skip/only와 우회 주석을 직접 검사한다.

## 제품 작업과의 연결

Chat012의 스크롤·초기 준비 계측·명령 출력 전환, Chat013의 Agent·Plan·Progress에 이 분담을 적용한다. Home002는 기존 작업 기록을 읽는 보드와 탐색을 같은 실행 정책으로 이어간다. 제품 기준·검증은 각 UUID를 유지하며 이 하네스 작업의 검사 통과로 제품 전체를 완료 처리하지 않는다.
