# 작업 내부 모델 배분 설계

## 책임과 데이터 흐름

기존 www-dev 실행에 선택적인 allocation을 전달한다. Sol은 작업 기준과 공통 계약을 소유하고 단위별 kind/risk/reason을 정한다. 순수 검증 모듈은 위험에 비해 낮은 모델·승인 밖 입력/쓰기·잘못된 시도 연결을 거부한다. run.ts는 검증된 model을 실제 Codex 호출에 연결하고 status 사건·시도 영수증에 요청/관측·사용량·실패를 보존한다. 단위 권한은 기존 작업 권한의 부분집합이며 격리의 OS 강제 보장은 아니다.

기존 역할 실행과 독립 검토 경로는 유지한다. allocation 없는 호출의 동작은 보존하고 정보·verify·review·complete·legacy 실행에 allocation을 넣으면 무시하지 않고 거부한다. 지원하지 않는 thinking은 명시 거부한다.

## 파일과 검증

- MODEL-PLAN: MODEL_POLICY.md를 정본으로 www-design/www-build에서 참조한다. 요청 모델과 관측값의 구분, 단일 모델 종료·상향 이유·파일 소유를 기록한다.
- MODEL-RUN: model-allocation.ts와 run.ts가 검증·실행·receipt를 연결한다. 실제 이전 시도와 의존 성공 영수증을 확인한다. 성공 인계에는 가짜 실패 원인을 요구하지 않는다.
- MODEL-VERIFY: 순수 검증·개발 행동·Codex/기존 하네스 회귀와 타입·소스·빌드를 실행한다. 실제 모델은 협업 도구와 Codex CLI를 별개로 확인한다. 영수증의 injected는 process로 승격하지 않는다.

## 실제 이번 분담

Luna가 실행 필드를 수집했다. Sol이 하네스 통합을 소유하고 Terra가 순수 검증 모듈과 행동 검사를 구현했다. 별도 Sol이 Chat013 계약·통합을 맡고 Terra가 Agent 투영을 구현했다. Terra는 명령 출력 전환과 실제 Electron QA 시나리오를 맡았다. root는 공유 파일·문서·전체 통합을 소유한다. 협업 도구 요청 ID와 전문은 .www/session-implementation에 보존하며 관측 모델 별도 미제공을 유지한다.

## 경계와 실패

과거 스킬 문서는 모든 작업의 주 모델을 Sol로 두었으나 이번 결정으로 내부 단위를 나눈다. 최종 감사는 사용자 지침에 따라 Opus 고정이며 과거 quota fallback으로 대체하지 않는다. 자동 제품 라우터와 개발 하네스의 단위 배분은 별개다. 토큰 합계는 동일 의미의 제공 필드와 누락 범위를 기록하며 모든 비용 절감이 입증됐다고 쓰지 않는다.

공식 저작의 최초 두 접속은 workId와 legacy verifier 누락으로 호스트가 실행되지 않았다. 세 번째는 실제 전후 검사를 수행하고 협업 결과를 주입하는 외부 bridge로 열었다. 하네스 준비 전 작성된 순수 모듈·명령 출력은 기존 baseline으로 구분한다. 처음 선언하지 못한 후속 파일은 누락을 숨기지 않고 다음 계획에 명시한다.
