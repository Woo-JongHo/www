## 단위 3 — 독립 적용과 완료 판단

- 소유: 통합 담당이 저작자와 다른 독립 패스에 최소 요청·대상 스킬·원시 자료를 제공한다. 평가자가 사용할 답이나 기존 결론을 주입하지 않는다.
- 관련 여정·기준: UC-1~3, 모든 기준.
- 의존성: 단위 1~2의 동결된 저작 결과.
- 확인: 계획 요청과 기존 UUID 재개, 실제 호출/결과 관측이 필요한 흐름, 작은 수정과 GUI 미실행 상황에서 생성된 산출물·판정을 검사한다.
- 실행 근거·남은 일: 초기 모의 분석과 A/B 수동 fixture, C2 주입·설정 실패, C3 개발 안내 누락, C4 실제 CLI 한 줄 변경을 각각 보존한다. 최종 Opus는 A/B의 원장·계획 불일치를 실험자가 사후 교정하고 여정 행을 보강한 결과를 스킬 행동 통과로 사용한 점을 불합격으로 판정했다. 원래 결과는 실패 관측으로 남기며, 그 뒤 파일 정합만으로 기준을 통과시키지 않는다. 수정된 정본으로 새 독립 에이전트가 최소 요청·원시 자료에서 명세·설계·구현·검증까지 직접 산출하게 하고, 사후 보강 전 결과와 원장/계획 인계를 검사한다. 현재 소스의 형식·링크·OSS 근거 검사도 실제 시도에 연결한 뒤 필수 Opus 재감사를 진행한다. 제품 GUI·호스트 의미 수용의 통과는 주장하지 않는다.

## 직접 영향받는 후속 변경

작업 원장과 INDEX의 상태/문서 연결은 통합 담당에게 인계한다. 이번 저작에서 실제 자동 보드 기능이나 제품 API를 수정하지 않았다.
