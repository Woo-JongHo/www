

## 작업 원장과 보고서 입력 한도 공유

관찰: 정식 검증 이력이 늘어난 구조 ID 작업의 work.json은 1,096,189바이트였다. 공식 보고서 발행은 “보고서 대상 작업 UUID가 없거나 중복돼 있습니다.”로 실패했다. 실제 UUID와 파일은 유일하게 존재했다. 원문은 로컬 phase14-preaudit.stderr에 보존했다.

코드 근거: scripts/workflow/reports.ts의 workLocations는 작업 원장을 공통 readJson으로 읽는다. readJson의 기본 1MiB 제한에 걸린 원장은 warnings로만 누적되고 works 목록에서 빠진다. locateWork의 matches가 0이 되어 위 오류가 발생했다.

수정 범위: 보고서 JSON은 기존 1MiB, 작업 원장 입력은 별도 8MiB 상한으로 분리한다. 정규 파일·심볼릭 링크 거부·파싱·보고서 최종 크기 검사를 유지한다. 이력과 기존 보고서는 보존한다. 실제 큰 유효 원장의 생성·발행·읽기와 상한 거부를 격리 회귀 검사로 확인한 뒤 공식 원장에 보고서를 다시 발행한다. 구현·검증 결과는 후속 시도에 기록한다.
