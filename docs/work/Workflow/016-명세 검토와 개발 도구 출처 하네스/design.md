# 명세 검토와 개발 도구 출처 하네스 설계

## 책임과 범위

기존 공식 진입점에 `artifact-context`, `artifact-review`, `artifact-status`, `tool-inventory`를 연결한다. 의미 검토는 에이전트가 체크 항목별 근거와 판단을 제출하고, 코드는 입력 형식·문서 위치·기준 연결·현재성을 확인한다. 정규식으로 문서 의미를 판정하거나 검토 기록을 테스트 통과로 승격하지 않는다.

## 데이터와 실패

- 검토 준비는 작업의 spec/design/tasks 및 수용 기준을 식별한다. 아직 없는 설계·작업 파일도 지문에 포함해 후속 생성 시 기존 판단을 오래된 것으로 표시한다.
- 검토 제출은 준비 때 받은 digest와 현재 digest가 같을 때만 허용한다. 체크 결과·근거·기준별 작업 위치를 work.json의 선택 필드 artifactReviews에 추가한다. 기존 schema1·schema2 기록은 보존한다.
- 문서·기준 변경 후 status는 stale을 보고한다. 명세 품질과 정합성은 별도 이력이다. 검토 미실행·지적·현재 검토를 구분하고 업무 완료 판정과 독립 감사를 대체하지 않는다.
- 도구 조회는 정본 경로·SHA256·발견 링크의 일치 여부를 표시한다. 컨텍스트에 실제 넣은 파일만 제공됨으로 기록하며 호스트의 의미상 수용은 미확인으로 둔다.
- 저장은 기존 작업 잠금·원자 저장을 재사용한다. 경로 탈출·외부 심볼릭 링크·잘못된 참조·오래된 제출은 거부한다.

## 검증

AC-1은 실제 임시 저장소의 기록·상태·문서/기준 변경·잘못된 위치 제출로 확인한다. AC-2는 실제 정본·정상 및 낡은 발견 링크·외부 경로로 확인한다. AC-3은 공식 CLI와 개발 컨텍스트 제공을 확인하고 기존 하네스 회귀·strict 타입·빌드·독립 검토를 수행한다. 모델 실제 수용은 실행 근거가 없으면 미확인이다.
