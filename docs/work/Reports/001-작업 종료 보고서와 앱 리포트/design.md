# 작업 보고서 설계

## 목적과 화면

오류 전용 보고서가 아니라 Codex가 작업을 마칠 때 남기는 저작 보고서를 앱에서 읽는다. 사용자 요청의 수정 사항을 반영해 성공·부분 완료·실패·감사 대기를 모두 다룬다. HTML 오류 보고서의 밝은 종이, 여백, 큰 제목, 전후 비교와 근거 추적 방식을 재사용하고 오류 원인 분석을 모든 작업에 강요하지 않는다.

앱 사이드바의 리포트를 누르면 작업별 저작 보고서 목록과 독립 HTML 읽기 화면을 연다. 자동 기록은 별도 탭으로 구분한다. 현재 Native 대화 폴더와 별도로 보고서를 읽을 프로젝트를 선택할 수 있다. 대화 DOM은 유지해 초안·선택·펼침·읽기 위치를 보존한다.

## 데이터와 경계

보고서는 작업 폴더의 reports/report-UUID.json과 같은 이름의 HTML로 보존한다. JSON은 저자의 summary, before, after, changes, decisions, limitations, next와 당시 work 상태·검증·검토 근거의 사본이다. HTML은 같은 JSON의 안전한 파생 보기다. 기존 work.json은 상태와 기준의 정본을 유지한다. 보고서의 완료 표시는 저장 시 work.status가 done일 때만 사용한다.

보고서 ID만 제한된 IPC로 전달한다. main은 선택한 저장소 내부에서 보고서를 읽고 renderer는 scripts·network·top-navigation 권한이 없는 sandbox iframe에 HTML을 표시한다. HTML에는 외부 의존성과 사용자 작성 JavaScript가 없으며 서술은 escape한다. 내보내기 경로는 main의 저장 대화상자가 소유한다. 손상된 기록 하나는 목록 경고로 격리하고 선택한 손상 기록은 오류로 표시한다.

## 저작과 수명주기 훅

기계는 work 기록의 사실을 투영해 자동 기록을 생성한다. 무엇을 왜 선택했는지는 저자가 report action으로 직접 작성한다. 자동 기록으로 저작 완료를 꾸미지 않는다.

검증 종료 → verification 훅, 독립 검토 기록 → review 훅, 호스트 정상 종료·실패 → 하네스 훅, 승인된 업무 완료 → complete 훅을 연결한다. 핵심 기록을 먼저 저장하고 보고서 실패는 reportHook.status로 별도 반환한다. 보고서 실패 때문에 이미 실행한 변경을 자동 재실행하지 않는다. 새 작업은 reportingRequired를 갖고 현행 소스·기준·작업 기록에 일치하는 저작 보고서가 없으면 완료할 수 없다. 완료 훅은 기존 저작 서술을 보존하면서 done 상태의 새 보고서 이력을 만든다.

전역 Codex Stop 훅을 설치했다고 주장하지 않는다. 보장 범위는 WWW 공유 core와 개발 하네스의 실제 호출 경로다. 독립 Codex 세션은 개발 역할 지침이 저작을 요구한다. SIGKILL·전원 종료처럼 종료 콜백이 실행되지 않는 상황은 재개 후 report-snapshot으로 사실 기록을 복구한다. 사실 스냅샷을 LLM 저작으로 설명하지 않는다.

## 검증

AC-1/2: 실제 renderer·IPC·파일 경계에서 저작 보고서와 자동 기록을 읽고 HTML을 독립적으로 표시한다. 빈 프로젝트·손상 기록·현재성 변경·프로젝트 전환·내보내기 취소와 오류를 다룬다.

AC-3/4: 실제 임시 저장소와 하네스 fixture로 훅이 파일을 만들고 UI 서비스가 읽는지, 반복 event가 중복을 만들지 않는지, 쓰기 실패가 검사 결과와 구분되는지, 미실행 검토와 오래된 보고서로 완료하지 않는지 확인한다.

AC-5: 집중 보안·행동 검사와 타입·번들, Electron 합성 Native 통합 시나리오, 360px HTML·키보드·모션 축소·인쇄를 확인한다. 실제 모델 검토는 별도 정책에 따라 실행하고 미실행이면 사실대로 기록한다.

## Native 종료 뒤 LLM 판단

최신 요청에 따라 공개 답변과 종료 사건을 모은 뒤 별도 읽기 전용 subprocess가 needed/reason/title/narrative를 반환한다. 짧은 응답은 작업을 만들지 않고 생략 이유만 보존한다. 필요한 응답은 종료 당시 프로젝트의 Native 작업 폴더와 보고서로 저장한다. 실제 검사 근거가 없으면 기준은 미검증이다. 원래 대화를 기다리게 하지 않으며 제한된 큐·입력·재시도 메모리와 멱등 키를 둔다. 실패·재시작 중단·저장 성공을 구분한다. 도구 시도는 실패 처리하되 호스트 내장 도구를 모두 강제로 비활성화했다고 표현하지 않는다.

AC-6은 실제 모델의 짧은 인사 생략과 합성 공개 설계 답변의 필요 판단·저장, 별도 subprocess의 프로토콜·취소 검사와 실제 Electron의 합성 Native 자동 경로로 검증한다. 합성 답변은 실제 구현한 작업으로 포장하지 않는다.
