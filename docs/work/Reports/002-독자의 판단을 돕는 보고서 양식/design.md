# 독자의 판단을 돕는 보고서 설계

## 독자와 목적

사용자가 요청과 결과의 연결, 선택의 타당성, 검증 신뢰도와 다음 행동을 판단하도록 한다. 상단의 작업 이야기는 왜 시작했는지에서 무엇이 달라졌고 어디까지 확인했는지로 자연스럽게 이어진다. 현재 결론·완료 차단·영향과 다음 행동을 앞에서 읽고 근거로 내려간다.

## 계약과 호환

ReportNarrative에 선택적인 reader를 추가한다. reader는 story, requirements, checks, decisions, references, nextActions로 구성한다. story는 3~5문장의 저자 설명이며 검사 상태 원장을 덮지 않는다. 요구와 결과를 대응하고 검사 대상·방법·기대·관측·미확인 범위를 서술한다. 정보가 없으면 null 또는 빈 배열을 쓰고 보고서에서는 미기록으로 표시한다. 모든 판단 과정·대안 개수·인용구를 강제하지 않는다. 실제 주요 결정만 문제·근거·실제 대안·선택·감수한 불리함으로 설명한다. 다음 행동에는 확인된 담당자와 관찰 가능한 해소 조건·영향을 남기고 담당자를 추측하지 않는다.

기존 필드는 유지한다. 옛 JSON·HTML을 덮어쓰지 않으며 새 읽기 렌더러가 기존 저작 문장을 재배치한다. AC나 exit0만으로 사용자 행동과 테스트 시나리오를 추정하지 않는다. 신규 수동 CLI·완료 이력과 Native 판단·큐·저장 전 경로에서 reader를 보존한다. Native는 공개 입력에 없는 시나리오·문서·결과를 발명하지 않는다.

## 상태와 상세

당시 검사 결과, 보고서 대상의 현재성, 독립 검토 실행, 저장 시점 업무 완료를 구분한다. 과거 evidence.summary의 현재 적용 가능은 기록 당시 원문으로 상세에만 보존하며 현행 유효 판정으로 재사용하지 않는다. 보고서 source가 현재와 같다는 사실도 각 검사 시도의 환경까지 현행 유효하다는 뜻이 아니다. 상태 지문의 실제 의미와 확인 불가 범위를 독자에게 설명한다.

해시·UUID·명령 전문·실행 환경·모든 검토 이력은 details 상세에 둔다. 본문은 요구–결과와 구체적 검사·한계·중요 결정 중심이다. 실제 생략된 자료가 있을 때만 전체/표시 개수와 생략을 알리고 실패·차단·미확인의 존재를 숨기지 않는다. 근거는 무엇을 확인하기 위해 여는 자료인지 이름과 목적을 표시한다. HTML은 escape/CSP·sandbox·오프라인·360px·인쇄 경계를 유지한다.

## 검증

집중 검사로 구형/신형 보존, 악성 서술 escape, null/미기록, 당시/현행 충돌, 메타데이터 접힘, 조건부 선택·실제 생략을 확인한다. 실제 Electron에서는 새 이야기 본문이 iframe 안에 보이는지 DOM과 box model로 확인하고 초안 보존·360px·모션 축소·PDF를 유지한다. 실제 모델 표본에서 reader가 생성되어 저장되는지 별도 확인하되 전체 판단 품질을 보장하지 않는다. 최종 독립 검토는 공유 정책의 Opus 읽기 전용 실행을 따른다.
