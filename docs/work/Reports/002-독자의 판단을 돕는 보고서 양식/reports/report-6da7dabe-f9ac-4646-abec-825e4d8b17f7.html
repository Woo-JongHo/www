독자의 판단을 돕는 보고서 양식

보고서 첫 화면에서 작업 이야기를 읽고, 요구와 결과·확인 범위·남은 행동을 구분해 판단하도록 양식을 바꿨습니다.

기존 보고서는 작업의 흔적을 잘 남겼지만, 무엇을 원했고 결과를 어디까지 믿을 수 있는지 읽는 사람이 직접 연결해야 했습니다. 그래서 제목과 요약 다음에 작업 이야기를 먼저 두고, 요구와 결과·검사 방법·남은 행동으로 이어지도록 바꿨습니다. 과거 통과 기록은 보존하면서 현재 적용성·독립 검토·업무 상태를 분리했고, 기록에 없던 설명은 새로 만들어 넣지 않았습니다. 실제 앱과 새 자동 보고서 경로를 확인했으며, 작성 형식 검사에 남은 지적은 별도로 정리해야 합니다.

다음 행동 남은 BoxBox 작성 형식 지적의 처리 범위를 정리합니다.

남은 차단 사항 새 양식의 읽기·저장·실제 앱·실제 모델 검사와 독립 검토는 통과했습니다. BoxBox 작성 형식 검사는 미해결이므로 정식 완료 판정은 보류합니다.

요구와 결과

아래는 작성자의 요구·결과 설명입니다. 연결 근거의 서술은 별도의 검사 판정을 새로 부여하지 않습니다.

상단에서 작업의 흐름을 글로 읽기

제목·요약 다음에 이야기 본문을 배치하고 상태와 다음 행동을 같은 상단 영역에 정리했습니다.

근거 실제 앱의 iframe 본문이 저장된 문장과 같고 첫 화면 상단에 배치되는지 비교했습니다.

화면 연결 검사는 합성 보고서 자료를 사용했습니다.

요구와 결과 및 검증 내용을 판단하기

요구별 결과·근거·한계와 검사 대상·방법·기대·관측을 따로 기록합니다.

근거 수동 저작·완료 이력·Native 판단과 큐를 거쳐 상세 서술이 보존되는지 검사했습니다.

저자 설명 자체가 새로운 검사 판정을 부여하지는 않습니다.

과거 통과와 현재 확인을 구분하기

당시 검사, 자료 현재성, 독립 검토, 업무 상태를 분리했습니다. 예전 현재 적용 가능 문구는 원시 상세에만 남깁니다.

근거 구형 보고서의 본문과 원시 상세를 나눠 문구 위치와 원본 보존을 확인했습니다.

개별 검사의 현행 실행 환경까지 이 보기에서 다시 검사하지 않습니다.

중요한 선택만 근거와 함께 읽기

실제로 작성한 주요 결정이 있을 때만 선택 영역을 보여 주며 대안 개수나 인용문을 강제하지 않습니다.

근거 빈 선택 목록과 실제 선택 목록, 미기록 필드의 출력 경계를 검사했습니다.

당시 기록이 없으면 과거 선택의 상세 근거를 발명하지 않습니다.

필요한 근거를 부담 없이 확인하기

긴 식별자·명령·검토 전문은 접을 수 있는 상세로 내렸고 관련 자료에는 확인 목적을 붙였습니다.

근거 기본 본문과 인쇄에서 원시 전문이 빠지고 필요한 설명이 남는지 확인했습니다.

자료가 실제 생략된 경우에는 생략 사실과 숨겨진 미확인 항목의 존재를 표시합니다.

중요한 선택과 그 이유

작업 이야기를 상태 카드보다 먼저 읽게 할지

선택 제목과 요약 바로 뒤로 이야기를 옮겼습니다.

판단 근거 첫 캡처에서는 상태 카드·차단 안내 뒤에 이야기 영역이 밀려 있었습니다.

함께 검토한 대안

  • 초기 시안처럼 상태 카드 뒤에 이야기를 두기

감수한 점 상세 상태표보다 짧은 작업 설명을 먼저 읽는 순서가 됩니다.

옛 보고서에 부족한 설명을 어떻게 다룰지

선택 저장 문장은 재배치하고 없는 설명은 미기록으로 표시했습니다.

판단 근거 기존 자료에는 구체적인 검사 시나리오와 구조화된 요구별 결과가 없는 경우가 있었습니다.

감수한 점 이전 내용이 저절로 풍부해지지는 않지만 기록에 없는 사실을 추가하지 않습니다.

불안정한 GUI 검증을 어떻게 다시 확인할지

선택 전체 검사 빌드가 끝난 뒤 GUI 검사를 단독 실행했습니다.

판단 근거 첫 실행에서 빈 창과 시간 초과가 관찰됐고 검사 중 다른 소스 변경도 감지됐습니다.

함께 검토한 대안

  • 빌드 출력을 공유하는 두 검사를 동시에 실행한 초기 방식

감수한 점 검증 순서가 길어지지만 공유 출력의 실행 시점을 분리합니다. 빈 창의 원인을 단정하지는 않습니다.

무엇을 어떻게 확인했나요

당시 관측과 현재 적용성은 다릅니다. 발행 당시 기록입니다. 이 HTML 사본은 현재 파일 상태를 조회하지 않습니다.

검증 설명은 작성자가 기록한 내용이며, 아래 저장 당시 검사·검토 판정과 별개입니다.

실제 앱에서의 이야기 표시와 화면 전환

확인 방법
저장소 fixture와 실제 Electron·합성 Native subprocess를 연결하고 iframe의 실제 본문·표시 위치와 대화 왕복 상태를 비교했습니다.
기대 결과
저장된 이야기와 화면 문장이 같고 첫 화면에 보이며 대화 초안·선택·읽기 위치가 유지됨
실제 관측
이야기 문장·양수 표시 높이·상단 위치 및 기존 화면 왕복 시나리오를 확인했습니다.

실제 사용자 업무의 수용이나 모든 플랫폼의 동작을 확인한 것은 아닙니다.

보고서의 보존과 자동 저작

확인 방법
파서·저장·읽기·완료 이력·별도 판단 subprocess·큐를 검사하고 실제 LLM에 인사와 설계의 합성 공개 답변을 전달했습니다.
기대 결과
옛 자료는 그대로 남고 새 상세 서술은 끝까지 보존되며 인사는 생략되고 설계는 저장됨
실제 관측
구형 원본 보존과 새 서술 왕복, 실제 모델의 생략·생성과 저장을 확인했습니다.
확인 범위와 한계
두 모델 표본은 일반적인 판단 품질을 보장하지 않습니다.

좁은 화면과 인쇄

확인 방법
좁은 창의 가로 넘침·필수 제목·모션 축소를 관찰하고 PDF의 본문 추출과 페이지 렌더를 확인했습니다.
기대 결과
필수 설명을 읽을 수 있고 원시 JSON 전문이 기본 인쇄를 압도하지 않음
실제 관측
좁은 화면의 가로 넘침이 없고 인쇄 본문에 요구·검사 설명이 남으며 원시 상세는 빠지는 것을 확인했습니다.
확인 범위와 한계
모든 프린터와 플랫폼의 인쇄 결과를 인증하지는 않았습니다.

확인하지 못한 범위

  • 작성 형식 검사는 미해결입니다. 기능 검사 통과와 정식 업무 완료를 같은 상태로 쓰지 않습니다.
  • 옛 보고서에 없던 구체적인 시나리오와 대안 비교는 이 양식만으로 복구되지 않습니다.
  • 보고서 자료가 같은지 비교하는 기능은 개별 검사와 실행 환경의 현행 적용성을 자동 재판정하지 않습니다.
  • 실제 모델 검사는 두 합성 공개 입력의 생략·생성과 새 서술 저장을 확인한 표본입니다.
