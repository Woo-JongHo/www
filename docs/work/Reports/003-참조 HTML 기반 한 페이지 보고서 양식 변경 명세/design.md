# 보고서 문서 양식 설계

## 책임과 여정

보고서 목록에서 항목을 선택하면 기존 읽기 서비스가 선택 entry와 저장 이력을 `report-view.ts`에 전달한다. 같은 렌더러가 앱 iframe의 읽기 시점 현재성과 독립 HTML의 저장 당시 상태를 각기 표시한다. 렌더러는 기존 JSON·UUID·semanticHash·이력을 변환하거나 다시 저장하지 않는다. 사용자는 번호 목차로 여섯 절에 이동하고 상세를 펼쳐 당시 근거를 읽는다. 앱의 sandbox, CSP와 escape를 유지한다.

## 매핑과 판단

- AC-1: 결론과 상태, 문제와 접근, 변경 결과, 검증과 한계, 남은 일과 완료 조건, 변경 이력과 상세 근거 순서다. 내부 앵커와 details는 스크립트가 필요 없다.
- AC-2: 저장 당시 업무·검사·독립 검토, 읽기 시점 자료 적용성, 차단과 미검증을 구분한다. 검토 모델이나 성공을 추정하지 않는다.
- AC-3: narrative의 before/after·changes와 reader의 requirements/decisions/checks/nextActions를 표시한다. reader의 행동과 기존 narrative.next는 서로 별도의 출처로 모두 보존하며 누락 정보는 미기록이라 표시한다. 완료 기록에 별도 행동이 없으면 기록된 남은 일이 없다고 한정한다. 차단된 기록은 해소 행동이 미기록이라고 표시한다.
- AC-4: 이력은 실제 entry의 시각·요약과 해당 entry의 당시 본문·원시 상세를 유지한다. 원문 경로 및 기준·소스 지문도 상세에 남긴다.
- AC-5: 790px에서 목차를 상단으로, 540px에서 결과 표를 세로로 배치하고 밝음/어두움, 포커스, 축소 모션과 인쇄를 위한 스타일을 제공한다. 선택 위치 추적 스크립트를 두지 않으므로 `aria-current`를 허위로 고정하지 않는다.
- AC-6: 저장 파일과 앱의 렌더링은 동일 함수를 사용한다. 앱은 읽기 시점 비교를 추가하고 파일은 현재 상태를 조회하지 않음을 표시한다.
- AC-7: 선택 entry와 이전 entry의 의미 보존, escape, 상태·앵커·legacy·완료/차단 반례를 집중 테스트한다. 실제 브라우저·Electron·키보드·대비·인쇄 관찰은 별도 검증이다.

인쇄에는 필수 본문과 사용자가 펼친 과거 이력 본문을 남기고 목차, 접힌 과거 이력과 원시 상세는 제외한다. 출력물에 제외 안내를 표시하고 전체 근거는 오프라인 HTML에서 확인한다. 과거 보고서 JSON과 저장 HTML의 일괄 재생성은 하지 않는다.
