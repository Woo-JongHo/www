# 번호별 최종 답변과 대화 가독성

## 요청과 목적

번호별 최종 답변과 대화 가독성

사용자의 직접 요청으로 접수했다. 요청 식별값은 work.json의 workflow.requestHash에 보존한다.

## 범위

변경 경로·표면·검증 명령과 커밋·게시 권한은 work.json의 workflow.authorization을 따른다. 범위 확대는 기존 권한으로 간주하지 않는다.

## 수용 기준

정의와 필수 여부의 정본은 work.json이다. 관련 기준: `FINAL-POLICY`, `FINAL-SESSION`, `FINAL-READ`, `FINAL-LIVE`.

## 결정과 열린 질문

작업 접수는 구현 완료가 아니다. 재개 시 같은 UUID와 현재 증거를 확인한다.

## 사용자 확인과 범위

사용자는 보고서에 만족하며 대화 마지막의 번호별 의미 구성과 요약을 원했다. 설계 설명 후 구현을 승인했고, WWW가 UI를 자유롭게 통제할 수 있으므로 가독성을 높이는 것을 추가 강조했다. 가재코드의 모든 답변에 고정 번호 양식이 있다는 주장은 확인되지 않았다. 기존 Markdown과 자체 Native 지침을 사용해 WWW의 대화 흐름에 맞춘다.

시나리오는 여러 결과가 있는 기능 구현, 미해결 실패, 사용자 지정의 짧은 질문, 저장 대화와 재개, 좁은 창·복사·키보드 실행 기록이다. 별도 LLM 재요약이나 보고서 변경·추가 권한·원본 변경·커밋·push는 포함하지 않는다.
