## 요청과 목적

사용자는 화면을 보면서 다음을 요청했다.

1. 오른쪽 사이드바에서 세션 흐름을 파악하고 Skill·Hook 호출을 신호등처럼 실시간으로 본다. 질문을 클릭해 작업 흐름을 상세히 읽는 방식은 유지하되 사람이 읽기 쉽게 하고 모니터링 정보를 보강한다.
2. 간헐적으로 Enter가 먹히지 않는다. Input → Output으로만 보이는 대화를 Input → Thinking 또는 Process → Output으로 바꾼다.
3. 전체 UI를 개선하기 위해 WWW 전용 Design 에이전트와 디자인 시스템을 만들고 오픈소스를 적극 활용한다.
4. 첫 파일럿은 Bash 등 명령 실행 내부의 출력을 들여쓰기를 보존해 약 10줄 보여주는 카드다. GJC가 레퍼런스다.
5. 후속 보고: 채팅 답변이 잘려 내용을 확인할 수 없다.

목표는 사용자가 답변 전에도 실행·대기·실패를 이해하고, 답변 뒤에는 질문별 근거와 결과를 끝까지 읽을 수 있는 작업 공간이다.

## 범위와 요청에서 받은 권한

제품 개발 범위는 오른쪽 패널, 채팅 본문·입력·스크롤, 명령 카드, Design 역할과 디자인 규칙 및 오픈소스 비교다. 영향 영역은 `ui`, `dev`이며 주 책임은 `ui`다.

**이번 직접 요청의 실행 권한은 개발 명세 작성·기록·검토다.** 제품 소스 수정, Design 역할 설치·활성화, 의존성 설치, 모델 설정 변경, commit·push·배포는 실행하지 않는다. 후속 개발은 같은 작업 ID와 실제 구현 권한을 연결한다.

별도 원격 모니터 서버, 메시지 DB, 모델별 비용 추정, 비공개 사고 원문 표시, 터미널 에뮬레이터 전체 교체는 제품 목표에서 제외한다.

## 오른쪽 세션 모니터

관련 기준: `AC-01`, `AC-02`, `AC-03`.

현재 작업과 과거 선택을 구분한다. 최신 턴을 따라가면 새 사건을 반영하고, 사용자가 과거 질문을 고르면 새 사건이 선택을 빼앗지 않는다. 현재 작업의 작은 상태 표시는 유지하고 ‘현재 작업으로 돌아가기’를 제공한다. 질문 제목은 입력의 읽기 쉬운 요약이며 전체 입력을 펼쳐 확인할 수 있다.

Skill·Hook에는 종류, 이름, 상태, 최근 발생 시각을 표시한다. 시작 때 켜지고 종료 때 완료 흔적으로 바뀌어 움직임을 알 수 있어야 한다. 짧은 호출은 최근 활동에 남긴다. 색상·아이콘·문구를 함께 사용하고 모션 축소 설정을 존중한다.

| 실제 관측 | 표시 의미 |
|---|---|
| Skill 명시 요청 | ‘요청됨’. 적용 성공이 아니다. |
| 구조화된 SKILL.md 읽기 시작·완료 | ‘읽는 중’, ‘읽기 완료’, ‘읽기 실패’. 읽기 완료를 적용 완료로 바꾸지 않는다. |
| 명시적 적용 근거 | 호스트가 제공하고 귀속을 확인한 범위에서만 ‘적용 확인’. 근거가 없으면 확인 불가다. |
| Hook 시작·정상 종료 | ‘실행 중’ → ‘완료’. 실제 run ID로 같은 실행을 갱신한다. |
| Hook 오류·차단·중단 | 각각 ‘실패’, ‘차단’, ‘중단’. |
| 시작만 있고 종료 없음 | ‘결과 미확인’. 턴 종료로 개별 실행 성공을 추정하지 않는다. |

질문 상세는 ‘입력 처리 확인 → 파일 2개 수정 → 테스트 실패 → 수정 후 재검증’처럼 한국어로 요약하고 기술 근거를 펼침에 둔다. 모델 설명에서 관측되지 않은 작업을 추출해 성공 이력으로 만들지 않는다.

우선 정보는 현재 작업, 경과 시간, 마지막 활동 시각, 승인 대기, 실패·재시도, 연결 상태다. 종료 후 경과 시간은 고정한다. 긴 무응답은 ‘마지막 활동 N초 전’으로 표시하고 실패·정지를 단정하지 않는다. 재시도는 실제 새 시도가 관측된 경우만 표시한다. 토큰·설정 모델·관측된 모델 전환·계정 한도는 보조 상세에 두고 미제공 값을 추정하지 않는다.

## 실시간 대화와 사건 연결

관련 기준: `AC-04`.

공개 진행 설명, 공개 추론 요약, 명령 시작·출력·종료, 최종 답변 델타를 받을 때 같은 턴의 화면을 갱신한다. 턴 완료까지 기다려 한꺼번에 보여주지 않는다. 채팅은 사람이 읽을 과정을, 패널은 같은 과정에서 관측한 실행 상태를 제공한다.

비공개 analysis·추론 원문은 표시하지 않는다. 공개 설명이 없으면 내용을 생성하지 않고 상태 안내로 ‘공개 진행 설명 미제공’과 실제 도구 상태를 보여준다. 가짜 진행 메시지나 무한 Thinking 애니메이션으로 대체하지 않는다.

`threadId`, `turnId`, `itemId`, Hook의 `runId`, 요청 연결 ID와 수신 순서를 보존한다. 중복·늦은 사건·다른 스레드 사건을 분리한다. 턴 귀속 없는 Hook은 세션 활동에 둔다. 과거 복원은 이력으로 표시하고 실시간 호출 효과나 실행을 재발행하지 않는다.

진단은 Native 생성 → main 수신 → renderer 전달 → 투영 → 화면 반영을 구분해 측정한다. 제안 목표는 정상 로컬 환경에서 수신 후 500ms 이내 상태 반영이다. 모델의 첫 사건 생성 대기 시간은 별도 기록한다. 이 수치는 사용자 확정값이 아니라 구현 후 실측으로 검토할 기본 목표다.

## 입력과 답변 잘림

관련 기준: `AC-05`, `AC-06`.

Enter는 전송, Shift+Enter는 줄바꿈이다. 한국어 조합 중 Enter는 글자 확정에 사용하고 조합 종료 후 별도 Enter는 전송한다. 이벤트 경계·시각·키 상태·전송 핸들러 진입을 조사한다. 전송 중 반복 Enter·클릭은 같은 요청을 중복 전송하지 않는다. 실패 시 초안을 보존하고 전달 결과 불명확 상태에서 자동 재전송하지 않는다. 실행 중 추가 입력의 현재 정책을 확인하고 새 큐·턴 정책을 임의 도입하지 않는다.

답변 잘림은 수신 원문 손실, 투영 제한, Markdown 렌더링, CSS overflow, 스크롤·입력창 가림을 분리해 조사한다. 긴 답변의 마지막 문장·목록·표·코드를 스크롤과 키보드로 읽을 수 있어야 한다. 긴 URL·코드가 전체 창을 가로로 밀지 않게 하고 필요한 코드 영역만 가로 스크롤한다.

아래에서 읽고 있으면 새 내용을 따라가고 과거 내용을 읽으면 위치를 보존하며 새 내용 알림으로 복귀한다. 창 크기 변경과 패널 전환 뒤에도 답변 끝에 접근할 수 있어야 한다. 보관 한도 초과는 생략 위치를 알리고, 보관하지 않은 원문을 전체 보기·복사로 복원할 수 있다고 약속하지 않는다.

## 첫 파일럿: 명령 실행 카드

관련 기준: `AC-07`.

‘bin / git bash’는 우선 Bash 등 명령 실행 도구의 출력 카드로 해석한다. 별도 셸 선택기나 터미널 앱으로 확장하지 않는다. 실제 GJC 출력 표현을 대조한 뒤 구조를 다듬는다.

```text
● 실행 중 · 3초
  git status --short
  작업 경로: 선택한 프로젝트

  출력
    M src/input.ts
    M src/renderer.tsx

  [보관된 출력 펼치기]
```

기본 미리보기는 논리 줄 기준 최대 10줄이다. 실행 중 최근 10줄을 갱신하고 정상 종료 후 앞 10줄을 보여준다. 사용자의 ‘앞에 10줄 정도’와 실행 중 최신 흐름을 함께 충족하려는 제안 기본값이다. 실패하면 보관된 오류 출력과 종료 상태를 우선 펼치되 원래 순서와 stdout/stderr 출처를 제공되는 범위에서 보존한다. 출처 없는 출력은 임의 분리하지 않는다.

들여쓰기·줄바꿈을 보존하고 명령, 경로, 상태, 경과 시간, 제공된 종료 코드를 구별한다. 출력이 없으면 ‘출력 없음’을 표시한다. 전체 보기는 보관된 출력만 제공하고 미리보기 생략과 원본 보관 한도 초과를 구별한다. 사용자가 펼치거나 접은 상태는 새 출력·종료로 덮어쓰지 않는다. 성공을 자동으로 접더라도 미리보기는 남긴다.

## WWW Design 역할과 디자인 시스템

관련 기준: `AC-08`, `AC-09`.

목적은 WWW 화면·컴포넌트의 일관된 규칙을 설계하고 개발에 인계하는 것이다. 역할 파일 생성과 호스트의 실제 호출·수용을 구별한다. 이름은 `www-design-agent`를 제안하며 기존 단계 스킬 `www-design`과 혼동되지 않게 한다. 등록 방식은 후속 설계에서 현재 호스트 지원을 확인한다.

| 항목 | 책임 |
|---|---|
| 입력 | 사용자 요구, 현재 화면, 기존 컴포넌트·CSS, 상태·접근성 요구, 라이선스 제약 |
| 산출물 | 디자인 원칙, 의미 기반 색상·글자·간격·모서리·모션 토큰, 컴포넌트 상태 명세, 파일럿 화면, 오픈소스 비교 근거 |
| 개발 인계 | 토큰·컴포넌트 정본 위치와 사용법, 상태별 상호작용, 반응형 동작, 검증 시나리오 |
| 권한 | 디자인 산출물과 허용 범위의 구현 제안. 별도 권한 없이 의존성 설치·실행 권한·게시 정책을 변경하지 않는다. |
| 검토 | Codex가 저작하고 읽기 전용 Opus가 독립 검토한다. Design 역할은 자기 결과를 최종 승인하지 않는다. |

명령 카드부터 상태 표시·질문별 흐름·메시지·입력창·패널로 확장한다. 원시 색상값을 복제하지 않고 의미 토큰을 참조한다. 실행·대기·성공·실패·미확인·빈 상태·로딩·비활성·포커스를 정의한다. 대비, 키보드, 포커스, 모션 축소, 긴 한국어 문구를 확인한다. 전체 화면 재작성은 첫 파일럿의 조건이 아니다.

오픈소스 후보 3개 이상을 공식 저장소·문서에서 조사하고 고정 revision, 라이선스, React/Electron 적합성, 스트리밍·접근성·스타일 확장성, 의존성, 채택·제외 이유를 기록한다. GJC 실제 화면은 직접 시각 참조로 별도 확보한다. 기존 Ovis 개작과 고지를 먼저 확인하고 기존 기반 유지도 비교한다. 이번 명세 작성에서 후보를 조사·선정했다고 기록하지 않는다.

| 순서 | 개발 단위 | 확인할 결과 |
|---|---|---|
| 1 | Enter·답변 잘림·스트리밍 재현과 경계 측정 | 재현 여부와 조건을 기록하고 원인별 근거를 구분한다. |
| 2 | Design 최소 규칙, GJC·오픈소스 비교, 명령 카드 파일럿 | 0·1·10·11줄·대량 출력, 긴 줄·들여쓰기·오류·중단·종료 누락을 읽는다. |
| 3 | 공개 진행과 오른쪽 모니터 통합 | 종료 전 갱신, Skill·Hook 변화, 질문 선택과 최신 복귀를 확인한다. |
| 4 | 디자인 규칙 확대와 통합 검증 | 본문·패널·입력 상태가 일치하고 읽기·대화 재개 회귀가 없다. |

입력은 한글 조합 확정 직전·직후 Enter, 영문 Enter, Shift+Enter, 반복 Enter·클릭, 포커스 이동, 실패를 실제 Electron에서 확인한다. 읽기는 긴 Markdown·표·코드·URL, 스트리밍 중·완료 후, 과거 스크롤, 창 축소·패널 전환을 포함한다.

사건은 Skill 요청만 있는 경우, 읽기 성공·실패, Hook 성공·실패·차단·중단·종료 누락, 중복·늦은 다른 턴 사건, turn 없는 Hook, 과거 복원, 연결 끊김을 포함한다. 첫 활동·마지막 활동·종료 및 실제 반영 시각을 남긴다.

합성 사건은 상태·순서 경계를, 실제 Native는 제공 사건과 수신 연결을, Electron GUI는 입력·배치·스크롤을 검증한다. Mac과 Windows의 한국어 IME 결과를 각각 기록하고 미실행 플랫폼은 통과로 쓰지 않는다. 집중 테스트·타입 검사·빌드와 읽기 전용 Opus 독립 검토는 후속 구현의 수용 조건이다. Opus 불가 시 자동으로 낮은 모델로 대체하지 않고 미실행 blocker로 기록한다.

## 수용 기준과 현행 요구 연결

기준 ID는 `AC-01`부터 `AC-10`이다. 정의와 현재 결과는 [work.json](work.json)에서 확인한다. 각 절의 시나리오는 해당 ID의 검증 입력이며 통과 증거가 아니다.

현행 [Chat 명세](../../../specs/chat.md)의 `CHAT-ACTIVITY-01`, `CHAT-ERROR-01`, `CHAT-OBSERVE-01`, `CHAT-INPUT-01`, `CHAT-RENDER-01`과 연결한다. Design 역할·오픈소스 조사·구현 인수는 이번 작업의 추가 기준이다. 현행 정본은 제품 구현과 대조해 갱신하고 미래 목표로 기존 구현을 완료 처리하지 않는다.

## 결정과 열린 사항

사용자가 확인한 방향은 오른쪽 흐름, Skill·Hook 실시간 움직임, 질문별 상세, 입력 문제 해결, 과정 표시, Design 에이전트·오픈소스 활용, GJC 카드 파일럿, 답변 잘림 해소다.

작성자 제안은 모니터 정보 우선순위, 실행 중 최근 10줄·종료 후 앞 10줄, 수신 후 500ms 목표, 역할 이름, 후보 3개 이상 비교다. 명세 작성 요청을 세부값의 사용자 승인으로 기록하지 않는다. 추후 조정 가능한 기본값이며 명세 작성을 막는 미결정은 없다.

후속 설계에서 실제 GJC 화면과 고정 revision, 오픈소스 채택안, 역할 등록 방식, 토큰 값·패널 폭을 확인한다. 후속 진단에서 Enter·스트리밍·잘림의 원인을 판별한다. 현재는 미실행이다.

## 이번 작성의 완료와 후속 인계

요구·관측·추정·제안과 동작·검증 시나리오·기준·권한·순서를 기록하는 것이 이번 명세 작성의 범위다. 문서 구조·링크와 독립 검토 결과를 별도로 남긴다. 제품 개발 작업은 `ready`이고 구현 기준은 모두 `unverified`로 유지한다.

후속 개발자는 같은 ID를 읽고 실제 구현 권한을 연결한 뒤 `www-diagnose`와 `www-design`으로 진입한다. 다른 작업 트리 변경을 보존하고 Design 역할·제품 기능이 설치·완료됐다고 가정하지 않는다.

## 2026-11-13 개발 재개 권한

사용자의 직접 요청 “개발진행”으로 같은 작업 ID의 진단·설계·제품 구현·필요한 의존성 비교와 검증을 이어간다. 위 명세 작성 당시의 실행 제한은 당시 접수 이력이며 이번 구현 권한은 work.json에 연결했다. commit·push·배포는 요청하지 않았다. 기존 사용자 변경은 보존한다.

## 2026-11-13 WWW 전용 흐름 중심으로 수정

사용자는 범용 sessionStart/postToolUse/stop의 반복 실패 목록보다 WWW에 정의된 에이전트와 개발 스킬의 활동을 중심으로 보고 싶다고 정정했다. 같은 작업의 구현 권한으로 반영한다. 역할 www-dev·www-design-agent와 여섯 www-* 스킬을 기본 화면에 두고 일반 Hook·명령 전체 목록·모델 정보는 상세로 둔다. Hook 실패는 숨기거나 성공 처리하지 않고 수와 근거를 별도로 보존한다.

문서가 등록돼 있다는 사실, 읽기 요청·읽기 완료, 문자 그대로의 문서 읽기 명령 관측, 실제 적용 확인을 구별한다. 실제 적용 근거가 없으면 적용됐다고 쓰지 않는다. 여러 파일 cat이 Native에서 unknown으로 분류되는 경우에는 엄격한 리터럴 cat 관측만 별도 근거로 허용하고 echo·스크립트·치환·임의 명령 문자열로 사용 이력을 만들지 않는다. 새 기준은 AC-11·AC-12다. 전역 Hook 설정이나 trust를 임의 변경하지 않는다.
