# 실시간 세션 모니터와 채팅 가독성 — 설계

작업 ID: `work-eed41da3-f22e-4fb9-b9df-9a1a7d76c44f`. 목표·범위는 [명세](spec.md), 수용 기준은 [작업 레코드](work.json)가 소유한다. 2026-11-13 사용자의 ‘개발진행’ 요청으로 같은 작업의 진단·설계·구현·검증을 잇는다. 이번 설계는 기존 Electron·React·Native 사건·Ovis 개작을 유지한다.

## 정보 배치

가장 먼저 현재 작업과 개입할 대기를 읽게 한다. 본문은 입력 → 공개 진행·명령 → 답변을 시간순으로, 패널은 현재 상태 → 질문 선택 → 선택한 흐름 → 보조 사용량 순서로 제공한다. 과거 질문을 선택한 동안 현재 작업의 작은 상태를 유지하고 최신 복귀로 돌아온다. 별도 사건·메시지 저장소를 추가하지 않는다.

```text
탐색       본문                               세션 모니터
대화       사용자 입력                        현재 작업·마지막 활동
목록       공개 설명                          질문 선택·최신 복귀
           명령·출력 10줄                     Skill·Hook과 작업 흐름
           최종 답변                          펼쳐 보는 모델·사용량
           입력창
```

좁은 창은 본문·입력의 최소 접근을 먼저 확보하고 모니터를 접거나 별도 보기로 연다. 읽기 영역의 최소 크기 제약과 overflow를 정리해 긴 답변이 입력·고정 바 아래로 사라지지 않게 한다. 스타일 계약은 [디자인 시스템](../../../design-system.md)에 둔다.

## 상태와 데이터 흐름

Native → main → renderer의 기존 `AppEvent`를 본문 `projection`과 활동 `native-activity`가 각각 투영한다. 요청 연결 ID, thread/turn/item/run ID와 seq를 유지한다. 새 애니메이션을 위해 같은 사건을 다시 발행하거나 과거 복원을 현재 호출로 만들지 않는다. 타이머는 받은 시각·종료 시각을 읽으며 성공을 추정하지 않는다.

현재 작업은 선택한 과거 질문과 분리한다. 과거 질문의 본문·초안·읽기 위치·펼침 상태를 보존하면서 현재 연결·승인·실행 상태를 알려준다. 실제 새 시도 없이는 재시도 상태를 만들지 않는다. Skill 읽기 관측과 적용 확인은 독립된 의미로 표시한다.

공개 설명이 없으면 미제공 안내와 관측된 상태를 보인다. 비공개 reasoning을 표시하거나 모델이 제공하지 않은 진행 문장을 만들지 않는다. 수신→화면 반영 500ms는 측정할 기본 목표이며 첫 모델 사건 생성 대기와 분리한다.

## 명령 카드 파일럿

명령 카드는 관측 상태·경과 시간, 명령, 제공된 경로, 출력 미리보기, 보관 출력 펼침을 갖는다. 실행 중 최근 10개 논리 줄·정상 종료 뒤 앞 10개 논리 줄을 보여주고 미리보기 밖 줄 수를 알린다. 실패·중단·종료 누락과 출력 없음은 별도 안내한다. 전체 보기의 대상은 보관된 출력이며 보관 절단과 미리보기 생략을 구별한다.

공백과 탭·줄바꿈은 고정폭 `pre`로 보존하고 긴 한 줄은 카드 내부에서 가로 스크롤한다. 사용자가 펼치거나 접은 상태는 새 출력·종료로 덮어쓰지 않는다. 기존 논리 행 상태를 재사용한다. [오픈소스 비교와 GJC 근거](comparison.md)는 선택 이유와 실제 확인 범위를 설명한다.

## 위험과 검증

Enter 누락은 기존 IME 시간 경계와 실제 이벤트를 분리해 조사한다. 전송 중복 방지와 실패 초안 보존은 유지한다. 답변 잘림은 수신·투영 제한·Markdown·CSS·스크롤을 각 경계에서 확인하며 시각 증거 없는 원인을 확정하지 않는다.

합성 사건은 중복·늦은 사건·종료 누락·복원의 상태 의미를, 실제 Native는 제공 사건과 수신 연결을, Electron GUI는 입력·포커스·스크롤·배치를 확인한다. Mac/Windows 한글 IME는 각각 실기 여부를 기록한다. 명령 출력 0·1·10·11줄과 대량·긴 줄·오류·중단, 과거 질문 선택 중 새 출력, 창 축소·패널 전환, 긴 Markdown의 마지막 문장·표·코드를 확인한다.

실행 코드의 source/type/BoxBox, 집중 테스트·빌드와 읽기 전용 Opus 독립 검토를 실제 근거로 남긴다. 작성된 역할 계약은 자동 호스트 등록의 증거가 아니며 호출·수용 확인은 별도 기록한다. 검토 정책의 적용은 공유 core가 맡는다.

## 피드백 반영: WWW 전용 관측을 기본 화면으로

현재 요청 요약 → WWW 전용 역할 둘 → 여섯 개발 스킬 → 일반 Native 활동 상세 → 모델·토큰 상세로 배치한다. 전용 문서 관측은 이름·정본·근거를 보존하고 사용자 펼침을 질문별로 기억한다. 역할의 실제 적용을 알리는 구조화 사건은 현재 없으므로 성공을 합성하지 않는다.

범용 Hook의 실패 수와 신뢰 검토 필요 건수는 접힌 요약에서 보이고 개별 오류·경로는 상세에서 확인한다. Native failed 상태를 지우지 않으며 같은 턴의 일반 명령·모델 응답이 정상이어도 개별 Hook 실패를 분리한다. Hook trust와 전역 설정은 이번 제품 수정의 쓰기 대상이 아니다.
