Skills와 Hook 활동 사이드바

Skills와 Hooks를 고정 목록으로 보여 주고 새 구조화 활동이 생긴 해당 행만 반응하는 최소 사이드바를 구현했습니다. 순수 투영과 기존 대화 회귀 76건 및 번들은 통과했지만, 의존성 설치 실패로 전체 타입 검사와 Electron GUI가 완료되지 않았습니다. 실제 Native 목록 표본과 BoxBox 후검사도 현재 환경에서 실행하지 못했고, 필수 Opus 검토는 인증 오류로 미실행 상태입니다. 따라서 변경은 구현되어 있으나 작업은 완료가 아닌 검증·감사 대기로 남깁니다.

요청의 확정 범위인 Skills·Hooks 목록과 해당 행의 짧은 새 활동 반응을 기존 넓은 활동 패널에서 분리해 구현했습니다. 목록 출처와 구조화 활동의 의미를 구분하고, 중복·이력 복원·다른 스레드·늦은 Hook 시작이 현재 행을 잘못 켜지 않도록 순수 투영에서 차단했습니다. 집중 회귀와 번들은 통과했으나 이 머신의 부분 설치와 실행 권한 제약 때문에 실제 GUI·Native 표본·전체 타입·BoxBox를 끝내지 못했습니다. 정책상 필수 Opus 검토도 인증 오류라 완료 판정을 내리지 않았습니다.

중요한 선택과 그 이유

목록 key가 Hook 시작 알림에 없는 상태에서 등록 행을 어떻게 연결할지

선택 eventName·sourcePath·displayOrder·handlerType이 정확히 하나와 일치할 때만 등록 행에 연결하고 나머지는 감지 행으로 분리했습니다.

판단 근거 codex-cli 0.166.0 생성 스키마에서 목록과 시작 알림의 공통 필드를 대조했습니다.

함께 검토한 대안

  • eventName만으로 연결
  • 모든 시작을 새 감지 행으로 표시

감수한 점 동일 tuple의 등록 Hook이 여러 개면 기존 행 반응 대신 별도 감지 행이 생깁니다.

복원 이력과 실시간 반응을 어떻게 구분할지

선택 snapshot은 상태 복원에만 사용하고 onEvent로 받은 live 사건만 pulse 입력에 넣었습니다.

판단 근거 events/get snapshot을 pulse로 쓰면 재시작·리렌더·패널 재진입 때 과거 활동이 새 활동처럼 보입니다.

함께 검토한 대안

  • 모든 최신 관측을 다시 애니메이션
  • 마지막 시각 기준 휴리스틱

감수한 점 패널이 숨겨진 동안의 활동은 최근 관측 상태로 남지만 다시 열 때 애니메이션하지 않습니다.

확인하지 못한 범위

  • npm install이 제한된 네트워크의 ENOTFOUND와 npm 종료 처리 오류로 완료되지 않아 @types/bun·@types/node가 비었고 npm run typecheck가 실패했습니다.
  • Electron 실행 파일이 node_modules에 없어 실제 Electron+합성 Native GUI, 좁은 패널, 모션 축소 computed style, 초안·패널 재진입 시나리오는 실행되지 않았습니다.
  • 샌드박스에서 실제 codex app-server 프로세스 시작이 Operation not permitted로 막혀 설치 Native의 skills/list·hooks/list 표본을 확인하지 못했습니다.
  • .www/development.local.json과 검증된 BoxBox 설치 runtime이 없어 요구된 BoxBox 작성 후 검사를 실행하지 못했습니다.
  • 정책상 Opus 읽기 전용 검토는 인증 오류로 not_run이며, 사용량 소진이 아니므로 Terra 대체는 수행하지 않았습니다.
  • 커밋·push·배포는 요청 범위가 아니어서 수행하지 않았습니다.
