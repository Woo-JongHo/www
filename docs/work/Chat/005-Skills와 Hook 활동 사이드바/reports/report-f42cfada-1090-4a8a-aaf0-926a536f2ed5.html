Skills와 Hook 활동 사이드바

Terra 재검토 2차가 확인한 확률 dedupe 오탐과 snapshot/live 순서 경합을 현재 제품 경계에서 수정했다. 서로 다른 Hook run 20,000개가 모두 반응하고 오래된 동일 ID는 다시 반응하지 않으며, bootstrap·대화 전환 중 live 사건은 snapshot과 seq 순서로 원자 병합된다. 집중·타입·빌드·전체 npm 검사는 frozen source digest에서 통과했다. 실제 Electron·Native는 부모가 별도 조사 중인 환경 실패 때문에 AC-4와 AC-5를 완료로 올리지 않았고, 부모의 GUI 재실행과 Terra 읽기 전용 재검토가 다음 단계다.

연결 세대의 Bloom-style 필터가 서로 다른 새 Hook run을 중복으로 오인해 실제 활동을 누락할 수 있었다. renderer는 live 구독 사건을 snapshot과 별도로 즉시 reducer에 보내므로 seq 3을 먼저 처리한 뒤 seq 1·2 snapshot이 도착하면 일반 watermark가 연결·catalog 복원을 버릴 수 있었다. 일반 사건의 처리 이력은 scalar watermark로 압축하고, 연결 세대의 Skill read·Hook run ID는 실제 문자열 Set으로 정확히 보존한다. 64개 bucket은 복사 범위를 나누는 데만 쓰며 해시는 중복 판정에 관여하지 않는다. renderer는 snapshot 요청 전에 tokenized live 큐를 열어 snapshot cutoff까지를 복원으로, 이후 live만 새 반응으로 적용하고 실패·취소·StrictMode 재진입도 안전하게 배출·격리한다.

기록에 남은 주요 선택

  • 임의 유한 메모리로 무한한 임의 ID의 exact dedupe를 약속하지 않았다. 새 활동 정확성을 희생하지 않고 연결 세대의 고유 ID 수에 비례하는 필수 상태를 보존하며 실제 새 transport 연결에서 회수한다.
  • 해시는 bucket partition에만 사용하고 실제 문자열 비교로 중복을 결정한다. updater마다 전체 ID 집합 대신 wrapper와 변경 bucket만 복사해 React 이전 state 불변성을 지킨다.
  • snapshot 최대 seq를 cutoff로 사용해 그 시점까지 큐에 있던 사건은 복원으로 처리하고 이후 live만 pulse로 처리한다. catalog와 transport는 별도 generation/lifecycle watermark로 늦은 snapshot을 수용하되 최신 상태를 역행시키지 않는다.
