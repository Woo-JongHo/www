# 명령 카드 표시 설계

## 데이터 흐름과 책임

projection의 원본 block.output은 바꾸지 않는다. command-preview.ts는 완전성 확인, JSON 토큰의 공백 정렬, 구문 토큰과 제한된 검토 보고값을 순수 계산한다. command-card.tsx는 표시/원문 선택, 원문 복사, 기존 10줄 미리보기·전체 펼침을 연결한다. chat.css는 명령·키·문자열·숫자·리터럴 색상과 내부 스크롤·포커스를 제공한다. 기존 구조 ID를 유지하고 생성 설계도를 공식 생성기로 갱신한다.

## 표시 정책

JSON.parse는 완전성 확인과 제한된 보고값 읽기에만 쓴다. 표시문은 원문 토큰으로 재구성하여 큰 정수, -0, 지수 표기, 중복 키, 이스케이프를 보존한다. 최대 입력 32,768 UTF-16 단위, 깊이 24, 정렬 결과 131,072 단위를 넘으면 원문으로 표시한다. 배열·객체 외 JSON 스칼라, 혼합 로그·NDJSON, 실행 중·절단 출력도 원문으로 둔다. JSON으로 감싼 문자열 안의 코드를 재해석하지 않는다.

명령은 따옴표 문자열과 옵션만 보수적으로 강조하고 실행·재작성하지 않는다. JSON 키·문자열·숫자·리터럴은 색상 역할을 나눈다. HTML 삽입은 하지 않는다. 원문 보기에서는 강조와 정렬을 제거하고 원문 복사는 항상 block.output을 사용한다. 전환 상태는 기존 행 메모리에 별도 키로 보존한다.

## 프로세스와 검토 보고

기존 completed 상태의 제목은 ‘실행 종료’로 표시한다. 완전한 종료 JSON에 review- 접두 ID, provider/model 문자열과 pass/fail/not_run 판정이 있을 때만 ‘출력의 검토 판정’으로 표시한다. 보고값이라는 설명을 붙이고 프로세스 상태는 변경하지 않는다. 일반 로그나 중간 출력에서는 업무 결과를 추정하지 않는다.

## 위험과 검증

AC-01: 토큰 보존·깊이/크기 경계·악성 HTML을 단위 검사한다. AC-02: raw 불변·불완전·절단·실시간 fallback과 10줄 경계를 검사한다. AC-03: exit 0 + not_run/fail/pass의 서로 다른 표시를 검사한다. AC-04: 실제 Electron 합성 이력에 사용자가 제시한 형태의 JSON을 추가하고 computed 색상·2칸 공백·원문 전환·클립보드·키보드·좁은 창·기존 수동 펼침을 검사한다. 실제 모델/Windows/OS IME와 구분한다.

## 검증 범위 분리

전체 GUI의 재연결 후 답변 수신 실패를 별도 이력에 보존한다. `--command-cards`는 같은 하네스의 카드·클립보드·폭별 레이아웃 시나리오까지 실제 실행하고 scope를 명시한 summary를 반환한다. 기본 전체 경로와 후속 검사는 유지한다. 제한 검사의 PASS를 재연결·전체 앱 검증으로 확대하지 않는다.
