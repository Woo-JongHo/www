채팅과 실시간 사이드바 및 프로젝트 Node Map 개편

인터뷰에서 확정한 UI 개편 명세를 WWW 작업 체계에 등록했다. GJC 세션 파일 없이도 작업 목차·명세·작업 레코드로 요구와 21개 수용 기준을 확인할 수 있다. 제품 구현은 수행하지 않았으며 작업은 ready, 다음 단계는 design으로 남겼다.

확정 명세가 GJC 숨김 세션에만 있어 WWW 작업 목차와 작업 UUID로 찾을 수 없었다. Chat 009 작업에 명세와 수용 기준을 등록하고 작업 목차에서 연결했다. 채팅 스크롤, 상태 사이드바와 대화별 리소스 영속화, 로컬 프로젝트 탐색, Node Map의 합의 내용과 제외 범위를 읽을 수 있다.

저장 당시 업무 상태진행 중 기록

다음 행동 같은 작업 UUID의 명세와 수용 기준을 사용해 후속 합의 설계를 진행한다.

저장 당시 기준 중 21개가 실패·차단·미검증 또는 미확인으로 남았습니다.

기록된 변경

  • 새 work.json에 21개 수용 기준과 명세 등록 권한을 연결했다.
  • spec.md에 네 영역의 사용자 시나리오·확정 결정·설계 과제·검증 계획·참고 자료를 작성했다.
  • 기존 작업 목차에 명세와 작업 레코드 링크를 추가했다.

요구와 결과

구조화된 요구·결과 설명이 없어 저장된 수용 기준과 당시 상태를 그대로 보여 줍니다.

긴 답변과 연속 메시지에서도 문서 전체가 세로로 밀리지 않고 대화 영역 내부에서 스크롤된다. 입력창과 탐색·상태 영역은 화면 안에 유지된다.
미검증으로 기록
긴 코드·URL·표의 넘침을 해당 영역에 가두며 앱 전체의 가로 넘침을 만들지 않는다.
미검증으로 기록
과거를 읽는 중 새 출력이 와도 읽기 위치를 빼앗지 않는다. 최신을 따라가는 중이면 새 내용과 레이아웃 변경 후 끝 위치를 유지한다.
미검증으로 기록
모니터 열기/닫기와 지원하는 창 크기 변경에서도 입력창 접근과 대화 스크롤이 유지된다.
미검증으로 기록
상단에 현재 요청의 단계·작업 체크리스트를 표시한다. 과거 요청의 완료 상태가 현재 요청으로 섞이지 않는다.
미검증으로 기록
실제 Skill/Hook 호출이 관측되면 즉시 이름·활동 상태를 알아볼 수 있도록 반영한다. 전체 설치 카탈로그를 기본 화면에 나열하지 않는다.
미검증으로 기록
단계·호출 자료가 없으면 미제공/누락을 표시한다. 대화 내용으로 호출·진행·성공을 추정해 만들지 않는다. 문서 읽기와 실제 실행도 구분한다.
미검증으로 기록
하단에 실제 사용 리소스를 시각적으로 정리해 대화(thread) 단위로 축적한다. 같은 대화의 후속 요청은 이어 쌓고 다른 대화·프로젝트와 섞지 않는다.
미검증으로 기록
앱을 재시작한 뒤 같은 대화를 다시 열면 보존된 누적 리소스를 확인할 수 있다. 이력 복원을 새 호출 반응으로 재생하지 않는다. 누락 구간·불완전 이력을 완전한 기록으로 주장하지 않는다.
미검증으로 기록
동일 관측의 중복 전달·복원으로 누적을 이중 계산하지 않는다. 저장 형식·용량·복구 오류 처리는 후속 설계에서 정하되 누락·손상을 숨기지 않는다.
미검증으로 기록
상세 실행 흐름·이벤트 및 필요시 전체 리소스 카탈로그는 사이드바와 분리된 상세 모니터 화면에서 확인한다. 상세 조회가 채팅 초안이나 읽기 위치를 잃게 하지 않는다.
미검증으로 기록
로컬 최근 프로젝트·즐겨찾기·프로젝트별 대화를 구별해 탐색할 수 있다.
미검증으로 기록
Figma의 명료한 탐색 계층을 참고하되 일관된 선형 아이콘·선택 강조·간격·타이포그래피를 적용한다. Figma 전체 서비스나 외형의 완전 복제는 아니다.
미검증으로 기록
프로젝트 전환 뒤 해당 프로젝트의 대화만 연결하며, 기존 실행·승인 중 전환 보호 및 저장 대화 재개 동작을 회귀시키지 않는다.
미검증으로 기록
아이콘만으로 의미를 전달하지 않고 접근 가능한 이름과 키보드 포커스를 제공한다.
미검증으로 기록
기존 구조 화면의 산만한 카드 배너 중심 구성을 기능→처리 흐름→담당 코드를 읽을 수 있는 연결 지도 중심으로 개편한다.
미검증으로 기록
연결선, 검색, 확대·축소, 지도 이동, 선택 항목 상세를 제공한다. 검색 결과를 지도와 상세에서 찾을 수 있고 선택/초점이 식별된다.
미검증으로 기록
선택 상세에서 기능·처리 단계의 역할과 담당 파일/코드 근거를 확인한다. 없는 연결·코드 근거를 생성하지 않으며 미제공을 표시한다.
미검증으로 기록
개념적 처리 관계와 실제 실행 순서·호출 추적을 혼동시키지 않는다. 설치된 코드 의존 관계를 표시하면 그 관계 유형을 구분한다.
미검증으로 기록
참고 HTML의 계층 탐색·연결·선택 상세 방식은 모티브로 사용하되 RPA의 Process/Task/Unit 용어를 WWW에 억지로 적용하지 않는다.
미검증으로 기록
큰 지도에서도 창 전체를 밀어내지 않고 내부 탐색이 가능하며 선택 상세를 닫거나 화면 전환 후에도 탐색과 채팅이 정상 동작한다.
미검증으로 기록

기록에 남은 주요 선택

  • 수용 기준 정의와 결과는 work.json만 정본으로 사용하고 명세에는 시나리오와 기준 ID를 연결했다.
  • 모든 제품 기준은 unverified로 유지하고 명세 등록을 구현 완료나 실행 승인으로 바꾸지 않았다.
  • 사용자의 최신 요청에 맞춰 합의 설계 진행은 보류하고 문서 등록만 처리했다.

구체적인 검증 대상·방법·기대·관측 설명이 기록되지 않았습니다. 명령이나 종료 코드만으로 사용자 행동을 확인했다고 추정하지 않습니다.

연결된 검사 시도가 없습니다. 미검증입니다.

독립 검토

연결된 독립 검토가 없습니다. 미실행입니다.

확인하지 못한 범위

  • node scripts/check-workflow.ts와 등록 비교 검증은 통과했으나 제품 테스트·타입 검사·빌드·실제 앱 GUI 검증은 수행하지 않았다. 실행 코드 변경이 없는 문서 등록이다.
  • 공유 검토 core를 통한 독립 Opus 검토와 현행 정본 전체의 완료용 문서 영향 검토는 수행하지 않았고 제품 작업을 done 처리하지 않았다.
  • 앱 리포트 화면을 직접 열지는 않았다. 생성된 보고서 HTML과 JSON은 파일로 확인한다.

남은 일과 해소 행동

  • 같은 작업 UUID의 명세와 수용 기준을 사용해 후속 합의 설계를 진행한다.
  • 구현은 별도 승인 이후 수행하며 현재 제품 기준의 미검증 상태를 보존한다.

담당·해소 조건·영향은 별도로 기록되지 않았습니다.
