# Native 대화 Bypass 기본값 적용

## 요청과 목적

Native 대화 Bypass 기본값 적용

사용자의 직접 요청으로 접수했다. 요청 식별값은 work.json의 workflow.requestHash에 보존한다.

## 범위

변경 경로·표면·검증 명령과 커밋·게시 권한은 work.json의 workflow.authorization을 따른다. 범위 확대는 기존 권한으로 간주하지 않는다.

## 수용 기준

정의와 필수 여부의 정본은 work.json이다. 관련 기준: `AC-1`, `AC-2`.

## 결정과 열린 질문

작업 접수는 구현 완료가 아니다. 재개 시 같은 UUID와 현재 증거를 확인한다.

## 배경과 변경 범위

사용자는 Bypass 기본 동작을 원하지만 새 대화가 on-request/workspace-write로 고정되어 세션 허용 요청이 발생했다. 새 대화와 기존 대화 재개에 never/danger-full-access를 명시한다. 저장된 모델·provider는 유지하며 승인 UI나 보고서 판단기의 읽기 전용 정책은 변경하지 않는다. AC-1은 요청 payload와 대화 복원 회귀 검사, AC-2는 소스 정책·타입 검사·빌드로 확인한다. 커밋·게시 요청은 없다.

## 재개 요청

사용자의 “진행해 뭐가 문제라고?” 요청에 따라 전체 빌드 차단 해소와 실제 앱 반영을 이어간다. 병행 작업의 누락 파일·타입 오류는 후속 보완에서 해소됐고, 마지막 빌드 차단인 보고서 테스트 3개의 구조 주석 앞 import만 주석 뒤로 옮긴다. 테스트 로직과 병행 작업의 기능 변경은 보존한다.
