# 오픈소스 채팅 뼈대 도입 비교

## 요청과 목적

개발용 채팅 완성을 위한 현재 기능 점검과 실제 공개 코드 뼈대의 도입 비교. 제품 이식 방식은 조사 결과를 보고 결정한다.

사용자의 직접 요청으로 접수했다. 요청 식별값은 work.json의 workflow.requestHash에 보존한다.

## 범위

변경 경로·표면·검증 명령과 커밋·게시 권한은 work.json의 workflow.authorization을 따른다. 범위 확대는 기존 권한으로 간주하지 않는다.

## 수용 기준

정의와 필수 여부의 정본은 work.json이다. 관련 기준: `AC-1`, `AC-2`, `AC-3`.

## 결정과 열린 질문

사용자는 개발 작업용 채팅을 목표로 선택했고, 오픈소스가 이미 제공하는 실제 뼈대를 가져오는 방식을 검토해 달라고 구체화했다. 비교 결과와 권장 경계는 [도입 비교](comparison.md)에 기록한다.

현재 범위는 기능 현황·검증 기준선·공개 코드와 라이선스·이식 경계 조사다. 전체 앱 기반 교체 또는 기존 앱 안의 UI 뼈대 도입 중 선택이 남아 있다. 제품 코드·의존성·기존 실행 정책을 바꾸지 않았다.

수용 기준 AC-1은 현재 코드·npm run check 결과, AC-2는 고정 SHA의 공식 소스, AC-3은 도입 비교의 책임 분리·실제 사용자 시나리오와 연결한다. 정적 문서 존재 검사를 외부 기능의 실제 이식 검증으로 취급하지 않는다.

작업 접수는 구현 완료가 아니다. 재개 시 같은 UUID와 현재 증거를 확인한다.
