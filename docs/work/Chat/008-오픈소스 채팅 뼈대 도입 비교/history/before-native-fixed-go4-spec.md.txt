## 요청과 현재 목표

개발용 채팅 완성을 위해 현재 기능·공백·실행 한계를 점검하고, Herdr 같은 완성 앱의 실제 고정 코드·라이선스·의존 경계를 비교한다. 최신 직접 재개 요청은 남은 제품·개발 작업의 부족한 검증 연결·문서·저작 보고서·독립 감사를 실제 증거로 회수하도록 허용한다. 근거 원문은 상위 TASK-RESUME.md와 `.www/evidence/resume-20261116/direct-resume-instructions.txt`, 감사의 별도 직접 원문은 direct-user-original.txt다. 기존 Opus fail과 당시 증거는 보존하고 현재 지적을 고친 소스로 다시 판단한다.

실제 첫 Terra 감사에서 자동 재연결 snapshot 전 live 사건 유실 가능 경계와 Windows 드라이브/역슬래시 UNC 경로 거부를 지적받았다. 해당 소스를 다시 읽고 현재 비교의 구체 제한·후속 개선 비용으로 반영한다. 제품 기능을 수정하거나 이 두 경계가 통과했다고 쓰지 않는다. 이 요청 범위는 비교 정확성 수정이며 기존 AC-1~3의 정의·필수 여부를 바꾸지 않는다. 공유 아키텍처의 동일 예외 교정도 읽고 반영한다. 과거 evidence summary는 기록 당시 문구이며 현재 적용성은 같은 UUID의 공식 status/evaluateEvidence로 판단한다.

현재 권장안은 [comparison.md](comparison.md)의 **Ovis에서 필요한 공개 채팅 동작만 개작하고 WWW의 Electron·Native 전송·원장·모니터·보고서를 보존**하는 것이다. 이미 세 독립 동작이 개작된 현재 사실을 반영한다. 이는 전체 앱 교체에 대한 새 사용자 승인이 아니며, 정정 전 assistant-ui 우선안이나 “아직 선택만 남음”을 현행 결론으로 유지하지 않는다. 추가 부분 반입·전체 포크는 파일/범위별 별도 구현 결정과 검증이 필요하다.
