# 긴 대화의 React 렌더와 탭을 넘긴 추가 지시

2026-11-24 macOS에서 표시창 성능 수정(#43)과 한글 Enter 수정(#45)을 결합한 `7b7eaf5`로 시험했다. 기준 renderer는 #43의 `0169e47` 번들이다. 같은 Electron 39.8.10 앱·명령 이력·창 크기(1,440×868)에서 각 번들의 React 루트에 Profiler를 감싸고 완료 CommandView 함수 진입 때 블록 ID를 기록했다. 대기와 스트리밍 각각 합성 입력 18개를 보내고 두 frame 후 실제 텍스트와 포커스를 확인했다. React 계측 비용이 들어간 이 실행은 지연·휠 비교에 포함하지 않았다.

| 18회 입력 중 관찰 | 기준 대기 | 후보 대기 | 기준 스트리밍 | 후보 스트리밍 |
| --- | ---: | ---: | ---: | ---: |
| React commit 수 | 19 | 19 | 41 | 39 |
| React render 시간 합, ms | 58.2 | 59.7 | 35.9 | 41.7 |
| commit 중 최대 render 시간, ms | 28.6 | 30.5 | 2.9 | 3.6 |
| 완료 CommandView 함수 진입 횟수 | 0 | 0 | 0 | 0 |

완료 카드는 대기·스트리밍에 이미 재렌더되지 않았다. 개선한 부분은 이전 비교기가 출력 문자열을 반복 직렬화하던 비용이다. React 시간은 각 상태에서 한 번 측정해 변화 방향을 판정하기 어렵다. #43의 별도 반복 표본에서 후보 스트리밍 입력 p95는 43.1–47.7ms, 최댓값은 50ms였다. 대기 p95 중앙값은 8.0→9.1ms였고 후보 대기·스트리밍 전체 표본에서 100ms 초과 입력 정지는 0건이었다. 사용자에게 긴 대화를 직접 입력시켜 체감 차이를 물은 기록은 없다.

기본 번들을 다시 빌드하고 `node scripts/verify-chat.ts --steer-tabs-only`로 합성 서버를 연결한 실제 Electron 검사를 실행했다. 첫 추가 지시는 합성 조합·반복 Enter로 최종 본문 ‘첫 추가 지시 각’을 한 번 보냈다. 이어 ‘대기 추가 지시’를 보내고 접수 응답 전에 새 탭에서 ‘둘째 탭 초안’을 작성했다. 응답을 허용하자 첫 탭의 두 지시만 접수됐고, 새 탭의 초안과 빈 사용자 이력이 보존됐다. stdio 기록에는 최초 시작 1회, 같은 thread·turn의 서로 다른 메시지 ID 2개, 중단 0회가 남았다. 실제 모델의 후속 행동은 이전 원장의 Native 관찰에, macOS 물리 키보드의 일반 전송은 #45에 각각 근거한다.

| 1차 미검증 기준 | 새 근거가 설명하는 범위 |
| --- | --- |
| AC-5 | 동일 환경 전후 입력·휠·스트리밍과 React commit·완료 카드 호출 관찰을 확보했다. 스트리밍 반복 계산 감소, 대기·휠에서 개선을 입증하지 못한 수치를 함께 기록했다. |
| AC-7 | #45의 실제 한글 한 번 전송 및 이번 계측에서 초점·값 보존과 완료 카드 재처리 0회를 확인했다. 긴 대화의 물리 키보드 커서 편집·붙여넣기 체감은 별도 관찰이 필요하다. |
| AC-10 | #43 입력 표본과 Working 중 이번 입력 관찰을 확보했다. Mint·좁은 창·모션 축소를 함께 적용한 긴 이력에서의 체감은 관찰하지 않았다. |
| AC-14 | 실제 Electron의 연속 추가 지시, 합성 IME Enter, 다른 탭 격리를 결합 후보에서 확인했다. 이전 원장의 실제 Native 행동·실패 시 원문 복원 및 #43 성능 표본과 함께 검토할 수 있다. |

기존 원장의 10/14는 당시 판정이다. 새 관찰로 AC-5와 AC-14의 검토 근거가 늘었으며, 후속 독립 판정은 아직 원장에 발행되지 않았다. 원시 commit별 시간과 두 Native 전송은 [관찰 원문](react-steer-observation.json)에 있다.
