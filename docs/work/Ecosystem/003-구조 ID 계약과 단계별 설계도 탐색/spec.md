# 구조 ID 계약과 단계별 설계도 탐색

## 요청과 목적

명세·코드·테스트·지도를 안정적인 구조 ID와 요구 ID로 연결하고 등록 누락·위반을 생성·빌드·저작 하네스에서 차단한다. 전체 구조에서 클릭으로 하위 책임을 탐색한다. 기존 002의 import 추출과 과거 검증 기록은 보존하며 새 계약의 수용 기준을 구분한다.

사용자의 직접 요청으로 접수했다. 요청 식별값은 work.json의 workflow.requestHash에 보존한다.

## 범위

변경 경로·표면·검증 명령과 커밋·게시 권한은 work.json의 workflow.authorization을 따른다. 범위 확대는 기존 권한으로 간주하지 않는다.

## 수용 기준

정의와 필수 여부의 정본은 work.json이다. 관련 기준: `AC-1`, `AC-2`, `AC-3`, `AC-4`, `AC-5`, `AC-6`.

## 결정과 열린 질문

작업 접수는 구현 완료가 아니다. 재개 시 같은 UUID와 현재 증거를 확인한다.

## 승인된 구현 시나리오

전체 구조에서 대화→세션→복원으로 들어가고 breadcrumb로 상위에 돌아온다. 해당 구조 ID로 요구·코드·테스트의 위치를 찾는다. 파일 이동은 위치 근거만 바꾸고 구조 ID는 유지한다. 선언을 빼거나 없는 ID를 쓰거나 허용되지 않은 의존성을 만들면 생성·check·저작 하네스가 실패한다. 현재 기존 50개 관리 모듈을 새 계약으로 이관한다.

등록 관계 검사와 행동 테스트 통과를 구분한다. 신규 의존성 설치, 서버 연동, 선택한 다른 저장소의 자동 분석, BoxBox 엔진 수정은 포함하지 않는다.

## 최종 검사 부수 회귀 수정 (phase6)

마지막 전체 검사에서 Native 보고서 취소의 persisted `interrupted`와 아직 제거되지 않은 `pending` 사이 경계가 드러났다. 이번 구조 작업의 전체 검사 신뢰성을 회복하기 위해 같은 허용 범위에서 terminal 중단 상태를 먼저 거부하도록 수정한다. 저장·생략 멱등성, 실행 중 중복 방지, 실패 재시도 책임은 유지한다. deferred judge와 실제 metadata 파일로 경계를 고정하고 수정 전 실패를 보존한다.

구조 사후 검사는 저작 중 generator가 변경돼도 같은 process의 import cache를 재사용하지 않도록 하네스 설치 위치의 checker를 새 subprocess에서 읽는다. 대상 root는 별도 인자로 전달하고 fixture 자체의 checker는 실행하지 않는다. 격리 설치본에서 generator의 실제 생성 동작을 변경하고 캐시된 검사 실패와 fresh 검사 수용을 Node/Bun 모두 대조한다. 부모가 이미 preload한 옛 하네스 함수까지 이번 자식 저작으로 교체되지는 않으므로 다음 fresh invocation의 실제 post 확인은 부모가 이어간다.
