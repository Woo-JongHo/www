# 중앙 지도 중심의 탐색과 선택 요약

## 요청과 목적

중앙 지도를 기본 작업 면으로 넓히고 프로젝트·대화 탐색과 노드 상세를 필요할 때만 연다. 선택 노드의 역할 요약은 지도 안에서 확인한다.

사용자의 직접 요청으로 접수했다. 요청 식별값은 work.json의 workflow.requestHash에 보존한다.

## 범위

변경 경로·표면·검증 명령과 커밋·게시 권한은 work.json의 workflow.authorization을 따른다. 범위 확대는 기존 권한으로 간주하지 않는다.

## 수용 기준

정의와 필수 여부의 정본은 work.json이다. 관련 기준: `CANVAS-SPACE`, `CANVAS-SELECT`, `CANVAS-CONTROL`.

## 결정과 열린 질문

사용자는 지도 안 선택 요약과 명시적 상세 열기를 선택했다. UI 배치의 미결정 사항은 없다. 구현·기능 검사는 수행했지만 최종 독립 검토는 모델 사용 한도로 차단돼 있으며, 업무 완료 판정과 구분한다. 재개 시 같은 UUID와 현재 증거를 확인한다.

## 관측과 합의

실제 앱 화면에서 프로젝트·저장 대화·노드 상세가 지도를 둘러싸고 있다. 사용자는 중앙 View가 메인이라고 지적했고, 선택 요약만 지도에 두고 상세는 눌러서 여는 방식을 선택했다. 기능·책임 지도를 이번 파일럿으로 삼고 기존 Chat·리포트·개념 안내의 기능은 유지한다.

## 시나리오

기본 지도에서 노드를 따라가고 요약으로 역할과 구성 수를 읽는다. 자세히 보기를 열 때만 상세가 나타나고 닫으면 선택 노드로 초점이 복귀한다. 필요하면 탐색을 열어 프로젝트·대화 목록을 확인한다. Chat 복귀 시 기존 탐색과 초안·읽기 위치가 남아야 한다. viewport 면적과 반응형·키보드 동작을 실제 Electron에서 확인한다.
