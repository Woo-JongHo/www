# 중앙 지도 중심의 UI

## 관측과 사용자 결정

실제 앱에서 왼쪽 프로젝트·저장 대화 목록과 오른쪽 상세, 여러 줄의 제목·ID·도구가 지도를 둘러싸고 있다. 사용자는 '지도에 선택 요약만 표시하고 자세한 내용은 눌러서 열기'를 선택했다. 기능·책임 지도를 이번 파일럿으로 바꾸고 개념 안내의 내용·Chat·리포트 기능은 보존한다.

## 최소 설계

- CANVAS-SPACE: 지도에서는 왼쪽을 64px 화면 전환 rail로 사용한다. 프로젝트·대화 목록은 탐색 버튼으로 원래 사이드바를 열 때 표시한다. Chat과 리포트로 돌아가면 기존 레이아웃을 유지한다. 제목·breadcrumb·검색/줌·관계 조작을 압축하고 snapshot 기술 메타데이터는 기본 읽기에서 숨긴다.
- CANVAS-SELECT: 지도 아래의 작은 선택 요약에 제목·역할·구성/코드 수를 표시한다. 노드 진입·검색·부모 선택·참조 강조가 닫힌 상세를 자동으로 열지 않는다. '자세히 보기'로만 열고 이미 열어둔 상세는 후속 탐색에 유지한다. 개념 안내의 '담당 코드 보기'는 명시적인 상세 요청으로 유지한다.
- CANVAS-CONTROL: 탐색 토글에 aria-expanded와 sidebar 연결을 둔다. rail의 아이콘에 이름·툴팁을 유지한다. 상세 닫기/Escape 뒤 선택 노드로 초점을 돌린다. DOM을 유지해 프로젝트·대화·지도 상태를 보존한다.

## 영향 경계

ecosystem-view가 탐색 열림과 선택/상세 상태를 소유한다. renderer의 화면 전환 버튼에는 rail용 label과 접근 가능한 이름만 더한다. CSS는 보이는 생태계에만 rail·압축 배치를 적용한다. 전역 프로젝트 선택·Native·IPC·저장 정책은 변경하지 않는다. 구조 snapshot은 공식 generator로 갱신한다. BoxBox project mode off를 유지한다.

## 검증

실제 Electron 1440×900에서 기본 nav 폭 64px, 상세 접힘, 지도 viewport 가로 90% 이상·main 높이 60% 이상을 확인한다. 노드/검색/참조 선택은 요약만 바꾸고 viewport 폭을 유지해야 한다. 사용자가 연 상세·탐색은 열고 닫을 수 있어야 한다. 기존 계층·검색·키보드·줌·팬·860/760px·지도/Chat 왕복 검사를 이어 수행한다. 집중 테스트·타입·소스 정책·빌드 후 공유 core의 읽기 전용 Opus 검토로 최종 소스를 판단한다.

## 작업 격리

사용자 지시에 따라 codex/canvas-focus worktree로 옮겼다. 원본의 Git-visible 작업 상태와 기존 작업 004를 포함한 미커밋 기반을 읽기 전용으로 복사했고 원본 파일은 되돌리거나 삭제하지 않았다. 기준 파일 manifest는 .www/worktree-baseline.json에 보존했다. 복사된 다른 작업의 변경은 이번 저작으로 분류하지 않는다. node_modules는 기존 설치를 읽는 링크이며 dist·작업 기록·증거·개발 설정은 worktree 안에서 독립 사용한다. 원본의 off 설정과 맞추기 위해 새 worktree에만 BoxBox project mode off를 적용했으며 전역 mode는 변경하지 않았다.

키보드 실패는 CDP helper의 virtual key/text 누락으로 확인했다. native HTML 버튼 입력을 보완한 뒤 실제 Electron의 Enter/Space 검사가 통과했다. 제품에 우회 키 핸들러는 추가하지 않았다. 실패와 재검증 근거는 verification.md에 보존한다.
