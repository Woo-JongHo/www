코드 기반 아키텍처 설계도와 계층형 Node 그래프

WWW 생태계의 기본 화면을 현재 TypeScript에서 추출한 코드 설계도로 바꿨다. 47개 모듈·105개 참조의 파일·행·원문과 계층별 방향 관계를 읽고 기존 수동 안내로 전환할 수 있다. 통합은 실제 코드와 화면 캡처를 읽고 확장 입력의 집중 검사·전체 검사를 통과시켰다. BoxBox 미해결과 수정 호스트의 권한 오류, 확장 입력의 GUI·추가 Chat 검사 및 Opus 인증 실패가 남아 업무 완료를 보류한다.

생태계를 열면 수동으로 정의한 고정 구조 안내가 표시되어 현재 코드의 import 근거를 읽을 수 없었다. 생태계를 열면 코드 기반 계층 개요가 먼저 표시된다. 파일 검색·계층 필터·모듈 선택에서 실제 참조와 원문 근거로 이동하며, 수동 생태계 안내는 별도 탭에서 읽는다. 현재 구현의 기능 관찰과 미완료 검증을 구분해 기록했다.

기록된 변경

  • TypeScript AST 분석·결정적 생성 JSON과 현재성 검사, 빌드 전 생성을 연결했다.
  • 계층 개요·선택 모듈 참조·상세 근거·검색·필터·빈 결과·배율·fit·키보드·드래그와 좁은 창 배치를 구현했다.
  • 코드 설계도 문서와 제품·구조·개발·생태계 정본을 갱신했고 기존 Chat/sidebar 변경을 보존했다.
  • 검사 입력을 생성 자료·CSS·전체 scripts/test와 관련 문서까지 확장하고 공식 verify의 실제 검사·분리 실행 원문을 연결했다. 통합에서 제품 코드를 추가 변경하지 않았다.

기록에 남은 주요 선택

  • 자동 import 참조와 수동으로 설명한 IPC/JSON-RPC 실행 흐름을 구분했다. 그래프를 실제 호출 tracing으로 설명하지 않는다.
  • 입력 범위가 다른 첫 호스트 GUI 통과는 과거 관찰로 보존했다. 같은 코드 내용이라는 이유로 현재 입력의 성공으로 승격하지 않았다.
  • 권한 오류로 실패한 공식 수정 실행을 기록하고 하네스 밖 제품 저작·자동 정렬로 우회하지 않았다.
  • Opus 인증 실패에는 quota 소진 근거가 없어 Terra 대체를 실행하지 않았다.

확인하지 못한 범위

  • BoxBox 미정렬 22건·REFUSE 24건이 남아 첫 저작 하네스와 공식 수정 하네스는 통과하지 않았다. renderer REFUSE 20건은 사전부터 존재한다.
  • 수정용 실제 자식 Codex가 in-process app-server 초기화의 권한 오류로 실행되지 않았다.
  • 첫 호스트 Electron 20개 관찰과 생태계 보존 검사는 당시 입력에서 통과했다. 확장 입력의 architecture/ecosystem 및 추가 Chat probe는 호스트에서 다시 실행해야 한다.
  • 정책의 읽기 전용 Opus 요청은 OAuth 만료로 exit 1·not_run·observedModel=null이었다. 필수 독립 검토를 충족하지 못했다.
  • 시각 확인은 보존된 설계도 네 장과 대화 한 장의 범위다. 모든 연결선 상태·스크린리더·실제 Native 변경 왕복을 확인하지 않았다.
  • Mac mini 분리 tmux·서버 PPID 1·Codex PID·로그·종료를 호스트 원문으로 확인했다. 노트북 실제 덮개 닫기나 재부팅 후 자동 복구를 시험하지 않았다.

남은 일과 해소 행동

  • 호스트에서 integration-repair.json의 같은 요청·권한과 새 eventId로 공식 수정 하네스를 실행해 구조적 미해결을 처리한다.
  • 수정 후 Bun PATH를 보완한 동일 호스트에서 전체 검사와 architecture·ecosystem·Chat GUI probe를 순차 실행하고 새 화면을 직접 읽는다.
  • Opus 인증 복구 뒤 공식 공유 review를 실행하고 실제 지적을 해결·재검증한다. 모든 필수 기준과 현재 검토가 충족할 때만 report-complete를 실행한다.
  • 상세 재개 절차는 .www/background/architecture/needs-host-verification.md, 검증과 한계는 같은 작업 verification.md#integration-1에서 확인한다.
