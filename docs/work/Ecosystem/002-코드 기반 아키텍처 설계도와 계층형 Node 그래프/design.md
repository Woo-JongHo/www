# 코드 기반 아키텍처 설계도

## 통합 3회차의 판정

제품 소스·생성 자료·검사 입력은 2회차 이후 바뀌지 않았다. 공유 status로 현재 입력 digest `08d55dbb47575a56cbac1db53a9bf5733d7bf9a1c793b7fb771b272560f9ddf7`와 문서 검토의 유효성을 확인했다. 최신 외부 architecture는 통과했으나 check·ecosystem은 실패했고 Chat 검사는 실행되지 않았다. ecosystem의 Bun 경로 누락은 원문으로 확인했다. 최신 check는 출력 내용 대신 길이·해시만 보존되어 이번 실패의 세부 원인을 새로 확정하지 않는다. 올바른 PATH에서 이미 통과한 같은 소스의 집중 검사·전체 check는 재실행하지 않는다.

1회차 수정 하네스의 Codex 초기화 EPERM과 필수 Opus의 OAuth 인증 만료가 해결됐다는 새 근거가 없다. 동일한 실패 호출을 반복하거나 하네스 밖에서 제품을 저작하지 않는다. 기존 수정 계획은 유효하며, 호스트가 공식 build를 실제 수행하고 Bun PATH를 Node 프로세스 내부에 지정한 검증과 인증 복구 후 검토를 이어야 한다. 현재 자동 회수 번호는 3이며 추가 자동 회수를 보장하지 않는다. 정확한 미완료와 호스트 실행 요청은 사적 `needs-host-verification.md`에 기록한다.

최신 네 스크린샷을 직접 읽어 계층·방향선·보이는 레이블과 좁은 창 근거 접근을 확인했다. 초기 개요의 맨 아래 계층은 스크롤이 필요하며 모든 모듈·연결선과 스크린리더 접근성을 검증한 것은 아니다. 인덱스 0만 검사하는 기존 연결선 테스트의 보강도 여전히 미완료다. 전체 수용을 보류하고 기존 독립 검토 실패를 그대로 보존한다.

## 통합 2회차의 판정과 호스트 실행 경계

제품 소스·생성 자료·검사 입력은 1회차 이후 그대로이며 현재 입력 digest는 `08d55dbb47575a56cbac1db53a9bf5733d7bf9a1c793b7fb771b272560f9ddf7`이다. 확장 입력에서 외부 architecture 검사는 실제 Electron으로 통과했다. 외부 check·ecosystem은 다시 `spawn bun ENOENT`였고, Bun 경로를 명시한 진단 및 공식 verify의 check는 통과했다. 실행 중인 호스트 셸의 환경은 스크립트 파일의 export 문구만 수정해도 바뀌지 않는다. 재호스트 실행은 새 프로세스 안에서 `process.env.PATH`를 명시하고 실제 Bun 경로를 확인해야 한다.

1회차의 수정 하네스는 Codex 초기화 EPERM으로 저작 전에 종료했다. 같은 환경에서 같은 실패를 반복하거나 통합자가 제품 코드를 직접 고치지 않는다. 기존 `integration-repair.json`의 같은 권한·요청과 새 eventId를 사용하는 공식 build를 호스트에서 실행해야 하며, 수정 범위·BoxBox 절차·연결선 검사 보강은 아래 1회차 계획을 유지한다. 이후 현재 소스의 순차 GUI·Chat 검사와 인증 복구 후 필수 Opus 검토가 필요하다. 구체적 재개 절차는 사적 `needs-host-verification.md`에 남긴다. 최종 수용은 보류한다.

## 통합 1회차의 공식 수정 범위

2026-11-13 통합 검증에서 첫 저작 하네스의 BoxBox 사후 실패를 확인했다. 같은 requestId·request·approval을 재사용한 공식 build가 아래 파일의 실제 미해결만 수정한다. 별도 저작 agent·중첩 하네스·새 접수는 하지 않는다.

- `src/architecture.ts`, `scripts/generate-architecture.ts`, `scripts/verify-architecture.ts`, `test/architecture.test.ts`의 미정렬 그룹과 `src/ecosystem-view.tsx`의 네 REFUSE 그룹을 기능 책임에 맞게 구조적으로 간결화한다. 자동 align·formatter, 승인되지 않은 수동 열 정렬, 무의미한 빈 줄·주석으로 그룹을 끊는 우회는 하지 않는다. 파일별 guide의 역할·경계에 따라 바꾸고 사후 결과를 실제 확인한다.
- `src/renderer.tsx`에는 기준 diff부터 있던 Chat/sidebar 작성의 REFUSE 20건이 있다. 동작과 기존 변경을 보존한다. 이번 하네스에서 파일 전체를 정리하려고 관련 없는 Chat 저작을 다시 쓰지 않는다. 현재 범위 안의 작은 구조 변경으로 해결할 수 있는지 확인하되, 불가능하면 원래 실패와 현재 한계를 명시한다.
- 레이아웃 검사는 인덱스 0만 확인하던 검증을 보강해 실제 표시 순서의 연결선과 개요 경로도 확인한다. 기존 계약·시나리오를 약화하지 않는다.
- 변경 후 `src/architecture.generated.json`을 공식 생성기로 갱신한다. 생성 자료의 수기 수정·이전 snapshot fallback을 금지한다. 제품 UI의 계층·탐색·동작 요구는 그대로 유지한다.

첫 외부 검사는 호스트 PATH에서 `bun`을 찾지 못해 check·ecosystem이 실패했다. 현재 통합 셸에서는 `npm run check`가 통과했고 실제 Bun 경로는 `/Users/woojongho/.bun/bin/bun`이다. 환경 문제를 제품 fallback으로 숨기지 않는다. 재호스트 실행은 해당 경로를 PATH에 포함해야 한다.

검사 입력은 공유 inputs action으로 `src`·`scripts`·`test`, 생성 자료·CSS, 소스 정책·설정·관련 현행 문서까지 확장했다. reports·작업 기록·사적 원문 출력은 제외한다. 첫 외부 통과는 과거 관찰로 보존하며 입력 범위 변경 이후 현재 통과로 승격하지 않는다.

## 목표와 현재 차이

기존 src/ecosystem.ts는 수동으로 정의한 앱·개발·기록·후속 방향 안내다. 좌표를 고정한 큰 SVG와 곡선 연결을 제공하지만 코드 의존성을 추출하지 않는다. 새 기본 화면은 현재 소스 모듈의 계층과 방향을 읽는 설계도다. 기존 안내는 보조 보기로 보존한다.

## 코드 근거

TypeScript compiler API로 현재 src 및 개발 절차 핵심 모듈의 정적 import·export를 파싱한다. 파일 경로, 행 번호, 실제 구문과 내용 식별을 담은 재현 가능한 snapshot을 빌드 시 생성한다. 빌드가 실패한 상태를 이전 분석의 성공으로 숨기지 않는다. snapshot은 생성 시각만 바뀌는 불안정한 결과보다 내용 hash를 사용하고 같은 소스의 출력은 결정적이어야 한다.

노드를 런타임 경계와 역할로 묶는다. 화면·투영, preload와 공유 계약, Electron main·Native 통신, 개발 workflow·검증과 기록이 후보이며 실제 파일과 imports를 확인해 정한다. 전체 파일 노출로 처음부터 연결이 얽히지 않게 개요와 세부 노출을 분리한다. 외부 라이브러리와 미구현 미래 노드는 실제 로컬 모듈처럼 표시하지 않는다. IPC·JSON-RPC 흐름을 설명할 경우 근거 파일·행과 수동 설명임을 표시한다.

현재 코드를 설명하는 docs/CODE_BLUEPRINT.md를 작성한다. 계층·모듈 책임, 주요 실행 흐름, 타입/런타임 의존성과 권한 경계, 그래프 재생성 방법, 분석 한계를 담고 코드와 직접 연결한다.

## 화면

사용자의 선택은 아키텍처 설계도다. 작은 고정폭 기술 라벨, 절제된 계층 색상, 충분한 여백, 균일한 모듈 노드, 구획 제목, 직각 중심의 방향 연결선, 범례와 분석 범위 표시를 사용한다. 장식적인 글로우나 임의의 force layout을 사용하지 않는다. 처음 열 때 뷰포트에 맞추며 레이블이 읽히지 않는 축소를 피한다. 개요의 연결을 묶고 선택한 모듈에 연결된 간선을 강조한다.

검색·계층 필터·빈 결과·초기화, 노드 상세·입출력 관계·파일/행 출처, 확대·축소·전체 보기·드래그 이동, Tab/Enter/Space 키보드 탐색을 제공한다. 기존 생태계 안내를 명확한 보조 탭으로 보존한다. 낮은 높이와 좁은 창에서 툴바나 상세 내용에 도달할 수 있어야 한다. 선택한 모듈과 보기가 바뀌어도 그래프 바깥의 Chat 상태를 건드리지 않는다.

## 책임과 영향 파일

빌드 전 분석은 scripts/generate-architecture.ts, 순수 모델·탐색·레이아웃은 src/architecture.ts, 생성 자료는 src/architecture.generated.json, 화면은 src/ecosystem-view.tsx, 전용 스타일은 src/ecosystem.css가 소유한다. build.ts와 src/index.html은 생성·스타일 로딩을 연결한다. 기존 src/ecosystem.ts 데이터는 생태계 안내에 그대로 재사용한다.

src/renderer.tsx의 변경은 사이드바 이름 및 기존 내장 probe의 새 화면 대응에 한정한다. 기존 미커밋 Chat 변경을 보존한다. 실제 Electron 검증은 scripts/verify-architecture.ts 및 필요한 기존 생태계 probe 수정으로 수행한다. 기존 검사를 약화하거나 삭제하지 않는다.

## 실행 소유권

저작 Codex는 부모가 시작한 공식 typed workflow 하네스의 자식이다. 동일 작업을 새로 접수하거나 중첩 저작 하네스·다른 저작 에이전트를 시작하지 않는다. 부모가 사전/사후 BoxBox·타입 검사, 검증 기록·독립 검토·보고서를 연결한다. 자식은 이 문서·spec.md·work.json을 읽고 선언된 writes 안에서 구현·집중 검사·같은 범위의 실패 수정을 책임진다. 부모와 다른 변경자가 같은 저장소를 사용할 수 있으며 타인의 변경을 되돌리지 않는다.

파일별 BoxBox guide/check의 authoring context를 실제 읽고 적용한다. 기존 오류와 승인되지 않은 형태를 구분하고 자동 align·formatter나 타입 우회로 검사를 숨기지 않는다. 독립 검토는 정책의 읽기 전용 Opus이며 부모가 공유 core로 실행한다. 자식이 done 판정을 쓰지 않는다.
