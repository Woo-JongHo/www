# 사람이 읽는 구조 지도와 책임 설명

## 목적과 최소 설계

현재 화면은 계층과 import를 동시에 그리고 같은 열의 출발·도착 포트를 공유한다. 상세에는 하위 구성 목록이 없고 정본 설명도 제목을 되풀이한다. 구조 ID·부모·실제 import 추출은 유지하면서 표현과 설명을 개선한다.

- MAP-READ: 구성 보기와 코드 의존 보기를 분리한다. 의존선은 오른쪽 출발·왼쪽 도착, 간선별 독립 통로와 포트를 사용한다. 번호를 관계 목록과 연결하고 특정 책임을 골라 참조를 좁힌다. 코드 import는 데이터 전달이나 실행 순서로 설명하지 않는다.
- MAP-NODE: 부모와 하위 노드는 폭 360px·높이 112px로 통일한다. 제목·역할 요약·구성 개수를 같은 위치에 두고 원문은 상세에서 읽는다. 화면이 부족하면 100% 크기를 유지하며 내부 스크롤한다. 상세는 360px 오른쪽 패널로 열고 닫을 수 있으며 노드 규격을 줄이지 않는다. 좁은 창에서는 지도 아래로 배치한다.
- MAP-DETAIL: 정본 description을 실제 구현 책임에 맞춰 작성한다. 역할, 하위 구성과 설명, 하위 포함 담당 코드·명세 수, 들어오는/나가는 실제 참조를 먼저 보여준다. 원문 명세·구현·검증 선언은 접을 수 있는 근거 영역에 보존한다. 직접 근거와 하위 포함 집계는 구분한다.
- MAP-FLOW: 기존 단일 클릭 branch 진입·leaf 선택, breadcrumb·전역 검색·키보드·줌·팬과 채팅 상태 보존을 유지한다. 새 필터와 상세 패널도 키보드로 조작한다.

## 데이터와 상태

architecture-tree가 하위 범위 근거 집계와 균일 배치·방향별 통로를 계산한다. view는 보기 모드와 참조 강조 대상, 상세 열림을 소유한다. 정본 structure.json의 설명만 갱신하고 snapshot은 공식 생성기로 만든다. 프로세스·IPC·Native 권한 변경은 없다.

## 검증과 위험

고밀도 간선·양방향·24개 이상 index에서 포트와 노드 비관통을 순수 검사한다. 하위 집계의 직접/후손·중복 테스트·범위 밖 참조를 fixture로 확인한다. 실제 Electron에서는 대화 세션의 3개 구성과 코드 경로, 의존 보기·대상 필터·상세 닫기, 긴 노드 제목·좁은 화면·검색·키보드·대화 보존을 확인한다. 스크롤을 요구하는 지도는 전체가 한 화면에 들어간다고 판정하지 않는다. BoxBox project mode는 현재 off로 관측됐으며 source/strict/구조 검사는 유지한다. 최종 판단은 공유 core의 읽기 전용 Opus 검토를 따른다.
