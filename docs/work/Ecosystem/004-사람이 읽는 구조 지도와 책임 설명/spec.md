# 사람이 읽는 구조 지도와 책임 설명

## 요청과 목적

구성 관계와 코드 의존 관계를 구분하고 동일 규격 노드와 역할·책임·하위 구성·코드 근거 설명을 제공한다.

사용자의 직접 요청으로 접수했다. 요청 식별값은 work.json의 workflow.requestHash에 보존한다.

## 범위

변경 경로·표면·검증 명령과 커밋·게시 권한은 work.json의 workflow.authorization을 따른다. 범위 확대는 기존 권한으로 간주하지 않는다.

## 수용 기준

정의와 필수 여부의 정본은 work.json이다. 관련 기준: `MAP-READ`, `MAP-NODE`, `MAP-DETAIL`, `MAP-FLOW`.

## 결정과 열린 질문

작업 접수는 구현 완료가 아니다. 재개 시 같은 UUID와 현재 증거를 확인한다.

## 사용자 시나리오

1. 생태계에서 구성 지도를 열고 같은 규격의 노드로 전체 책임을 비교한다.
2. 대화 → 대화 세션을 선택해 역할, 세 하위 구성과 설명, 담당 파일을 확인하고 구성요소로 내려간다.
3. 코드 의존 보기에서 특정 책임을 강조해 참조하는/참조받는 방향과 번호별 원문 근거를 읽는다.
4. 검색·breadcrumb·키보드와 좁은 창 스크롤로 같은 정보를 찾고 대화로 복귀해 초안이 남는지 확인한다.

## 제외 범위와 판단

소스 자동 편집·Canvas 저장·실시간 호출 추적·선택 프로젝트 분석은 추가하지 않는다. 역할 설명은 현재 구현과 문서에 근거한 사람이 작성한 정본이며 정적 import를 데이터 전달·실행 순서로 단정하지 않는다. 사용자 기존 합의대로 같은 브랜치에서 구현·검증한다. BoxBox project mode off를 유지하며 별도 형식 승인을 만들어 넣지 않는다.
