01결론과 상태

이슈 #4 응답 중 추가 지시 차단 해결안 게시

최근 2,000개 채팅 이벤트에서 최초 연결 이벤트가 밀려나면 응답이 계속 표시되는 중에도 추가 지시가 차단될 수 있다. 현재 연결 상태를 채팅 이력과 별도로 관리하는 해결안과 검증 기준을 GitHub 이슈 #4에 게시했다. 코드 수정이나 수정 후 검증은 확인되지 않았다.

응답이 계속 표시되는데도 추가 지시가 막히는 문제의 해결안을 이슈에 남기는 작업이었다. Native 답변은 로컬에서 기록한 재현 조건을 바탕으로, 연결 상태를 채팅 이력과 분리하는 제안을 이슈 #4에 게시했다고 보고했다. 제공된 자료에는 댓글 게시 명령의 종료 코드 0과 댓글 링크가 있지만, 실제 제보 세션의 원인이나 수정 후 동작은 확인되지 않았다. 구현 뒤에는 실제 Native 창에서 스트리밍 중 보낸 추가 지시가 같은 턴에 접수되는지 확인해야 한다.

저장 당시 업무 상태차단 사항 남음

다음 행동 현재 연결 상태를 채팅 이력과 별도로 전달하고, 해당 세션과 연결 세대의 상태만 적용하도록 구현한다.

남은 차단 사항 Native 실행 요약이며 업무 수용·독립 검토는 별도입니다.

저장 당시 기준 중 1개가 실패·차단·미검증 또는 미확인으로 남았습니다.

02문제와 접근

시작점

로컬 재현 기록에서는 응답이 스트리밍되는 중 최초 연결 이벤트가 최근 2,000개 범위 밖으로 밀려나자, 응답은 계속 표시됐지만 입력창이 ‘연결 미확인’을 표시해 추가 지시를 차단했다.

접근과 결과

같은 상황에서도 연결과 현재 턴이 유효하면 추가 지시를 보낼 수 있도록 설계안을 게시했다. 제안이 구현됐거나 사용자 동작이 바뀌었다는 근거는 없다.

중요한 선택과 그 이유

길이가 제한된 채팅 이력에서 연결 상태를 재계산하면 최초 연결 이벤트가 밀려날 때 현재 연결 상태를 잃을 수 있다.

선택 네이티브 세션이 현재 연결 상태를 별도로 전달하고, 수신 측은 세션·선택·연결 세대가 일치하는 최신 상태만 적용하도록 제안했다. 추가 지시는 확인된 연결과 현재 실행 중인 턴을 모두 요구한다.

판단 근거 게시 댓글에 기록된 로컬 재현에서는 응답이 표시된 상태에서도 최초 연결 이벤트가 사라지자 추가 지시가 차단됐다.

함께 검토한 대안

  • 최근 채팅 이력에서 연결 상태를 재계산하는 기존 방식
  • 응답 조각 수신을 연결 확인으로 간주하는 방식

감수한 점 이력 보관 한도를 유지하면서 연결 상태가 누락되거나 오래된 이벤트로 덮이는 일을 막는 대신, 별도의 상태 전달과 세대 확인이 필요하다.

함께 기록된 선택

  • 최근 2,000개 채팅 이벤트 보관 한도는 유지하고, 현재 연결 상태는 네이티브 세션이 별도로 관리하도록 제안했다.
  • 응답 조각 수신만으로 연결을 확인하지 않고, 해당 세션의 확인된 연결과 현재 대화에서 실행 중인 턴을 함께 요구하도록 제안했다.

남은 일과 해소 행동

이력 한도를 유지하면서 추가 지시가 확인된 연결과 현재 실행 중인 턴을 모두 요구하고, 기존 서버 측 검사는 유지된다.
영향
오래된 연결 이벤트가 이력에서 밀려나도 유효한 연결에서 추가 지시를 보낼 수 있게 한다.

이력 한도 초과와 실제 연결 종료를 검증하고, Native 창에서 탭 전환·재연결 후 스트리밍 중 추가 지시를 보낸다.

담당
미지정
해소 조건
유효한 연결에서는 같은 턴에 지시가 접수되고, 연결이 끊기면 즉시 차단되며, 이전 연결의 늦은 이벤트가 차단을 해제하지 않는다.
영향
추가 지시가 잘못 차단되는 문제와 끊어진 연결이 잘못 허용되는 문제를 함께 점검한다.

기존 서술에 기록된 남은 일

  • 연결 상태 분리를 구현한 뒤 이력 한도 초과, 실제 연결 종료, 탭 전환 및 재연결 상황에서 추가 지시가 기대대로 동작하는지 검증한다.

담당·해소 조건·영향은 별도로 기록되지 않았습니다.
