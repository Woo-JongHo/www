01결론과 상태

BoxBox 미정렬 그룹이 자동 수정되지 않은 이유

미정렬 검출과 파일 쓰기 허용은 별개다. Native 답변에 따르면 766개 그룹은 정렬안을 계산했지만 일치하는 승인 규칙이 없었고, 별도 489개 그룹은 엔진이 편집 안전 조건을 위반한다고 판정해 정렬안을 거부했다. 제품 `src/`의 미정렬 113개는 승인 규칙이 없는 사례로, 현재 규칙으로 바로 적용할 수 있는 그룹은 0개로 보고됐다.

사용자는 BoxBox가 미정렬을 찾고도 왜 자동으로 정렬하지 못하는지 물었다. Native 답변은 정렬안을 계산했지만 승인 규칙이 없는 766개와, 편집 안전 검사에서 거부된 별도 489개를 구분하고 코드 사례로 차이를 설명했다. 제공 기록에는 기존 정렬 계획과 소스 행을 조회한 명령의 종료 상태가 있지만 출력이 없어 수치나 거부 위치를 별도로 재확인하지는 못했다. 다음 단계는 승인 누락과 안전 검사 거부를 나누어, 전자는 승인 범위를 검토하고 후자는 거부된 편집을 특정하는 것이다.

02문제와 접근

시작점

BoxBox 정렬 결과를 본 사용자는 그룹이 미정렬로 표시됐는데도 왜 자동으로 수정되지 않았는지 알기 어려웠다.

접근과 결과

같은 정렬 결과를 볼 때 `FIXABLE`이지만 `no matching convention`이 나온 경우와, 엔진이 `REFUSE`한 경우를 구분할 수 있게 됐다. 이번 응답에서 파일이나 규칙을 바꾸거나 정렬을 다시 적용한 기록은 없다.

03변경 결과

요구와 결과

아래는 작성자의 요구·결과 설명입니다. 연결 근거의 서술은 별도의 검사 판정을 새로 부여하지 않습니다.

항목바뀐 동작근거와 한계
미정렬로 표시되는데도 BoxBox가 왜 정렬하지 못하는지 자세히 설명한다.정렬안 계산, 규칙 승인, 편집 안전 판정을 구분했다. 승인 규칙은 언어나 파일 전체가 아니라 문법 위치·행 형태·맞출 열 조합에 따라 적용되며, `align` 모드도 그 범위를 넓히지 않는다고 설명했다.Native 답변은 `src/shared.ts`의 승인 불일치, `scripts/setup-ci.ts`의 과거 적용 사례, `src/projection.ts`의 다른 문법 위치, `src/native-session.ts`의 안전 검사 거부를 비교했다.

규칙 추가, 엔진 수정, 정렬 재실행은 기록되지 않았다.

영향

기존 서술에 기록된 남은 일

  • 승인 규칙이 없는 그룹은 문법 위치·행 형태·정렬 열 조합별로 승인할 대상을 검토한다.
  • `REFUSE` 그룹은 대표 사례에서 어떤 편집이 안전 조건에 걸렸는지 먼저 확인한다.

담당·해소 조건·영향은 별도로 기록되지 않았습니다.
