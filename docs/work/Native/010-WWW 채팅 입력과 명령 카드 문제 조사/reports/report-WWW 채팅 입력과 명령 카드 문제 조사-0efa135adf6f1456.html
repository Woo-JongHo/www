01결론과 상태

WWW 채팅 입력과 명령 카드 문제 조사

WWW 채팅의 이미지 붙여넣기 미지원과 명령 카드의 혼합 출력 처리 방식을 확인했습니다. Enter 전송은 입력 핸들러의 한글 조합 관련 차단 조건을 확인했지만, 실제 앱에서 조합을 끝낸 뒤 첫 Enter가 누락되는 현상은 재현하지 못했습니다. 이번 작업은 조사이며 수정은 보고되지 않았습니다.

사용자가 WWW 채팅에서 이미지가 붙지 않고, 일부 명령 카드가 읽기 어려우며, Enter를 두 번 눌러야 메시지가 전송된다고 보고해 세 동작을 조사했습니다. 입력·전송 코드는 텍스트 전용이었고, 명령 카드에서는 단독 JSON과 혼합 출력의 표시 차이가 재현됐다고 Native 답변이 보고했습니다. Enter는 핸들러 수준에서 일반 입력과 한글 조합 관련 차단을 확인했지만, 실제 앱에서 조합 종료 후 첫 키가 누락되는 현상은 재현하지 못했습니다. 수정은 보고되지 않았으며, Enter 증상을 실제 앱에서 재현해 차단 조건과 대조하는 것이 다음 단계입니다.

02문제와 접근

시작점

사용자는 채팅에 이미지를 붙여넣으려 했으나 첨부되지 않았고, 명령 카드에서 단독 JSON은 읽기 쉬웠지만 여러 줄 명령이나 혼합 출력은 읽기 어려웠다고 보고했습니다. 메시지를 보내려면 Enter를 두 번 눌러야 하는 경우도 보고했습니다.

접근과 결과

같은 동작을 개선하는 변경은 보고되지 않았습니다. 이미지 붙여넣기는 현재 텍스트 전용 입력·전송 경로에서 지원되지 않고, 명령 카드는 JSON 뒤에 다른 출력이 붙으면 전체를 원문으로 표시합니다. 실제 앱에서 Enter를 두 번 눌러야 하는 조건은 여전히 미확인입니다.

중요한 선택과 그 이유

입력 핸들러의 조합 차단으로 실제 앱의 Enter 두 번 전송 현상까지 설명할 수 있는가

선택 확인된 핸들러 동작만 보고하고 실제 앱 증상의 원인은 미확인으로 남겼습니다.

판단 근거 모의 이벤트로 차단 조건은 확인했지만 실제 앱의 첫 Enter 누락은 재현되지 않았습니다.

함께 기록된 선택

  • 앞서 안내한 ⌘V와 드래그 첨부가 현재 WWW 채팅 화면에는 적용되지 않는다고 정정했습니다.
  • 입력 핸들러에서 확인한 한글 조합 중 전송 차단과 사용자가 실제 앱에서 보고한 첫 Enter 누락을 같은 원인으로 단정하지 않았습니다.
