01결론과 상태

대시보드 ‘검토 필요’ 34건의 분류 점검

Native 조사 기록에 따르면, 로컬 WWW 작업 원장에서 대시보드의 ‘검토 필요’ 분류에 들어가는 작업은 34건이었지만 다음 단계가 리뷰로 기록된 작업은 Chat/013과 Workflow/016 두 건이었다. 대시보드는 리뷰 여부를 따로 구분하지 않고 `verifying` 상태 전체를 ‘검토 필요’로 표시한다.

사용자는 대시보드에 검토할 작업이 많아 보이는 이유와 표시가 현재 현황에 맞는지를 물었다. Native 조사는 대시보드 분류 코드와 같은 수집기로 읽은 로컬 원장을 대조해, ‘검토 필요’에 해당하는 34건 중 다음 단계가 리뷰로 기록된 작업은 2건이라고 보고했다. 34건은 `verifying` 상태를 묶은 수치이므로 실제 리뷰 대기 건수로 그대로 읽으면 안 된다. 명령 기록이 일부 잘려 있고 작업별 증거의 최신성은 확인하지 않았으므로, 리뷰를 시작할 때는 해당 두 건의 원장과 검증 증거를 먼저 확인하는 것이 좋다.

저장 당시 업무 상태차단 사항 남음

다음 행동 Chat/013과 Workflow/016의 다음 단계와 검증 증거를 최신 소스 기준으로 확인한다.

남은 차단 사항 Native 실행 요약이며 업무 수용·독립 검토는 별도입니다.

저장 당시 기준 중 1개가 실패·차단·미검증 또는 미확인으로 남았습니다.

02문제와 접근

시작점

대시보드에서 ‘검토 필요’ 목록을 보면, 다음 단계가 다른 작업도 한데 묶여 있어 실제 리뷰 대기 건수를 구분하기 어려웠다.

접근과 결과

같은 목록의 분류 기준을 로컬 원장과 대조해, 표시 대상 34건과 원장상 리뷰 대상 2건의 차이를 설명했다. 대시보드나 원장의 변경은 보고되지 않았다.

중요한 선택과 그 이유

‘검토 필요’라는 라벨이 실제 리뷰 대기 건수처럼 보인다.

선택 두 기준의 건수를 함께 제시하고 실제 리뷰 대기 규모를 설명할 때는 원장상 리뷰 2건을 사용했다.

판단 근거 화면은 카드의 `verifying` 상태를 사용하지만, 원장은 작업별 다음 단계를 별도로 기록한다.

함께 검토한 대안

  • 대시보드 상태 기준으로 해당 목록의 전체 건수를 읽는다.
  • 원장에 기록된 다음 단계 기준으로 리뷰 대상 건수를 읽는다.

감수한 점 다음 단계 기준은 리뷰 대상을 구분하는 데 유용하지만, 원장 기록이 최신인지는 별도 확인이 필요하다.

함께 기록된 선택

  • 대시보드에 표시되는 건수와 원장에 다음 단계가 리뷰로 기록된 건수를 분리해 답했다.

03변경 결과

기록된 변경

  • 표시 대상 34건을 원장에 기록된 다음 단계별로 나눴다. 검증 실행 17건, 다음 단계가 없는 Native 실행 요약 11건, 구현·수정 3건, 리뷰 2건, 완료 처리 1건이었다.

항목바뀐 동작근거와 한계
대시보드의 ‘검토 필요’ 표시가 로컬 작업 현황과 맞는지 확인한다.대시보드 분류 기준으로는 34건이지만, 그 기준은 리뷰 대기만 세는 것이 아니라 `verifying` 전체를 묶는다.Native 답변에 인용된 분류 코드와 같은 수집기를 사용한 로컬 원장 집계.

집계 범위는 로컬 WWW 원장이며 화면을 직접 확인한 기록은 없다.

실제로 리뷰가 다음 단계인 작업이 몇 건인지 확인한다.원장에 리뷰로 기록된 작업은 Chat/013과 Workflow/016 두 건이었다.Native 답변의 `workflow.nextAction`별 집계와 작업 식별자.

원장에 기록된 다음 단계 기준이며, 각 작업의 검증 증거가 최신인지 확인하지 않았다.

확인 범위와 한계

확인하지 못한 범위

  • 집계는 조사 당시 로컬 WWW 원장 기준이다. 각 작업의 검증 증거가 최신 소스에도 유효한지는 확인하지 않았다.
  • 제공 기록은 일부 잘려 있어 명령 전문과 원시 출력으로 집계 결과를 독립적으로 확인할 수 없다. 이 보고서를 작성하면서 명령을 다시 실행하지 않았다.

    docs/work/*/*/work.json
