# 업무를 시작하고 이어가는 WWW 진입점 연구

확인일: 2026-11-15. 대상: 개인 업무관리와 로컬 AI 작업을 함께 하는 WWW. 이 문서는 공식 문서·현행 코드에 근거한 연구 및 설계 제안이며 제품 구현, 사용자 승인, 사용성 시험 통과를 뜻하지 않는다. 관련 기준의 정본은 같은 폴더 `work.json`의 R1–R3이다.

## 결론

기본 화면은 ‘오늘’, 기본 탐색은 아이콘과 이름이 함께 있는 **단일 사이드바**, 축소 상태는 **아이콘 바**를 권고한다. 중앙에는 지금 할 일을, 오른쪽에는 명시적으로 연 상세를 둔다. VS Code의 별도 Activity Bar와 탐색 열을 모두 상시 복제하는 안보다 개인 업무 목록의 공간과 메뉴 발견 가능성을 우선한다.

Linear에서 개인 업무를 추려 보여 주는 방식과 즐겨찾기를, VS Code에서 패널의 독립 제어·복원·빠른 이동을, Figma에서 선택 대상과 속성의 명확한 연결을 채택한다. 각 제품의 기능이 WWW에서도 더 좋다는 실측 결과는 없다. 세 패턴의 결합 비용을 제한하고 대표 여정으로 검증하는 것이 ‘장점만 가져오기’의 실행 가능한 의미다.

이전 대화의 ‘52px 아이콘 바 + 240px 탐색 패널’은 확정안이 아니며 이번 비교에서는 기본안에서 제외한다. 추가 라벨을 기본으로 보여 주는 Figma를 아이콘 전용 기본의 근거로 사용하지 않는다. 오른쪽 업무 상세는 WWW 제안이며 Linear가 같은 사이드 상세 UX를 제공한다고 주장하지 않는다.

## 연구 범위와 신뢰 한계

- 공식 원문을 실제 열어 확인하고, WWW 코드와 현행 요구를 대조했다. 출처 표의 관측 사실과 이후의 적용 판단을 구분한다.
- 참고 제품에 로그인해 직접 조작하거나 WWW의 현행 GUI를 이번 연구에서 실행하지 않았다. 설치 버전·계정별 노출 차이와 실제 시각 품질은 미확인이다.
- 날짜가 표시된 Linear 변경 기록 외에는 페이지 revision·게시일을 확보하지 못했다. 확인일은 제품 릴리스 날짜가 아니다.
- 수치로 제시한 너비·목표는 프로토타입의 시작값과 수용 시험 제안이다. 시간 절약률·오클릭 감소율·성능 향상률은 측정하지 않았다.
- 혼합형 개인 업무 관리가 작업 가정이다. 외부 캘린더 공급자, 다른 기기 동기화, 반복 일정은 아직 결정하지 않았다.

## WWW에서 확인한 사실

| 코드·현행 문서 | 이번에 읽어 확인한 사실 | 설계 영향 |
|---|---|---|

| `src/renderer.tsx` | 대화→지도/리포트→대화에서 초안·읽기 위치 보존을 확인하는 probe 코드가 있다. | 기존 보존 요구를 홈 이동에도 유지해야 한다. probe의 존재를 이번 실행 통과로 해석하지 않는다. |
| `docs/specs/ecosystem.md` | 지도는 축소 rail과 탐색 열기, 선택 요약·명시적 자세히 보기를 구분한다. | 공통 상세 외형 때문에 지도 선택마다 패널을 자동 열면 안 된다. |

기존 작업 트리에 다른 작업의 수정이 많이 있다. 해당 수정은 보존하며 연구 문서·접수 기록만 추가한다. 현행 파일이 바뀌면 구현 착수 시 위 가정을 다시 확인한다.

## 대안 비교와 선택 이유

| 대안 | 장점 | WWW에서 지불하는 비용 | 판정 |
|---|---|---|---|
| 별도 아이콘 rail + 탐색 열 + 중앙 + 오른쪽 상세 | 도구 종류와 하위 목록이 분리되고 큰 창에 유리 | 왼쪽 두 열의 폭, 중복 화면 선택, 작은 창의 본문 압박 | 지도 등 특수 화면에서는 가능하지만 앱 전체 기본으로는 보류 |
| 이름 있는 단일 탐색 → 아이콘으로 축소 | 메뉴 학습이 쉽고 보통 창에서 폭을 아낌 | 화면별 긴 목록의 배치 규칙이 필요 | 권고 기본안 |
| 사이드바 없이 상단 탭만 | 중앙 폭 최대 | 프로젝트·대화 목록을 열 때마다 추가 이동, 열린 탭 증가 | 기본안에서 제외 |
| 모든 패널 자유 도킹·분할 | 숙련자 개인화 | 설정·저장·충돌·키보드·좁은 창 QA 조합이 크게 늘어남 | 첫 버전 제외 |

우선순위는 업무 시작의 명확성 → 작업 맥락 보존 → 필요한 개입의 가시성 → 본문 폭 → 조작 속도 → 개인화다. 기본안은 사용성 시험을 거쳐 유지하거나 수정할 가설이며 사용자가 이미 선택한 확정 결정으로 기록하지 않는다.

```text
WWW                  [탐색 접기]      [뒤로] 오늘        [빠른 이동] [+ 추가]
───────────────────────┬─────────────────────────────────────────
오늘                   │ 확인 필요: 승인 대기 1건       [대화로 이동]
내 업무                │
일정                   │ 오늘 할 일                  오늘 일정
                       │ □ 제안서 초안                10:00 미팅
대화                   │ □ WWW 진입점 설계             15:00 검토
리포트                 │
                       │ 이어서 할 작업
즐겨찾기               │ WWW / 진입점 설계       [대화에서 이어하기]
  WWW                  │
  제안서               │
                       │
현재 화면의 목록        │
  대화 화면: 대화 목록   │
                       │
생태계                 │
설정                   │

```

표시 내용은 레이아웃 설명용 예시이며 실제 업무·현재 일정·관측 승인 건수가 아니다.

- 전역 목적은 오늘·내 업무·일정·대화·리포트다. 생태계와 설정은 하단 보조 목적에 둔다. 프로젝트는 목적 메뉴가 아니라 필터·소속·즐겨찾기 대상으로 둔다.
- 확장된 사이드바 안의 전역 메뉴 위치는 화면 전환에도 유지한다. 아래 상황별 목록만 바뀐다. 긴 목록은 독립 스크롤하고 메뉴를 밀어내지 않는다.
- 축소하면 전역 메뉴 아이콘이 같은 순서로 남고 상황별 목록은 숨긴다. hover 자동 펼침은 없다. 전역 메뉴는 화면 이동, 접기 버튼은 표시 제어만 한다.
- 축소 상태에서 다른 화면을 선택해도 축소를 유지한다. 목록이 필요하면 명시적으로 탐색을 연다. 최초 사용자는 이름이 보이는 확장 상태에서 시작한다.
- 즐겨찾기 초기 범위는 기존 프로젝트와 직접 관리 업무다. 종류·소속을 함께 표시하고 삭제된 참조는 설명과 제거 행동을 제공한다. 임의 문서까지 확장하지 않는다.
- 홈은 전체 개인 업무, 대화/리포트는 선택 프로젝트 범위를 제목 옆에 표시한다. 홈 필터를 바꿔도 실행 프로젝트는 바뀌지 않는다.

## ‘오늘’의 읽기 순서와 업무 의미

1. **확인 필요:** 미결 승인·연결 실패·저장 실패처럼 사용자 행동이 필요한 항목. 항목이 없으면 이 영역은 생략한다. 일반 완료 소식은 섞지 않는다.
2. **오늘 할 일:** 사용자가 오늘로 지정한 미완료 업무와 오늘 마감 업무의 합집합을 한 번씩 보여 준다. 기한 지난 업무는 별도 소제목으로 보이고 자동으로 오늘 계획에 편입하지 않는다.
3. **오늘 일정:** 시간순 약속, 종일 일정은 따로 표시한다. 선택 날짜가 오늘이 아니면 제목과 복귀 버튼이 이를 분명히 알린다.
4. **이어서 할 작업:** 마지막으로 확인한 관련 대화·작업 기록의 맥락과 명시적 이동 행동. 대화 최근 갱신 시각을 실제 업무 진행률로 바꾸지 않는다.

같은 업무는 안정 ID로 중복 제거한다. 마감일과 ‘오늘 하기로 한 날짜’는 다른 값이며 변경도 독립적이다. 사용자가 지정하지 않은 AI 우선순위를 확정 순위로 표시하지 않는다. 수동 순서가 없으면 우선순위·마감일·안정 tie-break 순으로 정렬하되, 사용자가 읽거나 키보드로 조작 중일 때 live 갱신으로 행 위치를 바꾸지 않는다. 변경이 있음을 표시하고 명시 새로 반영한다.

날짜는 로컬 날짜 단위 값, 시간 약속은 시간대가 있는 시작/끝을 사용한다. 종일 일정을 UTC 자정으로 임의 치환하지 않는다. 자정·DST·시간대 변경과 여러 날에 걸친 약속을 별도 검증한다. 반복 일정·외부 동기화·자동 시간 배치는 이번 최소 범위 밖이다.

## 선택·상세·실행 계약

| 행동 | 결과 | 보존해야 할 것 |
|---|---|---|
| 업무 행 제목/상세 버튼 활성화 | 그 업무의 상세를 오른쪽에 연다. 다른 프로젝트로 실행 전환하지 않는다. | 목록 필터·정렬·읽기 위치 |
| 업무 체크박스 활성화 | 완료 저장을 요청한다. 상세를 열거나 대화로 이동하지 않는다. | 실패하면 미완료 상태와 입력, 성공한 뒤 실행 취소 경로 |
| 목록에서 방향키 이동 | 해당 목록이 복합 위젯으로 구현된 경우 초점/선택 이동만 한다. 명시 활성화 전 숨겨진 상세를 열지 않는다. | 포커스와 스크롤 |
| 상세가 열린 상태에서 다음 업무 활성화 | 같은 패널의 대상과 제목·소속을 함께 바꾼다. | 저장 중인 다른 대상 데이터의 scope |
| 지도 노드 선택 | 기존 계약대로 요약을 갱신한다. 자세히 보기는 별도 행동이다. | 배율·위치·명시 닫기 의도 |
| ‘대화에서 이어하기’ 활성화 | 프로젝트·thread를 확인하고 기존 전환 제약을 통과한 경우에만 이동한다. | 진행 중 대화·승인·다른 대화의 초안 |
| 진행 중 다른 프로젝트로 이어하기 | 전환 제한 사유와 현재 대화 복귀를 표시한다. 자동 중단·새 실행을 하지 않는다. | 기존 Native 실행과 선택 |
| 상세 닫기 | 원래 행으로 초점을 복귀한다. 행이 완료 필터로 없어졌으면 다음 논리적 행이나 목록 제목으로 복귀한다. | 목록 위치·닫힘 상태 |

오른쪽에는 업무 상세·실행 모니터·노드 상세의 화면별 이름과 소속을 표시한다. 같은 컨테이너를 재사용하더라도 대상·열림·편집 상태는 화면별로 분리한다. 일상 선택이 기존 대화 모니터를 몰래 대체하지 않는다. 상세를 닫은 뒤 키보드 초점 이동만으로 다시 열지 않는다.

## 패널과 너비 계약

시작값: 탐색 확장 240px(조정 220–320), 축소 56px, 상세 320px(조정 300–420), 일반 중앙 최소 640px. 지도 등 화면별 필요 폭은 별도 적용한다. 실제 픽셀 값은 기존 토큰에 연결하고 GUI 관찰 후 확정한다.

- 일반 화면은 탐색과 중앙을 기본으로 열고 오른쪽 상세는 필요할 때 연다. 네 열을 기본값으로 강제하지 않는다.
- 상세를 옆에 놓을 조건은 `가용 폭 − 현재 탐색 폭 − 상세 폭 − 경계/여백 ≥ 중앙 최소폭`이다. 예를 들어 1280px에서 240+320을 빼면 경계 전 약 720px가 남는다. 1024px에서 같은 배치는 약 464px이므로 상세를 겹침으로 연다.
- 사용자가 상세를 열었다는 이유만으로 왼쪽 탐색 선호를 영구 변경하지 않는다. 작아진 창에서 필요한 임시 표시는 저장된 선호와 구분한다.
- 상세 겹침은 모달이면 배경 inert·내부 Tab·Escape·호출 위치 복귀를 함께 구현한다. 넓은 창의 고정 상세는 비모달이며 초점을 가두지 않는다.
- 패널을 닫을 때 그 안에 초점이 있으면 먼저 보이는 제어로 옮긴다. 숨은 패널은 접근성 트리·Tab 이동에서 제외한다.
- 패널 너비는 앱 기기 설정, 상세 대상·열림은 화면 맥락, 초안/읽기 위치는 프로젝트와 thread 맥락으로 나눈다. 전체 UI 상태를 하나의 전역 selectedId로 표현하지 않는다.
- 창을 다시 넓히면 사용자 선호로 돌아가고, ‘기본 배치로 복원’을 제공한다. 저장된 너비가 새 창에 맞지 않으면 가용 범위로 제한한다.

## 작업 중 상태와 빠른 이동

승인 대기·치명적 연결 오류·업무 저장 실패는 패널을 접거나 홈으로 이동해도 얇은 상태 요약에서 확인할 수 있어야 한다. 아이콘의 점은 보조 신호이며 본문에 조치 종류와 소속을 함께 표시한다. 알림을 읽거나 요약을 닫아도 실제 미결 승인은 해결되지 않는다. 승인 응답은 원래 대화에서 한다. 숫자는 실제 관측한 건수에만 붙인다.

빠른 이동은 `Cmd/Ctrl+K`를 후보로 두되 기존 링크 입력 등과 충돌 검증 후 확정한다. 화면·등록 프로젝트·직접 업무·현재 확보한 대화 제목/미리보기를 그룹으로 구분한다. 대화는 ‘불러온 대화’ 범위를 표시하고 이력 전체 검색을 약속하지 않는다. 명령과 검색 결과를 분리하며 검색만으로 Native를 실행하지 않는다. 현재 뷰 찾기는 별도로 범위를 표시한다. 첫 버전 원문 검색 색인·AI 자동 분류는 제외한다.

`Cmd/Ctrl+B`는 탐색 토글 후보, F6/Shift+F6은 주요 영역 이동 후보다. 메뉴/툴팁에 단축키를 보여 주고 마우스 경로도 유지한다. 입력 필드·contenteditable·IME 조합 중에는 문자 단축키와 목록 Space를 가로채지 않는다. Escape는 최상위 열린 겹침/메뉴부터 닫고 초안을 지우거나 실행을 중단하지 않는다.

## 상태 소유와 구현 경계 제안

```text
개인 업무/일정 원본 ─── 제한된 main IPC ─── 홈·업무·일정 투영
기존 프로젝트 인덱스 ─────────────────── 즐겨찾기·소속 선택
저장소 work.json/보고서 ── 읽기 참조 ───── 관련 작업·검증 표시
Native 대화 원장 ───── 기존 서비스 ────── 대화와 실행·승인
UI 맥락 저장 ─────── 화면·프로젝트·thread ─ 선호·선택·초안·읽기 위치
```

개인 업무·일정은 앱 데이터의 독립 원본을 권고한다. 프로젝트 연결은 선택이며 현재 프로젝트를 바꿔도 개인 업무는 유지한다. 여러 기기 동기화가 필요하면 충돌·원본 소유 결정을 별도로 해야 하며 로컬 저장만으로 해결됐다고 하지 않는다.

사용자가 직접 체크한 개인 업무 완료와 저장소 작업의 검증 완료, Native 턴 종료는 별개다. 연관 기록을 표시하되 자동으로 서로의 상태를 덮어쓰지 않는다. 참조한 프로젝트/작업이 삭제되거나 파싱에 실패하면 해당 소속을 미확인으로 표시하고 개인 업무는 보존한다.

앱 셸은 탐색·범위·라우트·포커스를, 기능 화면은 자신의 선택·필터·스크롤을 소유한다. main은 저장·검증·Native 전환을 소유하고 renderer는 경로나 임의 명령을 쓰기 IPC로 보내지 않는다. 기존 프로젝트 전환 core를 재사용하고 홈을 위한 두 번째 실행 전환 경로를 만들지 않는다.

UI만 이동하는 개인 업무 데이터는 원자 저장과 revision/요청 세대를 사용한다. 대상 A 저장 중 B로 이동해도 A의 응답이 B를 덮어쓰지 않게 한다. 저장 실패를 완료로 표시하지 않고 입력과 재시도 경로를 보존한다. 재시도는 같은 작업 ID로 멱등 처리하며 서로 다른 생성 요청의 중복을 무조건 제목으로 합치지 않는다.

구현 시 예상 경계는 공통 셸/탐색, 개인 업무·일정 서비스와 IPC 계약, 홈 투영, 기존 대화 이동 연결이다. 구체 파일 분리는 현행 동시 변경을 다시 읽은 뒤 최소 단위로 정한다. `src/renderer.tsx`에 모든 데이터 처리·패널 상태를 추가하는 방식은 피한다. 첫 구현 파일럿은 셸 전환과 홈→업무 상세→대화 복귀의 한 여정으로 잡는다.

## 시각 설계

현재 어두운 토큰·한국어 시스템 글꼴을 이어 간다. 탐색은 13px 안팎, 업무 제목은 14px 안팎의 시작값으로 분리하고 작은 글씨로만 공간을 확보하지 않는다. 업무 행은 40–44px 시작값으로 클릭 표적과 제목·소속·마감 정보의 정렬을 맞춘다. 길어진 한글 제목은 상세에서 온전히 읽을 수 있게 한다.

상위 레이아웃은 얇은 구분선과 여백으로 나누고, 모든 정보를 같은 모양의 카드로 둘러싸지 않는다. 홈에 진행률 원·거대한 숫자·활동 차트를 기본으로 넣지 않는다. 선택 강조는 얕은 배경과 표시선, 포커스는 별도의 외곽선으로 구분한다. 파랑은 이동/포커스·실행, 빨강은 실패, 경고색은 조치 필요처럼 기존 의미를 재사용한다.

접힘 전환은 사용자의 행동을 설명하는 짧은 모션만 사용한다. 모션 축소에서는 즉시 바꾸며 행 갱신마다 반짝이거나 순서를 재생하지 않는다. 로딩은 빈 상태와 구분하고, 연동되지 않은 달력은 ‘일정 없음’ 대신 연결/등록 상태를 설명한다. 첫 버전은 로컬 일정이므로 외부 연동이 된 것처럼 꾸미지 않는다.

## 완성도를 판단할 실제 여정

아래는 구현 후 수행할 시험 계획이다. 이번 연구에서 실행하거나 통과한 결과가 아니다.

| 여정 | 관찰할 성공 조건 |
|---|---|
| 아침에 앱 시작 | 오늘 할 일·일정·필요한 개입을 구분하고 등록/재개 행동을 찾는다. 빈 데이터·로딩·실패를 구별한다. |
| 제목만 입력해 업무 추가 → 재시작 | 한 항목만 생성되고 입력한 제목·날짜·소속이 복원된다. 실패 시 입력이 남는다. |
| 오늘 목록에서 완료 → 실행 취소 | 상세 열기와 체크 동작이 분리되고 저장 결과·복구가 정확하다. |
| 업무 상세 → 관련 대화 → 홈 복귀 | 원래 업무·필터·스크롤·초점이 유지된다. 전환 전 대화 초안도 보존된다. |
| 대화 실행 중 홈 이동 → 승인 도착 | 패널이 닫혀도 조치 필요가 보이고 원래 프로젝트/thread로 복귀한다. 임의 승인·실행 중단이 없다. |
| 프로젝트 A 실행 중 B 업무 조회 | 조회는 가능하되 Native 전환은 기존 제한을 지킨다. 늦은 A 응답이 B 상세에 섞이지 않는다. |
| 키보드와 한글 IME만 사용 | 생성·목록·상세·닫기·탐색·복귀가 가능하고 입력 글자가 단축키로 소비되지 않는다. |
| 1440/1366/1280/1024/800px 폭, 100/125/150% 확대 | 중앙 가독성과 입력 접근이 유지되고 상세의 고정/겹침 전환·초점이 맞다. 넓혀도 사용자 설정이 사라지지 않는다. |
| 긴 제목·동일 제목·많은 목록 | 제목/소속으로 구별하고 가로 전체 스크롤 없이 필요한 항목에 접근한다. 메뉴와 주요 상태는 목록에 밀리지 않는다. |
| 자정·종일·다른 시간대·DST | 날짜 밀림·누락·중복 없이 의도한 업무와 약속을 표시한다. |
| 파일 손상·삭제된 프로젝트·부분 조회 실패 | 실패한 범위를 알리고 다른 정상 데이터와 입력을 보존한다. 0건으로 위장하지 않는다. |
| 탐색 20회 왕복·너비 조절·배치 초기화 | 초안·선택·읽기·닫힘 의도가 유지되고 누적 중복 구독/재실행이 없다. |

초기 사용성 관찰은 같은 대표 업무로 기존 화면과 파일럿을 비교한다. 클릭/되돌아가기 횟수, 목적지 선택 오류, 맥락 유실, 완료까지의 시간을 기록하되 익숙함과 학습 순서를 함께 남긴다. 개인 유지자 1명의 결과를 일반 사용자 모집단의 통계로 해석하지 않는다. 확인되지 않은 ‘두 배 빠름’ 같은 목표는 사용하지 않는다.

## 구현 순서와 아직 열린 결정

1. 공통 탐색의 확장/축소·화면 복귀·범위 표기를 실제 데이터로 검증한다. 이때 기존 대화와 지도의 회귀를 먼저 잡는다.
2. 직접 업무 저장과 오늘 투영, 제목만 빠른 추가·완료/복구·상세를 한 여정으로 완성한다.
3. 로컬 일정의 날짜/시간대·주간 이동과 기존 작업/대화 참조를 연결한다.
4. 빠른 이동·배치 복원·긴 목록·실패·키보드·창 크기 관찰을 거쳐 세부 밀도를 확정한다.

미결정은 외부 일정 공급자와 동기화, 업무 기록의 다른 기기 공유, 반복 업무/일정의 필요성이다. 이들은 첫 로컬 파일럿의 선행 조건이 아니다. 초기 방문은 오늘로 시작하고, 평소 앱 재활성화/백그라운드 복귀는 현재 작업을 유지하는 안을 권고한다. 완전 재시작 시 오늘 우선과 마지막 화면 복원 중 선호는 파일럿에서 확인한다. 실행 복구 기능을 이 UI 제안만으로 약속하지 않는다.

이번 전달은 근거를 갖춘 연구 제안이다. 화면의 실제 완성도와 사용성은 구현 파일럿과 위 여정의 실측 이후 판단한다.
