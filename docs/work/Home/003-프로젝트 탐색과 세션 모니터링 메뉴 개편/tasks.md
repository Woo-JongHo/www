# 실행 계획 — 프로젝트 탐색과 세션 모니터링 메뉴

## 현재 상태와 실행 권한

이 문서는 다음 구현의 작업 순서다. 현재는 문서 작성 요청만 실행했으며 제품 코드·기능 검사·GUI·필수 최종 감사는 미실행이다. 기준과 결과의 정본은 [work.json](work.json), 행동은 [spec.md](spec.md), 상태·경계는 [design.md](design.md)를 따른다. 아래 작업은 완료 체크리스트가 아니라 실행할 구체적인 계획이다.

## A — 재개와 기준선 확정

담당: Codex Sol이 요청 범위·공통 계약·통합을 소유한다.

- 같은 UUID의 명세·설계·산출물 검토 결과를 읽고 구현 권한과 실제 쓰기 경로를 연결한다. 현재 위치·브랜치·작업 트리와 Home 002·Chat 014의 후속 변경을 확인한다.
- 공식 typed 작성 하네스와 구조·소스·타입 검사 경로를 확인한다. 미승인 파일과 다른 세션의 문서를 보존하고 기존 기록·수용 기준을 약화하지 않는다.
- 첫 진입·프로젝트별 대화·리포트·생태계와 두 기존 모니터 버튼의 현재 동작을 기록한다. 최소 재현과 화면별 상태 보존 대상, 키보드 진입/복귀 지점을 확정한다.
- 통과 조건: 권한·예상 경로·기준별 작업·실제 검사 명령이 연결되고 문서 모순이나 공유 파일의 중복 소유가 없다.

연결 기준: DOC-HANDOFF, NAV-KEEP, STATE-RETURN.

## B — 왼쪽 탐색과 중앙 상태 분리

담당: Sol. 상태·실행 보호·세션 경계가 맞물리므로 기본 통합 책임자가 처리한다.

- `renderer.tsx`의 목록 표시와 중앙 화면 상태를 분리한다. 프로젝트 목록 열기/닫기와 현재 프로젝트 재선택은 중앙을 변경하지 않는다.
- 전체 대시보드는 명시적 화면 이동 항목으로 제공한다. 최초 View Page와 등록 프로젝트 없음, 같은 프로젝트의 WWW 별칭도 처리한다.
- 다른 프로젝트 선택 성공 후에만 새 프로젝트 대시보드로 전환한다. 추가 취소·실패·늦은 이전 응답에서는 기존 선택과 초안을 유지한다.
- 전송·실행·대화 준비·미결 승인·실패 원문 보호는 실제 전환에 유지하며 목록 탐색은 허용한다.
- 행동 테스트와 Electron Home 시나리오에 대화·리포트·생태계에서 목록 왕복, 현재 프로젝트 재선택, 다른 대상 선택, 추가 취소/실패, 보호 중 목록 탐색을 추가한다.

연결 기준: NAV-KEEP, NAV-SELECT, NAV-GUARD, STATE-RETURN.

## C — 다섯 메뉴와 세션 모니터링 연결

담당: Sol이 세션·API 연결을 소유하고, 경계가 확정된 표시 컴포넌트는 Terra에 배분할 수 있다. 배분 전에 파일 소유를 확정한다.

- 메뉴를 대시보드·대화·생태계·리포트·모니터링 순서로 구성한다.
- 대화 상단의 상세 모니터와 세션 모니터 접기/열기 버튼 두 개를 JSX 주석 처리한다. DOM·접근성 트리·Tab 순서에 기존 버튼이 없는지 확인한다.
- 기존 세션 개요·상세 투영을 새 모니터링 화면에서 재사용한다. 내부 상세 링크도 새 진입과 일치시키고 기존 오버레이의 중복 상태를 정리한다.
- 현재 sessionId·프로젝트·thread·선택 턴을 표시하며 새 대화·로딩·자료 없음·EOF·오류·부분 이력·오래된 관측을 보존한다. 화면 진입만으로 새 thread/turn과 자동 재전송을 생성하지 않는다.
- 다른 탭의 동일 프로젝트·동일 승인 요청 ID·다른 token을 사용한 행동 테스트로 관측 격리를 확인한다. 승인/중단은 기존 대화로 연결하고 기존 기본 Agent 개요·Working 경로와 충돌하지 않게 한다.

연결 기준: NAV-MENU, MON-ENTRY, MON-SCOPE, MON-STATES.

## D — 왕복·가시성·접근성 검증

담당: Terra가 일상 검증과 증거 수집을 맡을 수 있고 Sol이 상태 경계의 실패를 판단한다.

- 같은 대화에서 초안 입력 → 과거 스크롤 → 카드 펼침 → 모니터링 → 프로젝트 목록 열기/닫기 → 대화 복귀를 수행한다. 초안·기준 카드·읽기 위치와 최신 사건을 비교한다.
- 리포트 선택·읽기 위치, 생태계 노드·경로·배율, 대시보드 필터·상세 선택에서 목록만 왕복해 상태 동일성을 확인한다.
- 두 탭을 동시에 실행해 각 모니터링의 사건·승인·종료와 탭별 보기 상태를 대조한다. 비활성 상태의 수신과 복귀 표시도 확인한다.
- 키보드 목록 열기·선택·취소·초점 복귀와 좁은 창을 실제 Electron에서 조작한다. 숨은 화면/주석 버튼의 초점 진입이 없고 입력창·현재 실행 상태·승인 경로가 접근 가능해야 한다.
- Chat 014의 단일 스크롤·카드 펼침·Input P0·Working 시나리오와 함께 확인한다. 기존 문서를 자동 수정하거나 이번 범위를 입력 성능 전체 개선으로 확대하지 않는다.

연결 기준: STATE-RETURN, ACCESS-VERIFY, MON-SCOPE, MON-STATES.

## E — 구현 시 검사·문서·독립 검토

담당: Sol이 통합과 근거 회수, 읽기 전용 검토자가 별도 문맥에서 검증한다.

- 실제 변경에 맞춰 행동 테스트를 갱신하고 집중 검사, 소스 정책·워크플로 계약·strict 타입 검사, 공식 구조 생성과 빌드를 실행한다. 새 코드 파일이 생기면 구조·요구 등록과 검사 대상을 함께 갱신한다.
- 기존 `scripts/verify-home.ts`, `scripts/verify-sessions.ts`, `scripts/verify-chat.ts`를 필요한 범위로 확장해 새 목록·메뉴·모니터링 경로를 검증한다. 제한 실행은 해당 범위만 입증한다. 시나리오가 없는데 기존 명령 성공만으로 새 동작을 통과 처리하지 않는다.
- 실제 Electron·합성 Native 증거의 소스 식별·명령·기대/관측·스크린샷을 같은 UUID의 검증 기록에 연결한다. 테스트 시간 예산과 입력 반응성 성능 기준은 별도로 기록하고 과거 기본 검사 시간 초과를 새 성공으로 옮겨 쓰지 않는다.
- 구현과 같은 변경에서 제품·기능·구조·개발 안내를 갱신하고 문서 영향 검토를 기록한다. 현재 문서의 네 메뉴와 상세 모니터 설명을 새 다섯 메뉴·세션 화면에 맞추며 과거 작업 이력은 보존한다.
- 실제 가용성과 사용자 지침·검토 정책을 확인해 읽기 전용 교차검증과 필수 최종 감사를 수행한다. 미실행·불가·반려는 그대로 기록하고 문서 점검으로 대체하지 않는다. 저작 보고서를 갱신하고 현재 기준·증거·권한에 따른 완료 여부를 판단한다.

연결 기준: NAV-KEEP, NAV-SELECT, NAV-GUARD, NAV-MENU, MON-ENTRY, MON-SCOPE, MON-STATES, STATE-RETURN, ACCESS-VERIFY, DOC-HANDOFF.

## 파일 소유와 병렬화

Sol이 `renderer.tsx`의 탐색·세션·중앙 상태와 공통 타입을 단독 소유한다. 공유 경계가 확정되기 전 다른 작성자에게 같은 파일을 병렬 배분하지 않는다. 표시 모듈을 분리할 실익이 있을 때만 Terra의 독립 소유 경로와 입력·의존성·통과 명령·증거 경로를 정한다. Luna는 확정된 목록·축자 대조 등 작은 수집에 한정할 수 있다. 작은 작업을 모델 세 개 호출로 기계적으로 분해하지 않는다.

지금은 배분 계획만 존재하며 모델 호스트 실행·토큰 절감·제품 자동 라우팅의 근거가 아니다. 문서 검토 결과와 제품 감사 결과도 별도로 관리한다.
