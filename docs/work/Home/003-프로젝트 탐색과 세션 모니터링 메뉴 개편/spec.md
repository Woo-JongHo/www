## 요청과 목적

사용자는 왼쪽의 전체 보기로 돌아갈 때 중앙 작업 화면까지 사라지는 점을 불편으로 지적했다. 프로젝트나 다른 이동 대상을 명시적으로 선택하기 전까지 현재 화면을 유지하도록 요구했다. 이어 대화 상단의 상세 모니터와 세션 모니터 접기 버튼을 주석 처리하고, 프로젝트 메뉴를 **대시보드 · 대화 · 생태계 · 리포트 · 모니터링**으로 구성하며 모니터링은 세션 단위로 정의했다. 마지막 직접 요청은 “문서화다 만들어놔”다.

이번 산출물은 다음 구현의 명세·설계·실행 계획이다. 제품 구현은 아직 변경하지 않았으며 수용 기준의 정의·필수 여부·결과는 [작업 레코드](work.json)가 소유한다. 구현 전 문서 점검과 제품 기능 검증은 구분한다.

## 범위와 권한

포함 범위는 프로젝트 목록 탐색과 중앙 화면의 분리, 공통 메뉴 다섯 개, 기존 버튼 두 개의 주석 처리, 현재 대화 탭의 세션 모니터링, 화면 상태 보존과 구현·검증 계획이다. 이번 직접 요청은 작업 문서와 목차, 문서 검사 및 보고서 작성까지다. 제품 코드·테스트 구현, 커밋·푸시, 패키징과 배포는 실행하지 않는다.

새 프로젝트 생성 기능, 일반 셸/PTY, 모든 세션을 합친 전역 모니터, 새 메시지 DB, 무제한 사건 보관, 앱 재시작 후 화면 자동 복구, 작업 카드와 thread의 추정 연결은 범위 밖이다. 기존 폴더 추가는 기존 기능을 재사용한다.

## 사용자 여정과 수용 기준 연결

### 목록 탐색과 실제 전환

연결 기준: NAV-KEEP, NAV-SELECT, NAV-GUARD, NAV-MENU.

| 사용자 행동 | 왼쪽 탐색 | 중앙과 실제 선택 |
|---|---|---|
| 프로젝트 목록 열기 | 전체 프로젝트 목록 표시 | 현재 프로젝트·화면 유지 |
| 목록 탐색 또는 닫기 | 목록 안의 탐색만 갱신하거나 프로젝트 메뉴 복귀 | 대화·리포트·생태계·모니터링의 현재 상태 유지 |

프로젝트 목록을 여는 행위와 전체 대시보드를 여는 행위를 분리한다. 초기 진입의 View Page와 등록 프로젝트가 없는 상태는 유지한다. 실제 다른 프로젝트 전환에는 기존 전송·실행·대화 준비·승인·실패 원문 보호를 적용하고, 제한 이유를 표시한다. 목록을 살펴보는 것만으로 실행을 끊거나 thread·turn을 새로 만들지 않는다. 보호 여부는 해당 탭을 기준으로 판단한다.

### 메뉴와 모니터링

연결 기준: NAV-MENU, MON-ENTRY, MON-SCOPE, MON-STATES.

프로젝트 메뉴 순서는 대시보드 · 대화 · 생태계 · 리포트 · 모니터링이다. 대화 상단의 기존 상세 모니터 버튼과 세션 모니터 접기/열기 토글은 JSX 주석으로 비활성화한다. 주석 처리한 버튼이 DOM·클릭·키보드 초점 대상에 남아서는 안 된다. 기존 관측 기능을 삭제하는 것으로 해석하지 않는다.

모니터링의 대상은 현재 선택된 **대화 탭의 세션**이다. 프로젝트명·세션·대화와 선택 턴을 식별할 수 있어야 하며 같은 프로젝트의 두 탭도 관측을 혼합하지 않는다. 현재 턴과 과거·복원 관측을 구분하고, 세션 실행 종료를 업무 완료로 표시하지 않는다.

기존 세션 개요·공개 Plan/Progress·실행 흐름·Skills/Hooks·리소스·모델/토큰·계정 한도·사건 정보를 기존 제공 범위에서 재사용한다. 화면을 옮긴다는 이유로 비공개 reasoning이나 미제공 지표·진행률을 만들지 않는다. 새 대화, 자료 없음, 로딩, 연결 종료, 실패, 부분 이력, 저장 실패와 오래된 관측은 각각 사실에 따라 안내한다. 화면 진입만으로 새 thread/turn 생성·자동 재전송·불확실한 실행의 자동 복구를 수행하지 않는다. 추가 읽기 갱신은 기존 조회 정책과 출처를 따른다.

### 왕복과 상태 보존

연결 기준: STATE-RETURN, ACCESS-VERIFY.

대화에서 모니터링을 열고 돌아와도 초안·읽기 위치·출력 카드 펼침을 유지한다. 리포트에서 프로젝트 목록을 열고 닫아도 선택 보고서와 읽기 위치를 유지한다. 생태계의 선택 노드·탐색 경로·배율도 목록 탐색 때문에 초기화하지 않는다. 대시보드 필터와 상세 선택도 같은 원칙을 적용한다.

모니터링 화면이나 다른 탭을 보는 동안에도 해당 세션의 사건·승인·종료·오류를 계속 수신한다. 대화로 복귀할 때 갱신된 실제 상태를 표시하고 과거를 읽던 사용자를 강제로 끝으로 보내지 않는다. 탭마다 상태를 격리하고 기존 사건 보관 상한과 초안·승인 보호를 유지한다.

키보드로 목록을 열고 프로젝트를 선택하거나 취소할 수 있어야 한다. 목록 닫기 후 초점은 진입 버튼 등 의미 있는 위치로 돌아간다. 좁은 창에서도 현재 프로젝트와 선택 메뉴를 식별하고 대화 입력·실행 상태·필수 개입 경로에 접근할 수 있어야 한다. 이번 문서에서는 실제 GUI·IME·Windows 검증을 수행한 것으로 표시하지 않는다.

## 설계 기본안과 열린 결정

사용자 확정 사항은 목록 탐색 중 중앙 유지, 기존 버튼 두 개 주석 처리, 다섯 메뉴의 순서와 세션 모니터링 범위다. 다음은 구현을 위한 설계 기본안이며 사용자 원문을 인용한 결정과 구분한다.

- 기존 전체 보기 버튼의 이름은 **프로젝트 목록**으로 바꾸고, 목록 안에 중앙 화면을 실제로 여는 **전체 대시보드** 항목을 둔다.
- 다른 프로젝트 선택이 성공하면 그 프로젝트의 대시보드를 기본 진입 화면으로 쓴다. 현재 프로젝트 재선택은 기존 화면을 그대로 유지한다.
- 대화의 기본 Agent·Plan/Progress 개요는 유지하는 방향을 기본으로 하고, 기존 상세·리소스 관측은 모니터링 화면에 모은다. 상세 모니터로 향하는 내부 링크도 새 화면으로 연결해 이전 오버레이와 경쟁하지 않게 한다.
- 대화 안의 승인·중단 경로와 Working 표시는 유지한다. 모니터링에서 개입이 필요하면 해당 세션의 대화로 이동할 수 있게 한다. 관측 화면을 새 승인 실행 경로로 확대하지 않는다.

레이아웃의 정확한 폭·아이콘·모니터링 내부 구획은 기존 디자인 토큰을 재사용해 구현 때 조정한다. 외부 서비스나 새 상태관리 라이브러리는 현재 요구에 필요하지 않다. 독립 의미 검토에서 충돌이 발견되면 같은 작업 문서에서 정정하고 검토 digest를 갱신한다.
