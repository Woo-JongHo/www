# 설계 — 프로젝트 탐색과 세션 모니터링 메뉴

## 기준선과 재사용

명세와 수용 기준의 정본은 [spec.md](spec.md), [work.json](work.json)이다. `renderer.tsx`는 현재 `view` 하나로 홈/프로젝트 사이드바와 중앙 화면을 함께 바꾼다. 탭별 App과 `SessionApiProvider`는 이미 세션에 API와 사건 구독을 연결한다. 이 구조를 유지하면서 탐색 상태를 분리하는 것이 최소 변경이다.

`NativeActivityView`와 리소스 투영·원장은 관측 표현을 제공한다. 새 모니터링은 이 투영과 기존 세션 구독을 재사용하며 별도 Native 프로세스·원장·수집기를 만들지 않는다. `main`·preload의 세션 IPC와 동일 thread 단일 소유권은 기존 계약을 유지한다.

## 상태와 데이터 흐름

| 상태 책임 | 소유 범위 | 변경 계기 |
|---|---|---|
| 왼쪽 목록/프로젝트 메뉴 표시 | 각 대화 탭의 화면 상태 | 프로젝트 목록 열기·닫기·프로젝트 선택 |
| 중앙 화면 종류 | 각 탭의 기존 App | 명시적 메뉴 선택 또는 다른 프로젝트 선택 성공 |
| 실제 프로젝트·thread·선택 세대 | 기존 세션과 검증된 선택 계약 | 기존 프로젝트/대화 전환 API의 성공 |
| 초안·대화 읽기·출력 펼침 | 기존 대화별 기억과 컴포넌트 상태 | 입력·스크롤·카드 조작·명시적 대화 전환 |
| 리포트·생태계·대시보드의 보기 상태 | 각 세션 안의 해당 화면 | 해당 화면의 직접 조작 |
| 모니터링 관측 | 기존 세션 구독과 투영 | Native 사건·기존 원장 snapshot·사용자의 턴 선택 |

목록 열기/닫기는 실제 선택과 중앙 화면을 갱신하지 않는다. 표시할 목록 모드와 중앙 화면 종류를 서로 독립된 상태로 표현한다. 구체적인 타입·변수명은 구현 때 정하고, 하나의 `view="home"`에 두 책임을 다시 묶지 않는다.

현재 프로젝트 선택은 목록만 닫는 경로로 처리한다. 다른 프로젝트 선택은 기존 보호 검사 → 검증된 API 요청 → 성공 확인 → 대상·중앙 대시보드 전환의 순서다. 취소·실패·늦은 이전 선택 응답에서는 기존 화면과 초안을 보존한다. 동일 프로젝트의 WWW 별칭은 실제 경로/key 계약으로 비교해 불필요한 전환을 만들지 않는다.

초기 탭은 기존 View Page·전체 대시보드로 진입한다. 이후 전체 대시보드를 여는 것은 명시적 화면 선택이다. 기존 프로젝트를 유지한 채 보드를 열 수 있으며, 보드 조회가 현재 Native 실행 대상을 바꾸는 명령이 되어서는 안 된다.

## 세션 모니터링 구성

모니터링 메뉴는 현재 App의 세션 API를 소비한다. 대상 표시는 sessionId와 검증된 workspace/thread에서 얻고 선택 턴은 기존 관측에 연결한다. 새 대화의 thread 미생성과 과거 턴의 이력 여부를 정상 상태로 처리한다. 선택 탭이 바뀌면 해당 탭의 모니터링으로 바뀌며 이전 탭의 승인·토큰·리소스를 섞지 않는다.

기존 세션 개요·흐름·리소스·상세 사건을 필요한 내부 구획으로 모은다. 기본 대화의 Agent 개요와 현재 Working/승인/오류 안내는 계속 이용할 수 있게 하는 기본안이다. 대화 상단의 상세 모니터·세션 모니터 접기/열기 두 버튼은 JSX 주석으로 남기고 실제 진입은 메뉴가 담당한다. 기존 개요의 상세 링크가 필요하면 모니터링 화면 이동으로 연결한다. 이전 상세 오버레이와 새 페이지를 동시에 여는 상태는 만들지 않는다.

모니터링 진입은 관측 보기이며 새 실행을 생성하지 않는다. 승인·중단은 현재 대화의 기존 경로를 사용하도록 연결한다. 오류·누락·오래된 이력·미제공 사용량은 기존 출처와 함께 표시하고 정상 수치로 대체하지 않는다. 전역 합산 모니터나 프로젝트 카드의 업무 완료 판정은 추가하지 않는다.

## 화면 생명주기와 복귀

목록 모드 변경만으로 중앙 컴포넌트를 unmount하지 않는다. 대화와 모니터링은 탭별로 기존 사건 수신과 상태 소유를 유지한다. 화면 이동 시 리포트 같은 조건부 마운트 영역의 선택·스크롤을 유지하는 방법을 확인한다. 단순 DOM 유지와 세션별 보기 상태의 상위 보존 중 기존 구조에 맞는 작은 방식을 선택하되 숨은 화면의 polling·타이머를 불필요하게 늘리지 않는다.

프로젝트 목록 열기/닫기는 대화 목록 초기화·리포트 재선택·생태계 경로 초기화를 일으키지 않아야 한다. 실제 프로젝트 전환 뒤의 다른 프로젝트 화면 상태 복원까지 새로 약속하지 않으며 기존 전환·격리 계약을 따른다. 앱 재시작 후 자동 복원도 추가하지 않는다.

키보드 초점은 목록 진입 시 의미 있는 첫 항목이나 현재 프로젝트로 옮기고, 닫을 때 진입 버튼으로 복귀하는 기본안이다. 중앙 화면은 읽던 위치를 보존한다. 화면을 실제로 이동할 때만 해당 화면 제목·주요 컨트롤로 초점을 옮긴다. 숨은 화면과 주석 처리한 버튼은 Tab 순서에 남지 않는다.

| 경로 | 예상 변경 또는 확인 |
|---|---|
| `src/renderer.tsx` | 탐색/중앙 상태 분리, 프로젝트 전환, 다섯 메뉴, 두 버튼 주석, 화면 복귀와 기존 Agent 개요 |
| `src/native-activity-view.tsx`, `src/native-activity.css` | 기존 모니터 표현 재사용과 내부 상세 링크의 새 화면 연결 |
| `src/session-api.tsx`, `src/session-tabs.tsx` | 기존 탭 범위·구독·탭 상태 보존 확인, 필요할 때만 최소 수정 |
| `src/reports-view.tsx`, `src/ecosystem-view.tsx`, `src/dashboard-view.tsx` | 화면별 선택·스크롤·경로 보존과 가시성 경계 확인 |
| `src/chat.css`, `src/dashboard.css`, `src/session-tabs.css` | 메뉴·중앙 레이아웃·숨김·좁은 화면·초점 표현 |
| `src/main.ts`, `src/preload.ts`, `src/shared.ts`, `src/native-session.ts` | 기존 선택·IPC 계약 재사용 확인. 새 IPC를 먼저 추가하지 않음 |
| `test/session-tabs.test.ts`, `test/dashboard.test.ts`, `test/www-activity-view.test.ts`와 필요한 행동 테스트 | 탐색 분리·세션 격리·관측 상태·기억 검증 |
| `scripts/verify-home.ts`, `scripts/verify-sessions.ts`, `scripts/verify-chat.ts` | 새 메뉴·목록·모니터링 왕복의 실제 Electron 시나리오 |

이는 다음 구현의 예상 영향 목록이다. 이번 문서 작업의 코드 쓰기 권한이나 확정 파일 분할이 아니다. 새 파일은 기존 모듈 책임으로 충분하지 않을 때만 추가한다. 코드 작성에는 공식 typed 하네스와 구조 생성 계약을 적용한다.

## 위험과 검증 전략

| 위험 | 확인할 증거 | 기준 |
|---|---|---|
| 목록이 중앙을 다시 홈으로 바꿈 | 각 화면에서 목록만 왕복한 전후의 중앙 종류·프로젝트·선택 동일성 | NAV-KEEP, STATE-RETURN |
| 현재 프로젝트 재선택이 대화를 초기화 | API 호출 수와 thread·초안·읽기 위치 동일성 | NAV-SELECT |
| 실행 중 다른 프로젝트 전환을 허용 | 승인·전송·실행 상태별 거부와 기존 thread 보존 | NAV-GUARD |
| 다른 탭의 사건이 새 모니터에 표시 | 두 실제 fixture child·동일 요청 ID·서로 다른 승인 token·탭별 DOM | MON-SCOPE |
| 리포트/생태계 remount로 보기 초기화 | 선택 보고서와 scrollTop, 노드·경로·배율의 왕복 관측 | STATE-RETURN |
| 미제공/종료 관측을 현재 실행으로 표현 | 새 대화·EOF·부분 이력·저장 오류·과거 턴 fixture | MON-STATES |
| 숨은 화면의 타이머·투영이 입력을 지연 | Chat 014의 입력·스트리밍 성능 시나리오와 수신 경계 대조 | STATE-RETURN, ACCESS-VERIFY |
| 버튼 주석 후 관측 진입 또는 초점 손실 | 메뉴와 DOM·키보드·좁은 창의 실제 조작 | NAV-MENU, MON-ENTRY, ACCESS-VERIFY |

실제 모델·OS 한국어 IME·Windows 실기와 합성 Native/Electron 검사는 구분해 기록한다. 이번 문서 작성으로 위 검증이 실행된 것은 아니다.

## 미래 범위와 인계

전역 세션 대시보드, 새 관측 보관 정책, 앱 재시작 복원, 새로운 승인 API는 결정하지 않는다. [tasks.md](tasks.md)의 선행 조건·파일 소유·기준별 검증을 준비한 뒤 같은 UUID로 구현한다. 구현을 시작하기 전 직접 요청의 제품 쓰기 권한을 확보하고, 문서 작성 권한을 구현 승인으로 승격하지 않는다.
