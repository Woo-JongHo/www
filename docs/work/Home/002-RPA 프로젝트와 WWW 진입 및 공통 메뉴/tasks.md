# 후속 설계·구현·검증 단위

이 문서는 구현 착수 전 실행 계획의 이력이다. 당시 권한은 문서 작성이었고 각 단위의 미결정 해소와 별도 구현 요청이 필요했다. 2026-11-16 전체 구현과 독립 Codex 탭·동시 실행을 허용한 후속 직접 요청은 [명세의 현행 범위](spec.md#현행-범위와-초기-기록의-구분)에 연결했다. 아래의 ‘후속’, ‘미정’, ‘구현하지 않는다’는 당시 계획 상태이며 현재 완료 판정은 work.json과 실제 검증 기록을 따른다. 현행 데이터·화면·세션 계약은 [대시보드 명세](../../../specs/dashboard.md)와 [Chat 명세](../../../specs/chat.md#chat-sessions-01)를 따른다.

## 초기 계획 T1 — 진입과 탐색 — 이력

관련 기준: S1, S2, S3, S5.

RPA 프로젝트 등록 방식·WWW 식별·선택 후 메뉴 표현을 결정한다. View Page, 대상 공간, 공통 메뉴, 전체 보기 복귀를 연결한다. 프로젝트 미등록·추가 취소·추가 실패·실행 중 실제 대상 전환을 검증한다.

## 초기 계획 T2 — 보드 데이터 계약 — 이력

관련 기준: S3, S5, S7.

카드 단위, 원본, 상태 판정 주체와 전체 조회 범위를 결정한다. 대상별 관측·업무 상태·미확인·부분 실패·갱신 시각을 구분하는 읽기 계약을 설계한다. 여러 프로젝트 집계를 이유로 Native를 자동 실행하지 않는지와 늦은 응답 격리를 검증한다.

## 초기 계획 T3 — 칸반 표시와 이동 — 이력

관련 기준: S2, S5, S7.

T2 이후 전체/대상별 보드, 현황 요약, 응답 필요 강조, 필터와 상태 열을 구현할 수 있다. 카드에서 정확한 대상과 Chat·터미널로 이동하는 흐름, 빈 상태·오류·키보드·좁은 화면을 실제 GUI로 검증한다. 터미널 연결은 T4의 계약 확정 이후 연결한다.

## 초기 계획 T4 — Chat 여러 터미널 — 이력

관련 기준: S2, S3, S6, S7.

터미널 종류를 먼저 결정한다. 종류에 맞게 프로세스·세션 식별, 탭 전환·닫기·종료, 입력·출력·승인·중단, 동시 실행과 복원 정책을 설계한다. 이후 두 개 이상 열기와 세션 간 격리를 검증한다. 질문에 답이 없는 현재 상태에서는 구현하지 않는다.

## 초기 계획 T5 — 문서 정합성과 후속 수용 — 이력

관련 기준: S1, S2, S3, S4, S5, S6, S7, S8.

확정·제안·미결정을 대조하고 작업 레코드·명세·설계·목차의 연결을 검사한다. 실제 구현 시 현행 제품·구조·기능 명세를 갱신하고 집중 테스트·타입 검사·빌드·Electron GUI 및 필수 독립 검토를 수행한다. 미실행을 통과로 기록하지 않는다.

## 초기 계획 T6 — 업무별 모델 배치 — 이력

관련 기준: S3, S4, S8.

특정 스킬에 한정하지 않고 모든 작업에 적용할 자동 선택 원칙을 정한다. 기본 모델 고정과 불필요한 다중 호출을 피하고, 분류·맥락 전달·재시도·검토까지 포함한 작업별 총 토큰을 관측한다. 간단한 작업의 단일 모델 종료, 위험한 단계의 상향, 실패 시 재판단, 사용량 미제공을 검증 시나리오에 추가한다. 품질을 유지한 실제 사용량 비교 전에는 절감 효과를 확정하지 않는다.

개발 호스트와 제품 Chat의 적용 순서를 정하고 전역 지침·MODEL_POLICY·검토 정책의 모델 ID와 대체 조건을 정합화한다. 업무 역할·실패 위험·선택 사유·요청 모델·관측 모델을 구분하는 실행 계약을 설계한다. 이후 실제 호출과 영수증·모니터의 일치, 모델 미지원·quota·시간 초과·관측 모델 미제공, 작성과 독립 검토의 분리를 검증한다. 실행 라우터 구현은 별도 개발 권한을 받은 뒤 진행한다.
