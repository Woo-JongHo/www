# 칸반 작업 상세와 계획 및 검증 근거 연결

## 현재 검증 회수와 과거 관측의 구분 — 2026-11-17

현재 재개는 기존 UUID의 기능 근거·문서·독립 감사·보고서 및 완료 판정을 회수하는 단계다. 과거 시도·권한 원문·보고서를 보존하며 아래의 날짜 없는 “현재”, “최신”, “fresh”가 과거 로그나 시도를 가리키면 당시 기록으로 읽는다. 최신 소스의 실제 관측은 work.json과 verification.md의 새 시도 및 적용성으로 판단한다.

이번 Terra 검토는 현재 직접 사용자 승인 원문과 요청 해시 `76e671ded65c0d349b239afa9626aa1727d62fc562bfdd1482849993117a171c`, 해당 작업 요청 해시·현재 source/criteria/policy·review 단계에 묶인 공식 직접 경로를 사용한다. 일반 검토 정책이나 과거 실패를 변경하지 않고 실제 관측 모델·별도 process receipt를 확인한다. 검토 실행 전 상태를 통과로 표시하지 않는다.

KANBAN-VERIFY는 집중 검사와 이 UUID를 대상으로 실행한 Root 실제 GUI artifacts의 관측을 독립 Terra가 검토하는 복합 경로로 판단한다. 다른 UUID의 PASS를 복사하지 않으며, 실제 backend 오류와 renderer API 실패 주입을 구분한다. 과거 홈 GUI의 actual chmod/복원/삭제/닫기/필터 관측은 최신 GUI가 재실행하기 전까지 당시 근거다.


## 요청과 목적

기존 칸반의 작업 UUID에서 명세·계획·검증 근거를 확인하도록 연결한다. 이번 세션에서 발견한 상세 열기 배선 누락을 수정하고, 업무 상태와 실제 검증 현재성을 구분한다. 기존 누적 작업의 구현·검증은 각 UUID에서 계속하며 중복 작업으로 이관하지 않는다.

사용자의 직접 요청으로 접수했다. 요청 식별값은 work.json의 workflow.requestHash에 보존한다.

## 범위

기존 칸반 카드를 선택해 같은 프로젝트·작업 UUID의 기준, 다음 단계, 명세·설계·계획·검증 문서를 읽고 보드로 돌아오는 흐름을 연결한다. 이번 세션에서 사용자가 지적한 명세의 구체성, 다양한 유스케이스, 검증 공백과 사용성을 함께 다룬다. 실제 저작은 Home002 기존 광범위 저작 하네스에 묶지만 본 작업과 Chat013의 수용·검증·완료는 각 UUID에서 따로 판정한다.

기존 누적 작업을 복제하거나 별도 세션 보드를 만들지 않는다. 업무 상태와 기준 결과는 기존 work.json, 실행 계획은 같은 폴더 tasks.md, 실제 실행·한계는 verification.md가 소유한다. 계획 문서 작성이나 보드 열기가 실제 실행·검증·완료를 뜻하지 않는다.

이번 범위에는 업무 상태 드래그 변경, 자동 작업 실행, 임의 thread 연결, 원격 동기화와 제품 자동 모델 라우터가 포함되지 않는다. 커밋·푸시 요청은 없으므로 수행하지 않는다.

## 수용 기준

정의와 필수 여부의 정본은 work.json이다. 관련 기준: `KANBAN-DETAIL`, `KANBAN-TRUTH`, `KANBAN-SCOPE`, `KANBAN-VERIFY`.

## 결정과 열린 질문

상세는 카드 선택 후 기존 보드 안에서 연다. UI에서 임의 경로를 요청하지 않고 projectKey와 workId만 전달하며 main이 등록 프로젝트와 고정 WWW 범위를 결정한다. 각 문서는 최대 256 KiB, 네 문서는 합계 1 MiB로 읽고 상한 초과를 잘라 성공으로 표시하지 않는다. source digest 평가나 저장소 검사를 조회 중 실행하지 않는다.

같은 카드의 주기적 재조회는 읽던 문서를 유지하며 갱신 실패 시 기존 자료라는 사실을 알린다. 작업이 바뀌면 이전 자료를 숨기고 새 요청을 구분한다. 원장 내용과 문서는 서로 다른 파일이므로 전체를 단일 원자 snapshot으로 보장하지 않는다.

작업 접수는 구현 완료가 아니다. 재개 시 같은 UUID와 현재 증거를 확인한다. 독립 감사와 실제 화면 검증을 수행하기 전에는 KANBAN-VERIFY를 통과로 기록하지 않는다.

현재 감사는 사용자 직접 Terra 승인으로 수행하며 일반 review-policy 값은 유지한다. KANBAN-VERIFY의 독립 검토 부분은 아직 미실행 상태에서 공식 review를 접수한다. 실제 fresh functional 근거는 attempt-b9cb3ef0-7092-40b4-a588-9a072dbafe33 및 .www/evidence/resume-20261116/home004-steps.json이다. 필요 원문은 그 디렉터리 home004-step-0.log부터 step-4.log까지의 실제 파일에서 읽으며 과거 evidence.summary를 현재 성공으로 해석하지 않는다.
