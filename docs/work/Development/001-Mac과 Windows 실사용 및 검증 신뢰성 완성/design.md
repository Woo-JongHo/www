# 구현과 검증 경계

## 소유와 병렬 실행

Mac의 공통 Chat 상태·입력은 projection·renderer·shared·input과 회귀 검사가 소유한다. 검증 신뢰성은 workflow의 잠금·review·evidence와 전용 검사가 소유한다. 실제 Native 검사는 main의 QA 조건과 별도 임시 작업 폴더·하네스로 수행한다. Windows 담당자는 게시 기준 a0076fd에서 별도 네이티브 checkout을 만들고 Windows 전용 스크립트·검사·배포와 공통 실행 호환 패치를 부모에게 전달한다. 공통 main·package 통합은 부모가 맡는다.

기존 chacada의 다른 저장소와 별도 Skills 번역 변경은 수정·게시 범위에 포함하지 않는다. 서버·Canvas·대화 저장과 일반 개발 현황 UI는 이번 범위가 아니다. 이 작업은 구현·검증 권한만 사용하며 새 변경의 commit·push는 별도 실행 요청으로 구분한다.

## 원격 실행에 대한 사용자 정정

사용자는 chacada에 Handoff를 전달하고 원격 에이전트가 백그라운드에서 독립적으로 작업하기를 요청했다. 로컬 에이전트가 SSH 명령을 매번 조작하거나 원격 데스크톱 로그인·직접 입력을 요구하는 방식으로 확대하지 않는다. 원격 작업은 목표·권한·소유 파일·기준·다음 행동을 가진 Handoff, 독립 프로세스, 상태·로그·결과 파일로 연결한다. SSH 연결을 종료한 뒤 별도 연결에서 실행 지속을 확인한다.

Windows GUI와 OS IME 수동 시험은 백그라운드 자동 검사의 통과로 대체하지 않는다. 해당 근거가 없으면 그 부분은 미검증으로 보존한다. RDP 연결 시도는 취소했고 인증서 경고를 우회하거나 인증·보안 설정을 변경하지 않았다.

## 관찰과 완료

AC-1은 fixture가 아닌 실제 앱→Native 사건과 결과 파일을 대조한다. AC-2·3은 Windows 네이티브 OS에서 실제 실행 파일을 생성·실행한다. WSL 빌드나 버전 조회만으로 이를 충족하지 않는다. SSH에서 창을 관측할 수 없다면 실행 프로세스와 GUI·입력 관찰을 구분한다.

AC-4의 실제 한국어 조합·키보드·포커스 관찰은 자동 이벤트 회귀와 별도로 기록한다. 문자 붙여넣기를 IME 조합으로 쓰지 않는다. AC-5는 접수 상태에서도 중복 요청을 막고 늦은 ACK와 연결 종료가 실제 최종 결과를 덮어쓰지 않도록 검사한다.

AC-6은 잠금 보유 프로세스의 실제 강제 종료와 살아 있는 실행 보호를 검사한다. 소유자가 입증되지 않은 잠금을 자동 삭제하지 않는다. AC-7은 요청 모델만 알려진 결과를 실제 모델 확인으로 승격하지 않는다. AC-8은 자기 검증 기록 쓰기와 전체 문서 일관성의 변경을 별도 범위로 식별한다.

관련 집중 검사 후 현재 통합 코드의 타입·전체 테스트·빌드를 실행한다. 실제 모델·GUI·Windows 증거가 없으면 해당 기준을 미검증으로 남긴다. Opus 읽기 전용 감사와 현재 소스·기준·정책의 재대조 뒤 공통 완료 API로 완료한다. 과거 통과 기록은 보존한다.
